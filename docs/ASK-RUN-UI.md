# 微信问答 / AI 问答运行过程 UI 方案

## 1. 目标与原则

「微信问答」的 `Ask.tsx` 与「AI 问答」的 `SessionAsk.tsx` 共用同一套运行视图
`AnswerRunView`、状态模型和样式。两个界面只在检索范围与页面容器上不同，回复、
思考、工具、证据、异常与交互语义保持一致。

落地原则：

1. **过程先于结论**：状态摘要常驻，思考与执行过程在上，正式回答在下；过程在正文
   出现后自动收起，避免执行细节长期压住结论。
2. **过程完整可访问**：思考全文、工具参数摘要、调用结果、错误、证据和接地核对
   不会在数据层被前端静默丢弃；长内容通过折叠、滚动或“显示全部”访问。
3. **三通道标识**：每个状态都同时使用文字、图标和语义颜色，不只依赖颜色。
4. **单一状态解释层**：生命周期与最终结果分离，页面不各自推断状态文案。
5. **不伪造数据**：缺失耗时、工具结果或状态保持“未知”，不补成 0 或成功。

## 2. 共用信息结构

两个界面统一按以下顺序渲染：

```text
状态摘要条（始终可见）
├─ 状态：已提交 / 思考中 / 调用工具 / 生成回答 / 核对结果 / 已完成 / 已停止 / 执行异常
├─ 图标 + 文字 + 语义色
├─ 耗时、首字时间、思考耗时、工具数量与工具耗时
└─ 运行中：停止按钮

思考与执行过程（默认按阶段和用户选择折叠）
├─ 思考过程
├─ 检索规划与召回
├─ 执行步骤
├─ 工具调用与结果
└─ 证据与接地核对

正式回答（有正文时显示）
├─ 标题 / 段落 / 列表 / 引用 / 代码块
├─ 可点击引用角标
├─ 长回答折叠 / 展开
└─ 流式光标

状态原因与告警
├─ 失败原因、降级原因
├─ 未采用 / 生成异常
└─ 接地核对异常；失败时提供重试

回答脚注与相关资源（页面原有能力，位于正文之后）
```

## 3. 状态语义

### 3.1 生命周期

| 状态 | 用户文案 | 图标 | 颜色 | 说明 |
| --- | --- | --- | --- | --- |
| `queued` | 已提交 | 时钟 | 中性 | 请求已进入运行时 |
| `thinking` | 思考中 | 思考 | 青/品牌 | 正在分析问题或产出 reasoning |
| `tool_calling` | 调用工具 · 工具名 | 工具 | 青/品牌 | 至少一个工具已开始调用 |
| `preparing` | 准备回答 | 编辑/时钟 | 品牌 | 工具已全部结束，正文尚未到达 |
| `generating` | 生成回答 | 编辑 | 品牌 | 已收到正文增量 |
| `verifying` | 核对结果 | 盾牌 | 信息蓝 | 正在做接地核对 |
| `completed` | 已完成 | 对勾 | 成功绿 | 正常运行结束 |
| `stopped` | 已停止 | 停止块 | 中性 | 用户主动停止，不是错误 |
| `failed` | 执行异常 | 关闭圆 | 危险红 | 请求级硬失败 |

生命周期回答“系统此刻在做什么”；最终结果回答“这一轮是否成立”。降级完成仍属于
`completed`，但 outcome 为 `degraded`，不会误报为成功绿或硬失败红。
工具节点全部收口而正文仍未到达时进入 `preparing`，不能继续显示“调用工具”或
“正在调用工具检索原文”。

### 3.2 最终结果

| Outcome | 文案 | Tone | 处理 |
| --- | --- | --- | --- |
| `ok` | 已完成 | 成功 | 正常收尾 |
| `degraded` | 已完成 · 已降级 | 警告 | 保留回答/证据并说明原因 |
| `insufficient` | 证据不足 | 警告 | 展示证据缺口 |
| `needs_clarification` | 需要澄清 | 警告 | 引导补充条件 |
| `blocked` | 已阻止 | 危险 | 展示阻止原因 |
| `stopped` | 已停止 | 中性 | 不显示红色异常 |
| `failed` | 执行失败 | 危险 | 展示原因与重试 |
| `unknown` | 状态未知 | 警告 | 保留原始语义，不伪装成功 |

### 3.3 节点状态

步骤和工具卡统一支持：`pending`、`running`、`success`、`warning`、`error`、
`timeout`、`skipped`、`aborted`。工具调用中的 retry 不是最终状态，卡片显示
“重试中”，终态到达后由终态覆盖迟到事件。请求已经失败或用户停止时，仍停留在
`running` 的节点只在展示层收口为“已中止”，不回写、不伪造后端阶段快照。

同一 `callId` 的重试按 `attempt` 单调合并：更高 attempt 可以结束上一 attempt
的失败态；成功终态清除旧的 `errorClass/deadlineExceeded`；较低 attempt 的迟到
事件不得把进度改回去。合并卡下方仍保留原始“尝试记录”，每次调用、重试、错误
摘要与结果均可展开核对。

## 4. 视觉层级与切换

整体借鉴 DeepSeek 对话窗口的**阅读流层级**，保留现有深色主题与 `--nm-*` 令牌：

1. **单一阅读轴**：微信问答使用约 720px 的居中阅读列，不再让提问贴最右、回答贴最左
   形成五五分观感；AI 问答打开后接管消息流并保留会话列表，全屏时再收起列表，
   内容同样限制在 720px 阅读轴内，不与聊天记录并排各占一半。两个入口的 Agent
   身份统一显示为“AI 问答”，由页面标题和读取范围表达上下文。
2. **用户消息独立**：右对齐、内容自适应宽度、最大 66%/420px，使用中性低对比底、
   无描边和 14px 圆角（右下收至 4px）；内边距 `7px 11px`，正文 12.5px/1.6。
3. **状态行最轻**：单行“Agent 标识 + 状态文字 + 计时”，状态与 Agent 名 10.75px、
   辅助指标 10px；不使用卡片底、边框或胶囊描边。成功态只保留低饱和图标，文字回到
   中性色；运行、核对、降级和失败才使用语义色。
4. **回答最重且无卡片**：正文直接落在对话底色上，12.5px/1.65 并占满阅读轴；标题、
   段落、列表、引用与代码块通过间距和字重区分，不再套第二层回答卡。
5. **行内格式安全渲染**：模型输出的加粗、斜体、行内代码按文本节点渲染，不执行 HTML；
   连续引用角标聚合为一个轻量数字组，同时保留每个编号独立点击能力。
6. **过程是摘要行与时间轴**：收起态只有一行 28px 高的中性摘要，文案优先使用
   “思考 6.4s · 7 个工具”；证据数只在展开后的证据区展示。展开后思考、检索、步骤、
   工具和证据共用一条轻量分隔轴与细线节点，不再叠加卡片、胶囊和多层纵向轨道。
7. **只有异常需要底色**：失败、超时、阻止和未通过核对使用低饱和警示底与左侧错误线；
   常规完成态不使用大面积色块。
8. **状态切换不跳位**：状态行保持固定基线；思考中、调用工具、准备回答、生成回复、核对结果、
   完成、停止和异常只替换图标、文案与语义色。正文到达后过程自动收起；用户手动展开
   后保持展开，窄栏换行也不因状态变化造成大幅闪动。
9. **滚动服从主回答**：没有正文时把本轮状态对齐线程顶部；正文生成时跟随最新内容；
   完成后若用户原本贴底，回到本轮状态起点，避免自动滚到过程底部而遮住回答。
   正文、思考和阶段状态每次增长或切换都重新评估滚动，而不是只在提交时计算一次。
10. **无可见滚动条**：对话、过程、输入框和代码块保留滚动能力，但隐藏滚动条轨道与
    滑块，避免在深色界面上形成一条抢眼的绿色竖条。
11. **接管而非对半**：AI 问答替代消息流成为当前主视图；用户不需要在两个约 50% 宽的
    窄栏之间同时阅读聊天和问答。关闭问答后原消息流恢复，会话列表默认始终可换会话。

间距规范：对话轮次 20px；Agent 状态到过程、过程到回答 8px；正文块间 8px；
列表项间 3px；过程分组顶部 5–7px；工具行高度 24px；正文列表左缩进 18px；
工具参数与结果使用 10.5–10.75px 辅助字号。过程正文 11px/1.6，正式回答 12.5px/1.65。
桌面交互目标最小 24px，粗指针/触屏设备的关键按钮提升到 44px；引用角标是紧凑排版例外，但必须
保留完整可访问名称、键盘焦点和可点击语义。圆角、颜色和字体全部复用全局 `--nm-*`
令牌。

## 5. 长内容、折叠与默认策略

| 内容 | 默认 | 长内容策略 | 用户操作 |
| --- | --- | --- | --- |
| 回答 | 展开 | 超过 1600 字或 12 个块时，预览最多 6 块 / 约 1100 字 | 同一按钮切换展开全文 / 收起全文 |
| 思考 | 跟随过程区 | 超过 600 字或 10 行时显示 6 行预览 | 展开完整思考 / 收起 |
| 工具调用 | 成功单行收起，运行/超时/失败展开 | 单行摘要常驻；完整参数、结果、重试和错误按需展开 | 点击工具名展开 / 收起详情 |
| 工具参数与结果 | 跟随工具调用 | 展示脱敏摘要；成功调用可展开结构化结果快照，截断由后端标记 | 点击工具名展开；结构化结果用原生 disclosure 展开 |
| 证据 | 跟随过程区 | 默认 6 条 | 显示全部 N 条 |
| 思考与执行过程 | 动态 | 思考/工具阶段且无正文时自动展开；正文出现后自动收起 | 手动选择优先；异常首次到达强制展开一次 |
| 异常过程 | 展开 | 失败、阻止、工具失败、超时或综合异常时自动展开 | 首次展开后仍可手动收起 |
| 完成但空正文 | 明确提示 | 显示“本轮没有生成可展示的回答”，不渲染空回答卡 | 仅失败轮次提供重试 |

规则：

1. 用户手动设置过程区开合后，覆盖后续普通的自动展开/收起；该选择按客户端 `runId`
   保留，流式视图替换为完成态历史轮次时不会重置。唯一例外是异常首次到达：即使
   此前已手动收起，也必须强制展开一次，让失败原因、超时节点或综合异常立即可见；
   之后用户仍可再次收起。
2. 移动端不把过程区强制塞入固定高度；使用容器查询降级为单列。
3. 证据和工具结果的“截断”只由后端预算产生，并且必须显式标记，不由前端二次截断。
4. 页面滚动由问答线程容器统一负责；过程主体不设固定高度或内部滚动。超长执行步骤
   和结构化工具结果使用原生 `<details>` 显式展开，而不是套一个内层滚动窗。仅实时
   长思考和代码块保留隐藏滚动条的内部滚动能力，完成后改由显式“展开完整内容”控制。
5. 实时思考不套用完成态的六行摘要，超过预览上限时在内部滚动；只有用户仍在底部
   附近时自动跟随，上翻后停止拉回并显示“回到最新”，回到底部或主动点击后恢复跟随。
   实时态不显示无意义的展开/收起控制，完成后才显示唯一的完整思考开合按钮。
6. 长回答预览会按字符预算截断实际 DOM，而不是只做 `max-height` 视觉裁剪，避免
   不可见引用按钮仍进入键盘 Tab 顺序。

## 6. 完整思考、工具与结果

### 思考过程

- 实时 reasoning 流与完成后 `turn.reasoning` 使用同一个展示组件。
- 思考开始/结束、首个 reasoning、首个正文的时间点由客户端记录；实时思考耗时从
  第一段 reasoning 内容到达时开始，不拿整轮墙钟时间冒充思考时间。
- 完成后优先使用后端总耗时与 `metrics.toolMs`；思考耗时来自首个 reasoning 到
  正文开始/轮次结束的真实事件区间。
- 实时长思考在固定高度内滚动，按接近底部策略跟随最新内容；完成后可展开完整思考，
  数据完整保留。

“总耗时”从收到用户请求时开始，到运行时结果返回、历史落库前结束，覆盖索引准备、
意图识别、工具循环、综合生成和接地核对，不使用运行时内部子区间冒充端到端耗时。

### 工具调用

工具卡展示：

- 中文动作名与调用顺序；
- 状态、轮次、尝试/最大尝试、重试次数；
- 耗时、命中数、事实数、缓存复用；
- 后端脱敏 `argumentsSummary`；
- `detail`、`note`、错误分类/错误码；
- `resultSummary`、可展开的 `resultDetail` 与 `resultTruncated` 截断标记；
- running、failed、timeout、skipped 的明确文案。

优先级：实时工具阶段负责过程状态；最终 `toolCalls` trace 负责补齐轮次、重试、错误码
和 note。相同 `callId` 合并为一张摘要卡，不重复展示；原始 `called → retry →
completed/failed` 事件保留在默认折叠的“尝试记录”中，可逐条展开查看状态、累计耗时、
错误分类与结果摘要。

成功工具默认只占一行：工具名、完成状态、耗时与命中数常驻；轮次、尝试次数、重试和
缓存复用只在展开详情时出现。运行中、超时和失败工具自动展开，因此关键错误不会被折叠。
结构化结果是后端按同一套脱敏与预算规则生成的快照；命中条数、事实数或文本长度触发
预算时，摘要会明确写“已按条数或长度截断”，不会把截断内容伪装成完整结果。

### 证据与核对

- 消息、知识库、统计事实和资源不混类；资源仍在正文后的独立资源区。
- 证据项保留完整摘要、来源、时间、发送者、工具来源和后端截断标记。
- 接地核对展示核对数、引用数、自动修订和未找到原文的具体条目。

## 7. 加载与异常即时反馈

1. 提交后立即出现状态条，不再只显示静态“分析中”文案。
2. 没有正文时显示骨架反馈，并按当前阶段切换“整理思路 / 检索原文 / 核对原文”。
3. 工具调用超过预期时显示 running 与已耗时；超时后节点转为 timeout。
4. 回答生成失败时保留已收到的思考、工具和证据，显示完整原因、错误码与重试。
5. 用户停止后立即在本地结束本轮，迟到的流事件和结果不会串到下一轮。
6. 状态条使用 `aria-live="polite"`；`aria-busy` 只包裹回答正文，不阻断状态变化播报。
   硬失败由包含原因、错误码与重试动作的单一 `role="alert"` 区域播报；秒级计时从
   live region 排除，避免读屏每秒播报。
7. 流式正文里先出现的 `[n]` 在来源尚未返回时显示为“来源生成中”的中性角标，不误报
   为无效编号；完成后再切换为可点击引用。
8. 只对线程最后一条失败回答提供重试，避免重试历史失败轮时静默截断其后的对话。
9. 完成态没有可展示正文时显示独立空回答状态；`failed/blocked` 走失败说明，其余
   outcome 也不把空正文渲染成正常成功回答。

## 8. 数据结构与组件

| 名称 | 用途 |
| --- | --- |
| `AskRunPhase` | 生命周期状态 |
| `AskRunOutcome` | 最终结果状态 |
| `AskNodeStatus` | 步骤/工具节点状态 |
| `AskRunMetrics` | 总耗时、首字、思考、工具耗时 |
| `runId` | 客户端轮次标识；关联流式/完成态并保留过程区手动开合选择 |
| `AskStage` | 实时步骤与工具事件 |
| `stageEvents` | 原始阶段事件序列；用于展开工具每次尝试，不参与摘要卡状态合并 |
| `ToolCallTrace` | 完成后工具轮次、重试、错误、结果摘要与结构化结果快照 |
| `Stages` 快照 | 后端把本轮所有阶段事件随 `AskResult` 返回；当前线程完成态可复原完整过程 |
| `AnswerRunView` | 两个入口共享的状态、回答、过程、证据与异常视图 |
| `AnswerRunThinking` | 共享思考区；实时跟随、上翻暂停、回到最新和完成后折叠 |
| `AnswerBody` | 安全块级正文、引用角标、长回答折叠 |
| `parseAnswerBlocks` | 标题/段落/列表/引用/代码块解析，不执行 HTML |
| `createThinkingAutoFollow` | 实时思考是否跟随底部、上翻暂停与“回到最新”的无 React 状态机 |
| `useAskStreamFeed` | 回答、思考、阶段三条流式事件的统一订阅与迟到事件过滤 |
| `useAskThreadAutoScroll` | 两个入口共享的线程滚动策略，优先保持状态、过程摘要和正式回答可见 |
| `answer-run.module.css` | 状态、排版、折叠、滚动、窄屏和减少动效 |
| `answer-run-process.module.css` | 过程摘要、思考、步骤、工具、尝试记录和证据的轻量时间轴样式 |

兼容策略：

- 旧后端没有 `durationMs` 时使用客户端墙钟时间。
- 旧后端没有 `stages` 时使用流式快照和 `toolCalls`。
- 最终 `toolCalls` trace 优先补齐工具终态；迟到的 `done` 阶段不能覆盖 trace 的失败/超时。
- 成功 trace 优先于陈旧阶段诊断；同一调用重试成功后，不再计入异常数。
- 当前历史弹窗尚未承载完整过程；跨页面历史若需要复原过程，需先扩展历史持久化与弹窗
  视图，不能把当前线程内快照能力误写成历史能力。
- 旧后端没有新增字段时保持未知，不补造过程。

## 9. 验收标准

1. 两个入口都由 `AnswerRunView` 渲染实时轮次和已完成轮次。
2. 思考与执行过程的 DOM 顺序在正式回答之前，资源区在回答之后。
3. 思考中、调用工具、生成回答、完成、异常均有文字、图标和颜色。
4. 思考、工具参数/结果和证据都能访问完整内容。
5. 长回答、长思考、证据列表均有明确展开规则。
6. 失败、工具超时自动展开过程；普通完成默认折叠；用户手动选择优先，但异常首次到达
   必须强制展开一次。
7. 停止是中性状态；失败有完整原因和重试；未知状态不被当成成功。
8. 桌面、窄栏、键盘焦点和 `prefers-reduced-motion` 均有样式保障。
9. 窄栏完成或失败后不会被自动滚动带到思考与执行过程底部；本轮状态和主回答仍在首屏。
10. 工具重试成功后显示完成且异常数为 0；展开尝试记录仍能看到先前失败；失败/停止后
    没有“进行中”残留节点。
11. 实时长思考上翻后不会被新的 reasoning 文本强制拉到底部；完成后只有一个带
    `aria-controls` 的展开/收起按钮。
12. 两个入口的用户气泡参数一致；状态、回答和过程不会形成三层连续卡片，过程节点
    仍能通过文字、图标和语义色明确区分运行、完成、跳过、超时与失败。
13. 问答主滚动区、过程区、输入框和代码块均无可见滚动条，同时滚轮、触控板与键盘
    滚动仍可用。
14. 模型正文中的 `**加粗**`、`*斜体*` 与行内代码不会泄漏标记符；连续 `[1][2]`
    引用呈现为一个紧凑数字组，且每个编号仍可独立点击。
15. AI 问答在桌面端接管聊天消息区而不是与其五五分栏；全屏后同时收起会话列表，
    阅读轴、输入框、引用详情和过程区均无可见滚动条。
16. 工具全部结束但正文未到时显示“准备回答”；完成态空正文显示独立提示；异常首次
    到达可覆盖此前的手动收起。
17. 超长执行步骤用显式 disclosure 展开，不创建内层可见滚动条。
