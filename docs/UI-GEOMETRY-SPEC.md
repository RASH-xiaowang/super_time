# UI 几何规范：布局、间距与圆角（2026-09-25）

> 权威定义在 `src/client/ui-wechat/src/client/pages/wechat-data/scifi-theme.css` 的 `:root` 令牌。
> 本文是**使用规范**：什么场景用哪个令牌、存量字面量怎么收敛、守卫怎么卡。
> 守卫：`theme-geometry.spec.ts`（vitest，与 `theme-tokens.spec.ts` 同目录同扫描方式）。
> 本文不覆盖聊天消息区（`--wx-*` 族）——那套由
> `docs/compose/spec/wechat-message-visual-system.md` 与 `npm run check:wx-tokens` 管，两套并行。

## 0. 为什么需要这份规范（2026-09-25 实测基线）

62 个前端 CSS（`src/client` 下，除令牌定义处/资源/产物）中：

| 项 | 实测 | 问题 |
|---|---|---|
| `border-radius` 声明 | **583 处** | 仅约 16% 走令牌；**336 处非法字面量**（52 个文件），取值 13 种单值 + 5 种复合角，含 5/7/9px 野值 |
| `999px` 字面量 | 81 处 | `--nm-r-pill` 存在却不用 |
| `50%` 字面量 | 66 处 | 部分并非圆形用途（矩形上是椭圆） |
| 间距声明（padding/margin/gap） | **1466 处** | 仅约 4% 走令牌；奇数 5/7/9/18px **122 处**（40 个文件） |

历史上曾有 `audit:scale` / `check:align` 等守卫（scifi-theme.css:369 注释仍引用），**它们已不存在于仓库**——本规范与 `theme-geometry.spec.ts` 是它们的重建。

## 1. 圆角刻度（iOS 式递进，沿用现有令牌值）

| 令牌 | 值 | 组件类型 | 例 |
|---|---|---|---|
| `--nm-r-xs` | 4px | badge / 状态点 / 迷你角标 / 表格单元格控件 | kit-table、batchCheck |
| `--nm-r-sm` | 6px | chip / 小控件 / 内联标签 / tooltip | dateChip、tooltip |
| `--nm-dense-r` | 8px | 紧凑行 / 小按钮（总结三页的密度） | dense 列表行 |
| `--nm-r-md` | 10px | 输入框 / 下拉 / 卡片内嵌块 / 媒体缩略图 / 图标容器 | SearchInput、statIcon |
| `--nm-r-lg` | 14px | 卡片 / StatCard / 面板子容器 | kit Card |
| `--nm-r-xl` | 20px | 大弹层 / Drawer / 整页卡 | Dialog |
| `--nm-r-pill` | 999px | 胶囊按钮 / 胶囊标签 | Badge、pill 按钮 |

**关系声明**：本刻度即「iOS 风格」——小圆角递进（4→6→10→14→20）+ 全胶囊按钮，与苹果
Human Interface Geometry 同构；按钮不搞大圆角方块，卡片不做超圆角。

## 2. 字面量 → 令牌映射决策表（收敛施工依据）

| 存量值（处数） | 归宿 | 视觉影响 |
|---|---|---|
| `4px` (31) | `var(--nm-r-xs)` | 零 |
| `6px` (37) | `var(--nm-r-sm)` | 零 |
| `8px` (65) | `var(--nm-dense-r, 8px)` 紧凑场景 / `var(--nm-r-sm, 6px)` 普通小件（逐处按上下文） | 紧凑场景零；普通场景 -2px |
| `10px` (72) | `var(--nm-r-md)` | 零 |
| `12px` (45) | 内嵌块/缩略图 → `var(--nm-r-md, 10px)`；卡片容器 → `var(--nm-r-lg, 14px)` | ±2px，按元素尺寸档位判 |
| `14px` (28) | `var(--nm-r-lg)` | 零（宽窗）；≤768px 时联动降为 10px（见 §4 R1） |
| `16px` (3) / `18px` (1) | `var(--nm-r-lg, 14px)` | -2/-4px（16/18 本就是野值） |
| `2px` (21) / `3px` (7) | `var(--nm-r-xs, 4px)` | +1~2px，仅在 <20px 的微型元素上，视觉不可辨 |
| `5px` (3) / `7px` (4) / `9px` (7) | 野值：5→`sm(6)`、7→`dense(8)` 或 `sm(6)`、9→`md(10)` | ±1px |
| `999px` (81) | `var(--nm-r-pill, 999px)` | 零 |
| `50%` (66) | **仅限确属正方形圆形**（头像、圆点、圆形播放钮）保留 `50%`；矩形/胶囊场景改 `var(--nm-r-pill)`。⚠️ `50%` 在非正方形上渲染为**椭圆**，与 pill 不等价——**禁批量替换，逐处确认** | — |
| `inherit` (1) | 合法，保留 | — |

**带兜底规则**：`ui-primitives-shim/` 与 `ui-app/` 的 CSS 不保证宿主加载了 `--nm-*` 令牌
（shim 属 `--dsw-alias-*` 体系），这两处目录下的收敛**必须带兜底**（`var(--nm-r-pill, 999px)`），
恰好落在 `theme-tokens.spec.ts` 的豁免口径内。`wechat-data/` 面板目录下 scifi-theme.css
必然注入，可不带兜底（但带兜底也无害）。

**复合角**：仅两种合法形态——
1. **令牌组合**：每个分量都是 `var(...)` 或 `0`（如 `var(--wx-radius) var(--wx-radius) 0 0`、`0 var(--nm-r-sm) var(--nm-r-sm) 0`）；
2. **已交付白名单**（聊天气泡尾巴等 6 个字面量复合角，守卫常量里逐字登记）：
   `4px 4px 0 0`、`0 3px 3px 0`、`12px 12px 3px 12px`、`4px 14px 14px 14px`、`4px 3px 0 0`、`6px 6px 0 0`、`0 6px 6px 0`、`4px 4px 2px 2px`、`14px 14px 4px 14px`。
新代码禁用字面量复合角。

**已知 bug（登记在案，收敛时修）**：`daily-summary.module.css` 有一处
`border-radius: var(--nm-fs-md)`——字号令牌（15px）当圆角用，语义错误。修复时改
`var(--nm-r-md, 10px)`（视觉 15→10px，本来就是错值）。

## 3. 间距刻度与层级节奏

| 令牌 | 值 | 层级 |
|---|---|---|
| `--nm-s-1` ~ `--nm-s-8` | 4 / 8 / 12 / 16 / 20 / 24 / 32px | 主阶梯 |
| `--nm-dense-g1` ~ `g5` | 2 / 4 / 6 / 8 / 10px | 紧凑 gap（组件内部） |
| `--nm-dense-pad-x/y`、`--nm-dense-row-y` | 10 / 7 / 5px | 紧凑密度专用（总结三页口径） |
| `--nm-panel-pad` | `16px 0` | 面板滚动容器标准契约（第 80 轮定，左右归零） |

**节奏规则**：
- 组件内部（元素↔元素）：`--nm-dense-g1~g5`
- 组件间（卡片↔卡片、行↔行）：`--nm-s-2` ~ `--nm-s-4`（8~16px）
- 区块间（节↔节）：`--nm-s-4` ~ `--nm-s-6`（16~24px）
- 页面边距：`--nm-panel-pad` 契约，不自造
- **对齐优先**：同一面板内，左边缘/栅格必须走同一令牌——历史教训：18px 不在刻度上，
  曾造成切页签时横向跳 18px（scifi-theme.css 第 80 轮注释）；奇数值天然破坏 4px 网格对齐

**奇数归宿表**（122 处存量的清理依据，逐处按「相邻元素对齐优先」判）：

| 存量值（处数） | 归宿 |
|---|---|
| `5px` (40) | `4px` 或 `6px`（dense-g1/g3）——看相邻 gap |
| `7px` (27) | `8px`（dense-g4） |
| `9px` (37) | `8px`（dense-g4）或 `10px`（dense-g5） |
| `18px` (18) | `16px`（s-4）或 `20px`（s-5）——18 是历史事故值 |

## 4. R1：媒体查询降级（收敛前必读）

`scifi-theme.css:404-409` 在 `≤768px` 窗口把 `--nm-r-lg: 14→10px`、`--nm-r-xl: 20→14px`。

后果：字面量 `14px` 收敛为 `var(--nm-r-lg)` 后，**窄窗口下会从 14 变 10**——这是行为联动，
不是等价替换。逐值决策：
- 卡片/容器类：**可接受**（窄窗口收紧圆角本就是该媒体查询的设计意图，跟随联动是对的）
- 需要在窄窗口保持 14px 的特例：收敛到 `var(--nm-r-lg, 14px)` 也躲不掉（媒体查询改的就是令牌值）——此类**保留字面量进守卫基线**，并在该行加一行注释说明原因
- `--nm-r-xl` 同理（20→14）

## 5. 守卫：`theme-geometry.spec.ts`

与 `theme-tokens.spec.ts` 同目录、同 walk 方式（扫 `src/client` 全部 CSS，排除令牌定义处
scifi/light-theme.css、ui-dist、public、node_modules）。四条断言 + 三条哨兵：

1. **圆角白名单门禁**：合法 = 令牌（`--nm-r-*`/`--nm-dense-r`/`--wx-*`，含带兜底与令牌组合复合角）、`0`、`50%`、`999px`、`inherit`、复合角白名单。其余按 **per-file per-value 基线棘轮**（基线常量写死在 spec 里，只许减不许增；基线条目对应的值消失后必须同步删条目——防空转）
2. **奇数间距棘轮**：5/7/9/18px 的 per-file 计数基线（122 处起步，只许减）
3. **999px ≤ 81 / 50% ≤ 66** 全局棘轮（双向：不许新增，也防「圆形滥用 50% 逃避规范」）
4. 哨兵：border-radius 总数 ≥ 500、间距声明总数 ≥ 1200、扫描文件数 ≥ 60（防解析坏了空转）

新守卫纪律：已做变异测试（新增 `border-radius: 11px` 红 / 新增 `margin: 7px` 红 / 基线手工调小红），全部还原。

## 6. 与既有体系的关系

- `--wx-*`（聊天消息区）：**并行不管辖**。check:wx-tokens 47 项断言守它，本规范的收敛施工不碰 chats-rows 消息类
- `--dsw-alias-*`（颜色族）：无关（本规范只管几何）
- `M21 文件大小棘轮`：收敛一律**同行替换不增行**（`10px` → `var(--nm-r-md)` 等）；说明性注释写进本文档，不写进 CSS（白名单文件禁增行）
- `theme-tokens.spec.ts`（未定义 `--nm-*` 引用门禁）：本规范的兜底写法与其豁免口径兼容
