> `X-API-Key` 头、不参与参数；桌面端本机仍可按 v26 口径点眼睛回读。逐条口径见第四节 G3。

## 一句话结论

你的微信数据在本机解析、存储与分析，**不上传到我们的任何服务器**（我们没有任何服务器）。
唯一会把你**内容**发出去的功能是 AI 问答与总结、ClawBot 发送/自动回复，以及**你自己逐条配置的
任务触发投递** —— 触发方式由你逐任务选择：Webhook（目的地就是**你填的那个地址**）或某个
**RPA 厂商**（八爪鱼（开放 API / MCP 两条通道）/ 影刀 / UiPath / 阿里云 / 来也 / 实在；目的地是厂商固定主机或你配置的
实例地址，只发会话名 / 触发文本 / 触发对象；八爪鱼的参数**全部由你在「附加参数」里逐条配置**
（最多 20 条，默认不发业务参数），值来自触发记录 / 固定值 / 自定义模板，**不发图片**），见第四节 G3。除此之外还有几处
**不涉及聊天内容**的出网点（头像、远程图片/视频、地图底图、语音模型下载，以及只发凭据的
**连接测试 / 余额查询**），第四节逐条列明。

**入站方向**：本应用**默认不监听任何端口**，别人无法从网络连进来。只有两种需要你显式触发的例外：① 标题栏「打开网页」交接（临时起服务，默认浏览器打开，点卡片返回即停）；② 设置 → 维护与自检 → 局域网访问（手机）的扫码入口（默认关闭，关闭/退出/轮换即停）。两者都见第四节 H；交接会话与桌面端同权限，点卡片返回即恢复「一个端口都不监听」。原来的「远程访问（手机）」设置已移除，扫码入口现在在「维护与自检」里。

> **应用内已没有任何出网开关**：本声明第四节列出的每一个出网点都会按描述发出请求，
> 应用里没有可以逐个关掉它们的按钮。要阻止这些请求，只能靠系统防火墙或直接断网
> （见第五节）。**"参与语义检索"是文件级的数据范围开关，不是出网开关**：它决定某个
> 知识库文件是否进入向量索引，关掉之后该文件完全不出网。

## 一、我们读什么

### 1. 本机微信数据（只读）

- 解密后的 SQLite 库：消息、联系人、群成员、朋友圈、收藏、转账记录等；
- 媒体缓存：图片、视频、语音、文件的本地副本与我们自己的解码缓存。

这些数据来自你**自己**的微信安装（`Weixin.exe`）与数据目录。应用把它们解密、
复制到自己的数据根后**只读**使用。

### 2. 运行中的微信进程内存（只读，用于取数据库密钥）

微信 4.x 的数据库密钥不以明文存在磁盘上，只在**运行中的微信进程内存**里。
因此「自动获取密钥」会：

- 通过 Win32 API（`OpenProcess` → `VirtualQueryEx` → `ReadProcessMemory`）**只读**扫描
  `Weixin.exe` 进程的内存区域；
- 只挑「已提交、可写、非 guard」的区域，按已知的密钥模式匹配并用一个数据库文件校验命中结果；
- **不写入、不修改、不注入、不 hook** 微信进程，也不把扫描到的内存内容保存或外发；
- 命中后把密钥写入本机 `<数据根>/secrets.json`（权限收紧到当前用户）。

代码：`src/backend/wechat-data/src/keys/win32-memory.ts`、`keys/service.ts`。
微信未运行时该能力不可用，可改为手动填写密钥。

### 3. 本机密钥材料与配置

图片密钥可从微信的 kvcomm 缓存（`*_input.statistic` 文件名前缀）与
`%APPDATA%\Tencent\xwechat\config\*.ini` 推导；这只读本机文件，不外发。

### 4. 设备指纹（用于授权）

授权校验需要一份设备指纹（机器标识的哈希）。它**只在本机计算**，写入你导出的
`activation-request.json`；只有你**主动**把该文件交给签发方时才离开本机。

### 5. 运行中的微信进程（可选：原图自动下载，默认关闭）

设置 → 图片解码里的「微信原图自动下载」是一个**默认关闭的实验功能**。只有你显式打开后，
应用才会把上游 WeFlow-X（MIT）的 `img_helper.dll` 注入正在运行的 `Weixin.exe`，
让微信在**接收新图片时**按它自己的策略下载高清原图（本应用自己不向微信服务器发请求、
不接触登录凭据）。它的边界：

- 只影响**打开之后**新收到的图片；历史图片不会补下载（仍需在微信里点开原图，
  由「原图自动收割」接住）；
- 会**修改微信进程内存**（这是它唯一的越界点，也是默认关闭的原因）；关闭开关或退出应用时
  应用会调用 `UninstallImgHelper` 还原；
- 应用被强杀/崩溃时，微信可能保持被修改状态直到**微信重启**；下次启动会在界面上如实提示
  （`cleanupUnconfirmed`），并拒绝在微信未重启时重复注入；
- 仅 win32-x64，微信版本兼容性未声明；组件在加载前按 SHA-256 校验，不一致直接拒绝；
- 组件来源、许可与已知边界见
  [`src/backend/wechat-data/native/img_helper/PROVENANCE.md`](../src/backend/wechat-data/native/img_helper/PROVENANCE.md)
  与 [`src/backend/VENDORED-LICENSES.md`](../src/backend/VENDORED-LICENSES.md)。

代码：`src/backend/wechat-data/src/query/wechat-image-autodownload.ts`。

## 二、我们不做什么

- 不登录微信、不发消息、不改动微信的任何文件或数据；
- 不写注册表、不安装驱动；**默认不挂钩（hook）微信进程** —— 唯一例外是你显式打开
  「微信原图自动下载」实验功能（默认关闭；打开后会注入组件让微信自己下载新图片的原图，
  见 1.5 节）；
- 不收集遥测、不做崩溃上报、不做使用统计；
- 不把数据库、聊天记录、图片或导出物上传到我们的服务（我们没有这样的服务）；
- **不监听任何端口、不接受任何入站连接** —— 只有两个显式例外：标题栏「打开网页」交接（临时启动，点卡片返回即停）和设置 → 维护与自检 → 局域网访问（手机）的扫码入口（默认关闭，关闭/退出/轮换即停；见第四节 H）。日常运行与启动时都不监听；
- 不在后台偷偷调用模型：AI 调用只由你的操作触发（提问、总结、定时总结任务、
  知识库的「生成摘要 / 语义索引 / 抽取实体 / 找链接建议」四个按钮）。
  > ClawBot 集成的**默认**行为同样不经模型：收消息自动、**发消息只由你在界面上的发送动作触发**
  > （没有定时发送）。唯一的例外是**你在实例卡上为某个实例打开「AI 自动回复」**（默认关闭）：
  > 打开后，收到消息时会自动走问答管道生成回复 —— 那正是上面说的「无需点击的模型调用」，
  > 用的也是你在这里配置的模型接口（触发方式不同：一个是你点、一个是收到消息）。

## 三、数据存在哪里

| 路径 | 内容 | 保护 |
|---|---|---|
| `<userData>\wechat\config.json` | 路径配置与非敏感设置镜像（**不含**密钥） | 目录权限收紧到当前用户 |
| `<userData>\wechat\llm.json` | 模型接口地址与 **API Key**（可保存多套已配置的模型，切换时整体替换） | 同上 |
| `<userData>\wechat\logs\` | 诊断日志（出网相关内容会脱敏） | 同上 |
| `<userData>\wechat-data\` | 数据根：`decrypted\`（解密库）、`decoded_images\`（图片缓存）、检索/笔记/待办库 | 同上 |
| `<数据根>\secrets.json` | 微信解密密钥（db / image / xor / api_token） | 原子写入 + 仅当前用户可读 |

除上表之外，`<数据根>\wechat_privacy.db` 保存三类**本机元数据**：AI 出站审计（见第七节）、
导出历史（每次导出的路径与参数），以及**问答历史**（每次问答的问题、回答与引用来源，
供「微信问答 → 历史记录」回看）。三者都只存在本机、按数据根隔离，**不参与任何导出或分享**；
问答历史与导出记录都可以在界面上逐条删除或整体清空。

### 微信 ClawBot 集成（`<数据根>\clawbot.db`）

「ClawBot」面板用于把 Super Time 接入微信（官方形态：**手机微信插件 ↔ 桌面端 Agent**
绑定，扫码即绑、无需 App ID / App Secret）。**一个微信号 = 一个实例**：可以同时管几个
（工作号 / 生活号各有自己的通道、会话与配置），每个实例各自持有一条长轮询。
它维护一个**独立的本机库** `<数据根>\clawbot.db`，写入者是 **Super Time 自己**
（单写方，无第三方进程写它）：

| 内容 | 说明 |
|---|---|
| 绑定状态 | 绑定四态（未绑定 / 绑定中 / 已绑定 / 已解绑）与绑定后的微信 `wxid`、昵称、头像（iLink 不下发昵称/头像时显示 `wxid`，不编造） |
| **实例标识** | 每个实例的 iLink 机器人 id（`ilink_bot_id`，**公开标识、非凭证**）与最后一条消息的接收时间（由本机会话表算出）。用于实例卡上区分「哪个号挂在哪个 bot 上」与「这个号最近什么时候有动静」 |
| **接入会话** | 你与本机 Super Time 之间的**每条消息正文原文**，含方向（收到 / 发出）、消息类型与时间；附件另记类型、文件名、体积与**语音时长**（协议自带，非本机测量） |
| **会话凭证** | iLink 会话凭据（`bot_token` / `ilink_bot_id` / 用户 id / 服务地址）、**同步游标**与**发送令牌**（按实例各存一份）。只存在本机、只有 worker 读得到（界面快照与导出都不含它们）；**解绑时随通道一起清除**。⚠️ `ilink_bot_id` 同时出现在「实例标识」与这里：它是**公开标识**（bot 编号），真正的密钥是 `bot_token` —— 前者进界面快照，后者永远不进 |
| **实例配置** | 每个实例的行为开关（AI 自动回复开 / 关、是否启用知识库增强及其库 id）、**系统提示词**（人设 / 语气 / 风格；留空 = 用内置拟人化默认值）与**长回复分段发送**开关。与绑定关系**分表存**：行为偏好是你的选择，应当**活过重新绑定**（重新扫码不该把开关重置成默认） |

**关于这份数据的五件事：**

- **绑定通道会出网：接收侧只发控制面，发送侧只发你写的那条正文，附件点开才取。** 扫码绑定与
  消息接收都要经腾讯 iLink 服务（`ilinkai.weixin.qq.com`，唯一目的地）：申请二维码、轮询扫码状态、
  绑定后**常驻消息长轮询**（约每 35 秒一轮，随应用运行，直到解绑）——这些请求只带会话凭证
  与同步游标，**不含任何本地数据**；而你在「接入会话」里点「发送」时，**你写的那条正文原文**
  会经同一服务送达你的微信（默认只在你的发送动作里发生；另外**按实例开关**的 AI 自动回复
  会自己发一条，默认关）；收到带附件的消息
  后，本机**自动**从腾讯 CDN 取回那份媒体（无人值守；**只下载、不上传**），解密后落本机缓存
  `<数据根>\clawbot-media\`。逐条口径见第四节的 **G2**。
- **发送的内容不做打码。** 「敏感字段打码」只作用于**展示层**：「发送」发的是你输入框里的
  原文（你对着它写、对着它发，改写反而会改变你要表达的东西）；库里与导出文件也是原文。
- **它写的是正文原文，且永久保留。** 这是本声明首次包含「会话正文」类别的本机落盘。
  **没有自动清理、没有保留期上限**；如果开启了「敏感字段打码」，那**只影响界面展示**，
  写入库里的仍是原文、导出文件里也是原文。
- **解绑不删除接入会话。** 解绑只是断开微信通道（停长轮询、清凭证与发送令牌）、把绑定状态
  置为「已解绑」；历史消息仍保留在本机，重新绑定后可继续查看。要彻底清掉请删除数据根
  （`<数据根>\clawbot.db` 随数据根一起消失）。**移除实例**是另一件事：它会把该实例的
  接入会话连同配置一并删除（界面在确认框里如实报出将删除的条数）。
- **AI 自动回复是这条链路唯一的自动外发**（2026-10-13 起）：为某个实例打开「AI 自动回复」后，
  你在微信里发给它的**消息正文会作为问题**走本机问答管道 —— 模型服务商（第四节 F 表那几个
  目的地）会收到它，**这一路是无人值守的**（不需要你点任何东西）；知识库增强打开时，被检索中的
  知识库片段也会一并进入同一次调用。**默认关闭**，开关就在实例卡上，关掉即停。
  ⚠️ **数据面限定（2026-10-17）**：自动回复的检索范围**只限「知识库 + 对话上下文 + 模型」**，
  **不检索本机微信数据**（消息 / 联系人 / 朋友圈 / 收藏 / 文件 / 账单）。理由：这条链路无人值守，
  微信里随便一个人发一句话就能触发一次模型调用 —— 若允许它检索本机数据，等于「任何人都能让你
  的全部聊天记录被检索并送去模型」，而你没有逐条同意过。手动问答不受此限（那是你亲手发起的，
  且界面上有范围选择）。关掉后：检索阶段跳过微信侧四个通道、不建消息向量索引（不把消息正文
  送去 embedding），只保留知识库通道；依据行会写明「本次仅检索知识库」。
  ⚠️ **系统提示词也会出网**（2026-10-17）：你为该实例写的提示词会作为 system 消息随每次自动回复
  发给模型服务商（与手动问答的提示词同一口径）。**不要在里面写敏感信息**（密码、密钥、身份证号）。
  留空则用内置的拟人化默认提示词（那份是公开的、不含你的任何数据）。
  长回复分段发送只是把同一条回复切成几条依次发出，**不改变出网内容**（总量相同）。
  除此之外 ClawBot 不参与任何自动分享；「ClawBot」面板的导出按钮把消息导出成 TXT/CSV 时
  由**你自己**选择落点。自动回复的模型调用会按 `ask_wechat` 记进 `wechat_privacy.db` 的
  AI 审计（与手动问答同一口径），并在操作日志里留一行 `clawbot_auto_reply`。

删除全部数据时，除了 `<userData>\wechat` 与 `<userData>\wechat-data`，`<数据根>\clawbot.db`
也会随之消失（它位于数据根下）。

`<userData>` 在 Windows 上是 `%APPDATA%\Super Time`。**安装目录保持只读**：
升级或卸载不会带走你的配置，也不会把本机路径与密钥带到其他机器。

删除数据 = 删掉 `<userData>\wechat` 与 `<userData>\wechat-data`（或你在设置里指定的数据根）。
卸载程序不会自动删除它们。

## 四、网络暴露面清单（出网点 + 入站监听，与代码逐条对应）

> A–G3 是**出网**（本机向外发请求）；**H 是入站**（本机监听端口、别人向本机发请求）。
> 两类都登记在这里，因为「我的数据会不会被别的设备看到」这个问题两边都要答。

### A. AI 调用：LLM chat（发的是**内容**）

| 项 | 说明 |
|---|---|
| 触发 | 微信问答、每日总结、周期总结、群总结任务，问答的「查询改写/优化」，单聊里的「**推荐回复**」，知识库文件详情里的「**生成摘要**」，以及 AI 年度回顾叙述（**按月分段**，每段最多 4,000 字，逐段发出该月的聊天片段） |
| 发出内容 | 检索到的聊天片段 / 当日消息 / 待总结文本（**不是**整个数据库）；「生成摘要」时是**你指定的那一份文件的开头正文**，上限 8,000 字、按文档原有顺序取前若干块 —— 文件更长时后面部分不会发出去，摘要也只覆盖前面那段 |
| 目的地 | 你配置的 `llm.json` 里的 `apiUrl`（默认 `https://api.openai.com/v1`） |
| 开关 | ⚠️ 应用内**没有出网开关**：这一条会按上面的描述发出请求。<br/>✅ 「敏感字段打码」开启时发送前脱敏（它只改发出去的字节，不是出网开关）；<br/>✅ 文件级：关掉「参与语义检索（会出网）」的文件**直接拒绝生成摘要**，不改标志位也不发送 |
| 审计 | ✅ 每次放行都记入本机审计表（功能、次数、字符数），可导出 CSV |

### B. AI 调用：embedding（发的是**内容**）

| 项 | 说明 |

| 触发 | ① 微信问答的稠密检索通道（把检索到的聊天片段向量化）；② **知识库问答**：把「参与 RAG」的文件**块正文**送去向量化，用于建/补该库的向量索引；③ 「知识库 → 文件」面板上的**「语义索引」按钮**（你主动点才发，只发当前这个库）；④ 同面板的**关键词+语义检索**：只发**你输入的那句查询词**，库内正文不外发 |

### B2. 模型精排（把候选正文发给重排序模型）

| 项 | 说明 |

| 触发 | 问答检索融合出候选之后。**只在「数据配置 → AI 大模型」的重排序模型名非空时发生** —— 这个字段没有独立开关，填了就启用（留空则整段跳过，顺序由本地启发式给出） |
| 发出内容 | 你的查询词 + 头部若干条候选的**正文**（默认上限 60 条；聊天片段与知识库文件正文都算候选）。不发出答案、不发出你的身份标识 |

| 审计 | 功能名 `ask_rerank`（独立一列）。名字里不写 `kb_` 是因为候选既可能来自聊天记录也可能来自知识库文件 |

> **一处必须说清的副作用**：开启「敏感字段脱敏」时，送出去的是**脱敏后的文本**。
> 脱敏是五条正则（手机号 / 身份证 / 银行卡 / 邮箱 / 口令），它不认识上下文 ——
> 文件正文里连续的 16–19 位数字（订单号、无连字符的 ISBN、时间戳串）会被整段替换成 `[银行卡]`。
> 也就是说**模型读到的字节与落库的原文不同**，而审计表只记录字符数、不记录被改写了什么。
> 这会影响精排的相关性判断（极端情况下把一条本来最相关的候选排到后面），
> 但不会把未脱敏的内容发出去。

> 代价要一并写清：① 代理只代取白名单内的微信系主机，指向站外图床的第三方封面 / 头像不显示（内容与卡片照常可读）；② 站外地址里的 `http` 图片（实测朋友圈 1,125 张里 1,104 张是 http）后端也只取 https，所以那部分要靠本机解码或微信里点一次；③ **表情图与朋友圈视频导出这两条链在 2026-09-30 补齐了同一道主机白名单** —— 此前它们只判协议，等于「消息 XML 里写哪个主机就去取哪个」；现在站外地址一律不发请求，且拒绝时会写明是哪个主机。
> 剩下仍由界面直接发出的只有地图底图数据（E 段）与语音模型下载（F 段）—— 两条都**没有**应用内开关。

> **这条能力的边界（2026-09-26 实测，脚本 `working/probe-original-coverage.ts` 与
> `working/probe-wecom-403.ts`，可自行复核）**：本机 51,983 条图片消息里，**16.5%** 带
> `tphdurl`/`tpurl`（8,604 条）、**81.6%** 只带 `cdnbigimgurl`/`cdnmidimgurl`（42,433 条）。
> 但这 8,604 条直链**实测一条都取不到**：它们全部指向企业微信的
> `wwfile.work.weixin.qq.com/cgi-bin/download?f=…&t=…&p=1`，匿名 GET **一律 403** ——
> 与消息新旧（**20 分钟前**的新消息同样 403）、请求头（裸 UA / 加 `Referer: work.weixin.qq.com`
> / 加图片 `Accept`）都无关，URL 里也没有 `tpauthkey`。也就是说**有链接 ≠ 能取**：这类是
> 需要企业微信登录态的服务端令牌端点，和 `cdnbigimgurl` 同类待遇（不取）。
> 真正能取的只有带 `tpauthkey` 的免登录直链（个人微信账号上是常态，本机这份数据里一条都没有），
> 因此「取原图」对它们会明确回一句「这条没有免登录直链，请在微信里点开一次」。
> 那部分指针技术上要的是**微信登录态凭据**（会话密钥 / 设备签名），也就是「以你的身份向微信
> 服务器发请求」—— 本应用**不做**，也不会去做：它和本文开头「不登录、不发送消息、不连微信
> 服务器同步聊天记录」是同一条承诺的两端。**因此「任何情况下 100% 拿到原图」在守住这条承诺的
> 前提下不可能成立**；能做的是把不越界的部分做到最大，并把剩下的缺口与补救动作说清楚。

| 触发 | **只有你在「设置 → 图片解码 → 第三方原图服务」里手动开启后**才会发生。开启后，本机没有原图的聊天图片在解码时会自动向该服务请求一次（`getImageDataUrl` 内部，无需你逐张点）。**默认关闭**，关着时一个字节都不发 |
| 目的地 | `https://wxcdn.c3o.re`（`POST /token` 换凭证、`GET /download` 取原图）。⚠️ **这不是腾讯官方服务**，是第三方 |
| 发出内容 | ① `POST /token` 的 multipart 里带**本机微信的 `global_config` 与 `global_config.crc` 两个文件的字节**，以及微信账号目录名（`wxid_xxx_<hash>`）；② `GET /download` 带该图片的 `cdnbigimgurl` fileid 与图片 `aeskey`。**不发聊天正文、不发通讯录、不发数据库** |
| 开关 | ✅ **有真开关**（本声明里除入站监听外唯一带开关的网络面）：`wxcdn_original_enabled`，默认 `false`。关掉即停，已下载的原图留在本机缓存里照常可用 |
| 代价 | **按流量计费**（Free 套餐 50 MB/天，实测一张 2.7 MB 就扣 2.7 MB）。界面显示剩余额度，可随时「查额度」 |
| 记录 | 走 `image_original_fetch` 那一条操作记录（与 D 段同口径），`via` 写 `wxcdn` |
| 代码 | `query/wxcdn-original.ts`（协议客户端：换 token + 下载 + 额度）、`query/image-auto-upgrade.ts` 的 `tryWxcdnUpgrade`（第三条升级路径）、`remotes/media.ts` 的 `getWxcdnQuota`、`panels/use-third-party-original.ts`（开关与额度） |

> **为什么它存在**：D 段那 81.6% 只带 `cdnbigimgurl` 的图片，本机没有原图、也没有免登录直链。
> 这个第三方服务接受本机微信配置换 token，然后按 fileid 返回原图字节 —— 不需要登录、不需要读
> 进程内存、不需要 hook。**它把「本机配置」发给了第三方**，所以默认关闭、必须你显式开启，
> 且额度与计费在界面上写清楚。
> 实测（2026-10-17）：token 签发成功、下载 8/8 成功、字节数与 XML 的 `hdlength` 完全一致；
> 带 `key=` 时 6/6 拿到真图片（JPEG/PNG，最大 2,751 KB）。
>
> **2026-10-17 补充实测（`working/probe-*.mjs`，脚本不入库）—— 把「读进程内存」这条路也堵死了**：
> ① 扫微信主进程 862 MB 内存，确实找到 `tpauthkey`（806 处）与 `sessionkey`（128 处）；
> ② 但把 `tpauthkey` 拼进 URL 的 **5 种变体全部 403** —— 它是给 mmtls 私有协议用的，不是 HTTP 凭据；
> ③ 内存里有 225 个完整 JPEG，但与数据库 48,882 个图片 md5 **交集为 0** —— 那是界面渲染缓存；
> ④ 内存里 4,014 个微信系 URL 中能直接 GET 的（`mmbiz.qpic.cn` 等）**全是公众号图/朋友圈图**，
>    URL 里含聊天图片 md5 的为 **0 个**。
> 结论：**聊天图片走 mmtls 私有 RPC，不是 HTTP 直链**。微信拿到字节后直接解密渲染，内存里留下的是
> 像素而不是可复用的 URL。要自己取，必须重写 mmtls + 私有 RPC 调用 —— 那是重写半个微信客户端。
>
> **因此本应用改走「收割」而不是「抓取」**：微信**自己**会下载原图（用户点「查看原图」时落盘
> `<md5>_h.dat`，实测本机 1,459 个且仍在新增）。`query/original-harvester.ts` 盯住这个落盘动作 ——
> **微信负责下载，我们负责收割**：不联网、不碰凭据、不注入进程。界面入口在「设置 → 图片解码 →
> 自动收割原图」（`originalHarvest` Remote，四个动作 `start`/`stop`/`status`/`now`）。
> 边界照旧：**只收割用户已经在微信里点开过的图**；没点开过的，微信磁盘上根本没有 `_h.dat`，
> 本应用也变不出来 —— 这是微信的下载策略，不是实现缺陷。

### H. 入站监听：打开网页交接 + 局域网扫码（2026-10-19 v22）—— **不是**出网点，但同属暴露面

> 2026-10-14 新增（v13）；2026-10-15 改为一次性配对码（v14）；2026-10-19 曾移除手机
> 远程访问设置、只留「打开网页」交接（v20）；**同日 v22 按用户需求恢复「局域网访问（手机）」**。
> 它与 A–G2 的方向相反：**本机监听、别的设备连进来**。两种入口都必须由用户在桌面端显式触发，
> 默认关闭，没有任何常驻监听或启动自启。

| 项 | 说明 |
|---|---|
| 触发 | **两种显式入口**：① 标题栏「打开网页」交接（点右下角卡片返回即停，`fullAccess`）；② 设置 → 维护与自检 → 局域网访问（手机）→「启用并生成访问凭据 / 轮换令牌」（关闭开关、退出或轮换即停）。**默认关闭**；启动时绝不按旧 `api_enabled` 自动监听。 |
| 监听什么 | 本机的**局域网 IPv4 地址**上的一个端口（默认 `5032`；被占用时顺移 5033–5042）。刻意**绑具体网卡地址而不是 `0.0.0.0`**；只在上述显式入口期间存在。 |
| 谁能连 | 同一局域网内能路由到该地址的设备都可能连到端口，因此必须持**一次性配对码**才能换会话：交接码只交给系统默认浏览器；局域网入口在桌面端显示二维码/链接，由用户自己扫码。 |
| 访问控制 | 桌面端在内存中生成**一次性配对码**：**5 分钟**寿命、**最多 5 次试错**、成功一次即作废；浏览器用 `?t=<配对码>&mode=desktop` 换取会话 Cookie（`HttpOnly` + `SameSite=Lax`，内存态、12 小时、重启/停服即失效）。长期 `api_token` 仍存 `secrets.json`，**不进二维码、地址栏或任何 UI**。Host 头必须等于当前监听的局域网 IP（回环监听额外接受 `localhost`），挡住 DNS rebinding。<br/>**权限**：两种入口都签发 **fullAccess** 会话（与桌面同权），因此二维码/交接链接等同于桌面端本人。 |
| 明确**不**开放 | 日常运行与启动时不监听；没有常驻开关/定时任务。fullAccess 意味着手机侧也能读写配置、模型 Key、许可证、诊断、备份与原生能力 —— 这是「和桌面一样」的代价，所以二维码只能给本人设备，关闭开关/退出/轮换要立即执行。 |
| 桌面交接会话 | ① 桌面端用 `shell.openExternal` 把 `http://<局域网IP>:<端口>/?t=<配对码>&mode=desktop` 交给系统**默认浏览器**；② 主窗口隐藏、右下角出现可拖动卡片，卡片只有「返回桌面应用」一个按钮；③ 浏览器内可执行与桌面端相同的方法，并通过 `/api/native/*` 弹出本机目录/文件对话框、截图导出、读写许可证/诊断/更新/远程访问设置；④ 这些请求只在本机主进程执行，不新增出网点、不上传到我们的服务；⑤ 点卡片后停服、作废全部会话与配对码，浏览器下一次请求即 401/连接失败。交接期间浏览器能看到桌面端能看到的全部内容（含密钥类配置），请把该窗口当作桌面端本人。 |
| 局域网扫码会话 | 设置 → 维护与自检 → 局域网访问（手机）里显式启用后，桌面端显示二维码/链接与配对码；手机扫码换来的会话是 **fullAccess**（与桌面端同一套方法，含配置写入与 `/api/native/*` 原生能力）。二维码/明文配对码只在生成时显示；轮换令牌会作废旧令牌、旧配对码与已连设备。 |
| 发出/返回内容 | 交接会话与局域网扫码会话都走与桌面端同一套后端方法，返回的就是桌面上能看到的同一份数据；不新增任何采集或出网点。 |
| 传输安全 | ⚠️ **明文 HTTP，没有 TLS**。在敌意网络（公共 Wi-Fi、被入侵的路由器）里，同网段的人可以嗅探到**配对码、会话 Cookie 与你查阅的数据正文**。只在你信任的局域网里使用；交接点卡片返回、局域网关闭开关即停。 |

## 五、如何断网

**应用内没有任何出网开关。** 2026-09-30 起，此前那批开关（出站拦截、地图底图拦截、
远端取原图与解密方式）已随这次改造**全部移除** —— 同类功能一律允许出网，界面上也不再有
「允许 / 禁止出网」的按钮。原因与代价都写在这里，而不是藏在代码里：那些开关要么只影响
"你能不能看到图"，要么与"内容是否发出"无关，留着只会让人以为关掉就安全。

**唯一能真正断掉出网的办法是系统级的**：

1. **断开网络**（拔网线 / 关 Wi-Fi）；或
2. **在系统防火墙里禁止 Super Time 出站**；或
3. **把模型地址指向你自己的内网 / 本机**：改 `llm.json` 的 `apiUrl`（例如自建的
   OpenAI 兼容端点或本机推理服务），内容包括向量化就不会离开你的网络。

断网后：本机已有的图片、头像、封面照常显示（都落在本地缓存里），本机没有缓存的会退成
占位（「加载失败」/ 首字母），地图底图不再画、语音模型与本地决策模型下载不可用，
AI 问答与总结会直接报网络错误。**其余功能（搜索、统计、导出、图谱、账本、备份、
隐私体检、待办提取）全部纯本地，断网照常可用。**

**还能关掉的东西（不是出网开关）**：

- `数据边界与出网 → 敏感字段打码`：出站文本发送前脱敏，见第六节；
- 知识库文件的 `参与语义检索（会出网）`：关掉之后**该文件**不进向量索引、正文不发送
  —— 它是**数据范围**开关，不是全局出网开关；
- 不点那些"按需才发生"的按钮（语音/本地决策模型下载、批量取原图、抽取实体、找链接建议）。

**入站方向是本声明里唯一有应用内开关的一处**：`设置 → 远程访问（手机）`。

- 关掉它 = 本机**立刻停止监听**，局域网里任何设备都连不进来（这是真正的开关，不是数据范围开关）；
- 「轮换令牌」= 让已经连上的手机失效（旧会话 Cookie 与旧配对码一并作废），二维码与链接随之更换；
- 上面那三条系统级办法（断网 / 防火墙 / 指向内网）对入站同样有效：**在系统防火墙里禁止
  Super Time 入站**，即使开关是打开的也连不进来。

> 注意口径差别：**出网**没有任何应用内开关（2026-09-30 起全部移除），要断只能靠系统；
> **入站**有一个真开关，而且**默认就是关的**。

## 六、发送前的敏感字段打码

`数据边界与出网 → 敏感字段打码` 开启后，出站文本在发送前会把手机号、身份证号、
银行卡号、邮箱、口令等模式替换为掩码（`src/backend/wechat-data/src/query/privacy.ts`）。
它作用于 A、B 两条 AI 链路，以及 G3 的任务触发投递 —— G3 只对**触发文本**脱敏，
任务名 / 会话名 / 触发对象名 / 关键词与图片内容不在脱敏范围内；八爪鱼「附加参数」里
由你选择的固定值、自定义模板渲染结果也同样**不脱敏**（模板能引用的白名单字段本身不在打码范围）。

注意：打码是**模式匹配**，不保证覆盖所有敏感形式。它只是改字节，**不减少出网点** ——
对内容最敏感的场景请配合断网使用。

## 七、AI 出站审计

`数据边界与出网 → AI 出站审计` 记录每次模型调用的功能名、次数、字符数、会话与消息数。
可导出 CSV、可清空。审计只存在本机数据库里（`wechat_privacy.db`），不外发。

## 八、你的控制权

| 你可以 | 怎么做 |
|---|---|
| 彻底断网 | 断网或系统防火墙禁止 Super Time 出站（见第五节） |
| 用手机访问，或彻底关掉入站 | `设置 → 维护与自检 → 局域网访问（手机）`：**默认关闭**；打开后显示二维码 / 局域网地址 / 实际端口，可随时「轮换令牌」让已连上的设备失效（旧配对码也一起作废），或直接关掉开关停止监听（见第四节 H） |
| 换模型 / 换服务商 | 设置 → 模型配置（`llm.json`） |
| 把模型指向内网 / 本机 | 同上，把 `apiUrl` 改成你自己的端点 |
| 切换已保存的模型 | 「数据配置 → AI 大模型」顶部的「已配置模型」芯片：点击即切换；也可逐条删除（其余配置不受影响） |
| 不提供密钥 | 不点「自动获取密钥」，改用手动填写；或在设置里清空 |
| 让某个知识库文件永不出网 | 关闭该文件的「参与语义检索（会出网）」（数据范围开关） |
| 停止某个任务的触发投递 | 「任务信息」里把该任务「标记待完善」或删除（所有触发方式都停）。见第四节 G3 |
| 导出你的数据 | 导出（CSV/HTML/TXT/…）、备份管家 |
| 删除问答历史 / 导出记录 | 「微信问答 → 历史记录」里逐条删除或整体清空；「导出记录」里删除或按策略清理 |
| 删除全部数据 | 删除 `<userData>\wechat`（含密钥与日志）与数据根目录 |
| 重看 / 重新同意本声明 | 主界面「数据配置 → 高级设置 → 重新查看启动页」 |

## 九、变更

本声明随版本变更；材料性变更（新增出网点、**新增入站监听面**、改变数据用途、扩大扫描范围）会提升
`PRIVACY_VERSION`，并要求你在下次启动时重新同意。文档与代码的对应关系由
`src/backend/tests/privacy-statement.spec.ts` 守住（出网点清单必须与代码里的实际调用点一致）。

> 说明：v14 是**把入站登录从「长期令牌可重复使用」改成「短命配对码一次性换取会话」**。
> 长期令牌不再出本机/过网，二维码里只放 5 分钟的配对码；这改变的是同一入站面的
> **访问控制机制**，因此要重新同意。
> v13 是**新增一个入站监听面**（此前本应用从不监听任何端口）—— 方向与 A–G2 相反，
> 但它回答的是「别的设备能不能读到我的数据」，比多数出网点更要紧。它默认关闭、且是本声明里
> **唯一带真开关**的网络面（出网开关已于 v4 全部移除）；升版是因为「打开了就会监听」这件事
> 本身必须被明确同意一次，而不是藏在设置页里。
> v11 是**把附件取回的时机从「你点开」改成「收到即取」**（并为持久化加了启动补扫）——
> 出网形态变了就得升版并重新同意；不想发生只能解绑（或断网）。
> v10 是**新增一条出网路径与一个落盘位置**（附件取数）—— 按既例必须升版并重新同意。
> v9 是**同一条链路从「仅接收」扩到「可发可收」**（新增一条由你逐条触发的
> 内容出网路径；按 A2 的先例 —— 形态变了就得升版并重新同意）。
> v8 是**新增一个出网点**（与 A2 那条同属「出网但不发内容」；区别是它常驻长轮询，
> 且会把服务端下发的会话凭证落盘）—— 按既例必须升版并重新同意。
> v7 是**新增一个 LLM 用途**（与 v3 同类）；它走的是同一个出网点与同一个 `privacyGate`，
> 但"发什么"变了 —— 一段最多 4,000 字的月度聊天片段，所以按 v3 的先例升版。

> 之所以仍按材料性变更升版，是因为它把「会话正文」这一类别首次纳入本机落盘。
