> 生效版本：**v39**（与 `src/client/ui-app/privacy/consent.ts` 的 `PRIVACY_VERSION` 一致）

> 本次修订：2026-11-18（v39：**消息分析改由对话模型完成，移除本地决策模型**）。
> 「更多 → 分析」原来跑在本机的 1.26 GB ONNX 决策模型上，完全不出网；现在改为在
> `analyze_message` 隐私闸后调用**你配置的对话模型**：送出的内容是当前会话里那条
> 消息及之前最多 20 条上下文（语音先在本机转成文字），换来的是 1–3 秒出结果、
> 不需要下载 1.26 GB 模型，并且单聊/群聊各有对应的问题域。该本地模型及其下载
> 入口一并移除，`huggingface.co` / `hf-mirror.com` 不再因它被访问。
> 这是**新增的出网内容类型**（聊天正文进入模型做意图研判），属材料性变更，故
> `PRIVACY_VERSION` 由 v38 升至 v39，要求重新同意。

## 一句话结论

你的微信数据在本机解析、存储与分析，**不上传到我们的任何服务器**（我们没有任何服务器）。
会把你的**内容**发出去的功能是 AI 问答与总结、**你自己逐条配置的
任务触发投递**，以及**消息列表的下游回复投递**。任务触发方式由你逐任务选择：Webhook
（目的地就是**你填的那个地址**；图片可走
兼容旧接收端的 JSON data URL，或避免 base64 膨胀的 multipart）或某个
**RPA 厂商**（八爪鱼（开放 API / MCP 两条通道）/ 影刀 / UiPath / 阿里云 / 来也 / 实在；目的地是厂商固定主机或你配置的
实例地址；所有业务参数**全部由你在「附加参数」里逐条配置**（每个列表最多 20 条，默认不发业务参数），
值来自触发记录 / 固定值 / 自定义模板；默认**不发图片**，
只有你显式选择 `imagesJson` / `imageCount` / `firstImageUrl` 时才发**短时签名直链**，由厂商
机器人经本机入站面取图），见第四节 G3；消息列表只投递给你为「会话名 + 触发对象」配置的
下游 Webhook，见第四节 G4。除此之外还有几处
**不涉及聊天内容**的出网点（头像、远程图片/视频、地图底图、语音模型下载，以及只发凭据的
**连接测试 / 余额查询**），第四节逐条列明。

**入站方向**：本应用**默认不监听任何端口**，别人无法从网络连进来。只有两种需要你显式触发的例外：① 标题栏「打开网页」交接（临时起服务，默认浏览器打开，点卡片返回即停）；② 设置 → 维护与自检 → 局域网访问（手机）的扫码入口（默认关闭，关闭/退出/轮换即停）。两者都见第四节 H；交接会话与桌面端同权限，点卡片返回即恢复「一个端口都不监听」。原来的「远程访问（手机）」设置已移除，扫码入口现在在「维护与自检」里。局域网访问开启期间，既有监听面还提供第四节 H.1 的消息列表入站 Webhook；它不另开端口，关掉局域网访问或轮换令牌即失效。

> **应用内没有任何全局出网开关**：本声明第四节列出的每一个出网点都会按描述发出请求，
> 应用里没有可以逐个关掉它们的按钮。要阻止这些请求，只能靠系统防火墙或直接断网
> （见第五节）。**"参与语义检索"是文件级的数据范围开关，不是出网开关**：它决定某个
> 知识库文件是否进入向量索引，关掉之后该文件完全不出网。

## 一、我们读什么

### 1. 本机微信数据（只读）

- 解密后的 SQLite 库：消息、联系人、群成员、朋友圈、收藏、转账记录等；
- 媒体缓存：图片、视频、语音、文件的本地副本与我们自己的解码缓存。

这些数据来自你**自己**的微信安装（`Weixin.exe`）与数据目录。应用把它们解密、
复制到自己的数据根后**只读**使用。

### 2. 运行中的微信进程内存（只读，用于取数据库密钥）

微信 4.x 的数据库密钥不以明文存在磁盘上，只在**运行中的微信进程内存**里。
因此「自动获取密钥」会：

- 通过 Win32 API（`OpenProcess` → `VirtualQueryEx` → `ReadProcessMemory`）**只读**扫描
  `Weixin.exe` 进程的内存区域；
- 只挑「已提交、可写、非 guard」的区域，按已知的密钥模式匹配并用一个数据库文件校验命中结果；
- **不写入、不修改、不注入、不 hook** 微信进程，也不把扫描到的内存内容保存或外发；
- 命中后把密钥写入本机 `<数据根>/secrets.json`（权限收紧到当前用户）。

代码：`src/backend/wechat-data/src/keys/win32-memory.ts`、`keys/service.ts`。
微信未运行时该能力不可用，可改为手动填写密钥。

### 3. 本机密钥材料与配置

图片密钥可从微信的 kvcomm 缓存（`*_input.statistic` 文件名前缀）与
`%APPDATA%\Tencent\xwechat\config\*.ini` 推导；这只读本机文件，不外发。

### 4. 设备指纹（用于授权）

授权校验需要一份设备指纹（机器标识的哈希）。它**只在本机计算**，写入你导出的
`activation-request.json`；只有你**主动**把该文件交给签发方时才离开本机。

### 5. 运行中的微信进程（可选：原图自动下载，默认关闭）

设置 → 图片解码里的「微信原图自动下载」是一个**默认关闭的实验功能**。只有你显式打开后，
应用才会把上游 WeFlow-X（MIT）的 `img_helper.dll` 注入正在运行的 `Weixin.exe`，
让微信在**接收新图片时**按它自己的策略下载高清原图（本应用自己不向微信服务器发请求、
不接触登录凭据）。它的边界：

- 只影响**打开之后**新收到的图片；历史图片不会补下载（仍需在微信里点开原图，
  由「原图自动收割」接住）；
- 会**修改微信进程内存**（这是它唯一的越界点，也是默认关闭的原因）；关闭开关或退出应用时
  应用会调用 `UninstallImgHelper` 还原；
- 应用被强杀/崩溃时，微信可能保持被修改状态直到**微信重启**；下次启动会在界面上如实提示
  （`cleanupUnconfirmed`），并拒绝在微信未重启时重复注入；
- 仅 win32-x64，微信版本兼容性未声明；组件在加载前按 SHA-256 校验，不一致直接拒绝；
- 组件来源、许可与已知边界见
  [`src/backend/wechat-data/native/img_helper/PROVENANCE.md`](../src/backend/wechat-data/native/img_helper/PROVENANCE.md)
  与 [`src/backend/VENDORED-LICENSES.md`](../src/backend/VENDORED-LICENSES.md)。

代码：`src/backend/wechat-data/src/query/wechat-image-autodownload.ts`。

## 二、我们不做什么

- 不登录微信、不发消息、不改动微信的任何文件或数据；
- 不写注册表、不安装驱动；**默认不挂钩（hook）微信进程** —— 唯一例外是你显式打开
  「微信原图自动下载」实验功能（默认关闭；打开后会注入组件让微信自己下载新图片的原图，
  见 1.5 节）；
- 不收集遥测、不做崩溃上报、不做使用统计；
- 不把数据库、聊天记录、图片或导出物上传到我们的服务（我们没有这样的服务）；
- **不监听任何端口、不接受任何入站连接** —— 只有两个显式例外：标题栏「打开网页」交接（临时启动，点卡片返回即停）和设置 → 维护与自检 → 局域网访问（手机）的扫码入口（默认关闭，关闭/退出/轮换即停；见第四节 H）。日常运行与启动时都不监听；
- 不在后台偷偷调用模型：AI 调用只由你的操作触发（提问、总结、定时总结任务、
  知识库的「生成摘要 / 语义索引 / 抽取实体 / 找链接建议」四个按钮）。

## 三、数据存在哪里

| 路径 | 内容 | 保护 |
|---|---|---|
| `<userData>\wechat\config.json` | 路径配置与非敏感设置镜像（**不含**密钥） | 目录权限收紧到当前用户 |
| `<userData>\wechat\llm.json` | 模型接口地址与 **API Key**（可保存多套已配置的模型，切换时整体替换） | 同上 |
| `<userData>\wechat\logs\` | 诊断日志（出网相关内容会脱敏） | 同上 |
| `<userData>\wechat-data\` | 数据根：`decrypted\`（解密库）、`decoded_images\`（图片缓存）、检索/笔记/待办库 | 同上 |
| `<数据根>\secrets.json` | 微信解密密钥（db / image / xor / api_token） | 原子写入 + 仅当前用户可读 |

除上表之外，`<数据根>\wechat_privacy.db` 保存三类**本机元数据**：AI 出站审计（见第七节）、
导出历史（每次导出的路径与参数），以及**问答历史**（每次问答的问题、回答与引用来源，
供「微信问答 → 历史记录」回看）。三者都只存在本机、按数据根隔离，**不参与任何导出或分享**；
问答历史与导出记录都可以在界面上逐条删除或整体清空。

### 任务信息与消息列表（`<数据根>\wechat_task_center.db`）

「任务信息」与「消息列表」共用同一个本机 SQLite 库，但表与领域独立：

| 表 | 内容 |
|---|---|
| `task_info` / `task_triggers` | 任务配置、触发记录、投递状态与厂商凭据（凭据列不返回普通列表） |
| `message_list_records` | 回复台账：回复 id、会话与触发对象、**触发文本**、图片引用、触发时间、来源、状态、备注、下游地址快照、错误与尝试次数 |
| `message_list_rules` | 按「会话名 + 触发对象」匹配的下游 Webhook、问候语与启用状态 |

消息列表的图片只保存微信本地引用、`http(s)` 地址或受限大小的安全 `data:image`，不接受任意
本机路径。台账与规则都只在本机，不参与 AI 索引或普通导出；删除对应记录请使用界面操作。

消息列表附件在跨机投递前会复制到 `<数据根>\message-list-spool\`，记录只保存随机
`stagedId`、展示文件名、大小与 MIME，**不保存源文件绝对路径**。暂存只允许桌面端通过
`stageMessageListAttachment` 创建（HTTP 远程通道为 `LOCAL_ONLY`）；Webhook 入站明确禁止提交 stagedId，
因此外部请求不能借记录引用桌面端文件。未被任何消息记录引用的暂存文件保留 7 天后清理；
正文与附件必须拆成两条消息记录，投递时才由消息列表读取本机字节、上传到发送端换取 `resource_id`。

`<userData>` 在 Windows 上是 `%APPDATA%\Super Time`。**安装目录保持只读**：
升级或卸载不会带走你的配置，也不会把本机路径与密钥带到其他机器。

删除数据 = 删掉 `<userData>\wechat` 与 `<userData>\wechat-data`（或你在设置里指定的数据根）。
卸载程序不会自动删除它们。

## 四、网络暴露面清单（出网点 + 入站监听，与代码逐条对应）

> A–G4 是**出网**（本机向外发请求）；**H 是入站**（本机监听端口、别人向本机发请求）。
> 两类都登记在这里，因为「我的数据会不会被别的设备看到」这个问题两边都要答。

### A. AI 调用：LLM chat（发的是**内容**）

| 项 | 说明 |
|---|---|
| 触发 | 微信问答、每日总结、周期总结、群总结任务，问答的「查询改写/优化」，单聊里的「**推荐回复**」，知识库文件详情里的「**生成摘要**」，以及 AI 年度回顾叙述（**按月分段**，每段最多 4,000 字，逐段发出该月的聊天片段） |

| 目的地 | 你配置的 `llm.json` 里的 `apiUrl`（默认 `https://api.openai.com/v1`） |
| 开关 | ⚠️ 应用内**没有出网开关**：这一条会按上面的描述发出请求。<br/>✅ 「敏感字段打码」开启时发送前脱敏（它只改发出去的字节，不是出网开关）；<br/>✅ 文件级：关掉「参与语义检索（会出网）」的文件**直接拒绝生成摘要**，不改标志位也不发送 |
| 审计 | ✅ 每次放行都记入本机审计表（功能、次数、字符数），可导出 CSV |
| 代码 | `gateway.ts` 的 `privacyGate(...)`（`ask_wechat` / `daily_summary` / `period_summary` / `summary_task` / `ask_optimize` / `kb_file_summary` / `suggest_reply` / `annual_narrative`） |

### A2. 模型账户类请求：连接测试 / 余额查询（发的是**凭据**，不是内容）

> 2026-09-30 新增。用户要求「给 AI 大模型增加链接测试按钮和余额查询接口，余额实时显示在主界面左下角」。
> 它**不是**内容出网点（一个字节聊天内容都不发），但确实是**出网**，所以照样逐条登记 ——
> 尤其第二条是**无人值守**的定时请求，这一点必须写明白。

| 项 | 说明 |
|---|---|
| 触发 | ① 「设置 → AI 大模型」里的**「测试连接」**（主模型）、**「测试向量」**、**「测试精排」**三个按钮（显式点击，用当前表单的地址与 Key，不必先保存）；② 同面板的**「查询余额」**按钮；③ **主界面左下角（设置按钮下方）的余额条**：挂载后查一次、之后**每 5 分钟一次**（无人值守），点它会立刻刷新 |
| 发出内容 | **只有 API Key**（`Authorization: Bearer`）。三条测试的差别要写清：**测试连接**是 `GET /models`（不发任何内容、不产生费用）；**测试向量 / 测试精排**各发一条**固定的测试串**（`连接测试`，约 3 / 6 个 token）—— 不是你的聊天内容、不是文件名、不是查询词。余额查询不带任何 body。全部动作都不发账号信息与本机路径 |
| 目的地 | 你配置的三套端点（可各不相同）：主模型 `apiUrl` 的 `/models`；向量 `embeddingApiUrl`（留空回落 `apiUrl`）+ `embedPath`（默认 `/embeddings`）；精排 `rerankApiUrl`（留空回落）+ `rerankPath`（默认 `/rerank`）；余额按厂商惯例 —— DeepSeek 打 `{origin}/user/balance`（注意**不带 `/v1`**），其余厂商先 `{base}/user/info`（SiliconFlow 惯例）再退 `{base}/user/balance` |
| 开关 | ⚠️ 应用内**没有任何全局出网开关**（与 A / B 同口径）。唯一按会话生效的例外是「AI回复」，默认关闭且不改变手动问答；要让它不发生：断网 / 在系统防火墙里禁止本应用出站；或在「AI 大模型」里**清空 API Key** —— 清空后余额条自动隐藏、也不再发任何请求 |
| 审计 | ❌ **不进** AI 隐私审计表 —— 那张表按「哪一类数据出了网」分列，而这两条不发数据。失败原因与耗时只在界面提示（余额条把原因放在悬浮提示里） |
| 厂商差异 | 部分厂商（如 OpenAI）**不提供**余额接口：此时会明确报「余额查询失败：… 404」，界面显示「余额 —」而不是一个编造的数字。查不到余额不影响问答与总结 |
| 代码 | `src/backend/llm-balance.js`（地址推导 `balanceUrlsFor` / 解析 `parseBalance` / 取数 `testLlmEndpoint`、`queryLlmBalance`）；IPC `wechat:llm-test` / `wechat:llm-balance`（`src/backend/ipc-wechat.js`，preload 暴露面同步）；出网统一走 `src/backend/llm-http.js`；界面 `panels/llm-probe.tsx`（四条探针）、`panels/SidebarBalance.tsx`（左下角余额条） |

### B. AI 调用：embedding（发的是**内容**）

| 项 | 说明 |
|---|---|
| 触发 | ① 微信问答的稠密检索通道（把检索到的聊天片段向量化）；② **知识库问答**：把「参与 RAG」的文件**块正文**送去向量化，用于建/补该库的向量索引；③ 「知识库 → 文件」面板上的**「语义索引」按钮**（你主动点才发，只发当前这个库）；④ 同面板的**关键词+语义检索**：只发**你输入的那句查询词**，库内正文不外发；⑤ 单聊「推荐回复」与已开启的 **AI回复**在勾选知识库后做混合检索时，把**最近对话文本**作为查询词送去向量化（审计功能名 `kb_embed`；与 ② 的建索引不同，这里发的是查询而不是文件正文） |
| 发出内容 | 待向量化的文本（按配置截断）：① 检索到的聊天片段；② **你选进知识库、且没有关掉「参与 RAG」开关的文件正文**；③ 同 ②（按钮触发的建库）；④ 检索词本身；⑤ 当前会话最近的对话文本（仅作为检索查询词，不附文件正文；未配置向量模型或关闭稠密通道时这一条不会发生） |
| 目的地 | 同 A（`apiUrl` + `embedPath`，默认 `/embeddings`） |
| 开关 | ⚠️ 没有出网开关。✅ 「敏感字段打码」发送前脱敏；两处的**审计功能名分开记**（`ask_embed` = 聊天片段的向量化；`kb_embed` = 知识库侧的建索引正文、以及知识库检索用的查询词），这样「我把哪一类数据发出去了」在审计表里分得开。逐文件的「参与语义检索」开关关掉后，该文件**连候选都进不来**（条件写在取语料的 SQL 里，不是取回后再过滤） |
| 代码 | `gateway.ts` 的 `makeEmbedFn`（`feature` 参数）/ `privacyGate` / `buildKbVectorIndex`；消息侧 `query/retrieval/embedding.ts`；知识库侧 `query/kb-vectors.ts` |

> 未配置模型时这两条链路都不会发生：问答直接报「未配置模型」，检索退化为纯本地稀疏通道。
> 知识库侧还有一道**文件级**闸门：「参与 RAG」开关（`kb_files.include_in_rag`）。
> 关掉它的文件，正文既不会进向量索引、也不会被发给模型 —— 该条件写在**取语料的 SQL** 里，
> 不是拿到结果之后再过滤（后过滤会让不许出网的文件先占满名额再被丢掉）。
> ⚠️ 但这**不等于「搜不到」**：它的正文仍留在本机关键词索引（FTS5）里，
> 「关键词检索」在本机就能命中它（不出网、不产生审计记录）；被挡住的只是出网那一路。
> 索引是**按库**建的：在哪个库里提问，就只把那个库的正文送去 embedding。

### B2. 模型精排（把候选正文发给重排序模型）

| 项 | 说明 |
|---|---|
| 触发 | 问答检索融合出候选之后。**只在「数据配置 → AI 大模型」的重排序模型名非空时发生** —— 这个字段没有独立开关，填了就启用（留空则整段跳过，顺序由本地启发式给出） |
| 发出内容 | 你的查询词 + 头部若干条候选的**正文**（默认上限 60 条；聊天片段与知识库文件正文都算候选）。不发出答案、不发出你的身份标识 |
| 目的地 | 同 A（`rerankApiUrl` 留空则回落 `apiUrl`；路径 `rerankPath`，默认 `/rerank`） |
| 开关 | ⚠️ 没有出网开关（**只在「重排序模型」那一栏填了模型名时才发生**，留空则整段跳过）。逐文件另有「参与语义检索」开关 —— 关掉的文件连候选都进不来。精排失败**不会让问答失败**，只是退回本地加权并在依据行写明 |
| 审计 | 功能名 `ask_rerank`（独立一列）。名字里不写 `kb_` 是因为候选既可能来自聊天记录也可能来自知识库文件 |
| 代码 | `gateway-llm-factory.ts` 的 `makeRerankFnOf`（整批过 `privacyGate`）；`query/retrieval/pipeline.ts` 的融合后精排阶段；`llm-bridge.js` 的 `rerank()`；出网统一走 `llm-http.js` |

> **一处必须说清的副作用**：开启「敏感字段脱敏」时，送出去的是**脱敏后的文本**。
> 脱敏是五条正则（手机号 / 身份证 / 银行卡 / 邮箱 / 口令），它不认识上下文 ——
> 文件正文里连续的 16–19 位数字（订单号、无连字符的 ISBN、时间戳串）会被整段替换成 `[银行卡]`。
> 也就是说**模型读到的字节与落库的原文不同**，而审计表只记录字符数、不记录被改写了什么。
> 这会影响精排的相关性判断（极端情况下把一条本来最相关的候选排到后面），
> 但不会把未脱敏的内容发出去。

### B3. 文档实体抽取（把文件正文发给语言模型换一批名字）

| 项 | 说明 |
|---|---|

### B4. 笔记的链接建议（把正在写的正文发给向量模型）

| 项 | 说明 |
|---|---|
| 触发 | 笔记编辑器里的**「🔗 找链接建议」按钮**（`kb_link_suggest`）。刻意**不**随打字触发 —— 那样会把同一句话发几十遍 |
| 发出内容 | 你正在写的**标题 + 正文**（截到 1,200 字）+ 本库的候选名字（已有笔记标题与上一步抽出的实体，最多 80 条短字符串）。不发给模型的是：别人的聊天内容、你的身份标识 |
| 目的地 | 同 B（本库的嵌入模型） |
| 开关 | ⚠️ 没有出网开关（**只有你点「🔗 找链接建议」才会发**，不随打字触发）；✅ 没配嵌入模型时直接报「未配置」，一个候选都不取 |

| 代码 | `gateway.ts` 的 `suggestKbLinks`；`query/kb/suggest.ts`（纯排序，无写路径） |

> 因此模型判错的代价是「你没点」，而不是「正文里多了一条你没写过的链接、还进了图谱」。

### C. 头像图片（不发内容，但会暴露你关注了谁）

| 项 | 说明 |
|---|---|

### D. 远程图片 / 视频 / 公众号封面（不发内容）

| 项 | 说明 |
|---|---|
| 触发 | 表情原图、**聊天图片的原图**（只有你显式动手才会发请求：逐条点图片下方的「取原图」，或在「设置 → 图片解码」点一次「批量取原图」；**没有任何后台自动批量取**，进会话/滚动都不会触发它）、朋友圈视频与封面、公众号文章封面在本机没有缓存时，后端按消息里的地址取回；**滚到卡片缩略图或朋友圈图片**时也算 —— 渲染层不再自己去取，而是把地址交给 `getRemoteImages`（本机缓存优先，未命中才出网） |
| 目的地 | 微信 CDN（消息 XML 里的 `cdnurl` / `<url>` / `<thumb>`；聊天图片走 `tpurl`/`tphdurl` 直链；头像走 `qlogo.cn`，**主机白名单固定为** `qq.com`、`weixin.qq.com`、`wechat.com`、`wechatcdn.cn`、`qpic.cn`、`qlogo.cn` 六个后缀），公众号文章页**只允许** `mp.weixin.qq.com`。**这条白名单现在管到所有由后端代取的图片、头像、视频与公众号文章页**（原图、朋友圈封面/视频、卡片与朋友圈的远程图、`getRemoteImages` 代理入口）——清单判在发请求之前，主机不在里面就一个字节都不发 |
| 开关 | ⚠️ 没有出网开关：本机没缓存就按消息里的地址去取（**已有缓存照常可用**，不会因为取不到就丢图）。<br/>✅ **域名白名单**（`query/cdn-hosts.ts`，唯一出处）：图片/头像/视频地址主机不在上面那六个后缀内就拒绝发请求，公众号文章页另收窄为 `mp.weixin.qq.com`（消息 XML 是可被离线改写的文件，不能让它指定我们去哪儿）；带凭据的 URL 一律拒。<br/>✅ 远端回来的加密流一律用 `<enc key>` **本机解密**（没有"服务端解密"这个选项）。 |
| 记录 | 取回成功/失败会写进**操作记录**（功能名 `sns_cover_fetch` / `sns_video_fetch` / `image_original_fetch` / `remote_image_fetch`）；批量取原图走同一个 `image_original_fetch`（目标写「批量」），并在本机落一份 `<解码缓存>/.originals-index.json`（**只有 md5 与时间戳**，用于下次续跑不重下）。注意这些**不进** AI 的那张隐私审计表 —— 它们不是模型调用，审计表按「哪一类数据出了网」分列，混在一起就会把「我把消息正文发给了谁」这条查询问成一个含糊的数 |

> 代价要一并写清：① 代理只代取白名单内的微信系主机，指向站外图床的第三方封面 / 头像不显示（内容与卡片照常可读）；② 站外地址里的 `http` 图片（实测朋友圈 1,125 张里 1,104 张是 http）后端也只取 https，所以那部分要靠本机解码或微信里点一次；③ **表情图与朋友圈视频导出这两条链在 2026-09-30 补齐了同一道主机白名单** —— 此前它们只判协议，等于「消息 XML 里写哪个主机就去取哪个」；现在站外地址一律不发请求，且拒绝时会写明是哪个主机。
> 剩下仍由界面直接发出的只有地图底图数据（E 段）与语音模型下载（F 段）—— 两条都**没有**应用内开关。

> **这条能力的边界（2026-09-26 实测，脚本 `working/probe-original-coverage.ts` 与
> `working/probe-wecom-403.ts`，可自行复核）**：本机 51,983 条图片消息里，**16.5%** 带
> `tphdurl`/`tpurl`（8,604 条）、**81.6%** 只带 `cdnbigimgurl`/`cdnmidimgurl`（42,433 条）。
> 但这 8,604 条直链**实测一条都取不到**：它们全部指向企业微信的
> `wwfile.work.weixin.qq.com/cgi-bin/download?f=…&t=…&p=1`，匿名 GET **一律 403** ——
> 与消息新旧（**20 分钟前**的新消息同样 403）、请求头（裸 UA / 加 `Referer: work.weixin.qq.com`
> / 加图片 `Accept`）都无关，URL 里也没有 `tpauthkey`。也就是说**有链接 ≠ 能取**：这类是
> 需要企业微信登录态的服务端令牌端点，和 `cdnbigimgurl` 同类待遇（不取）。
> 真正能取的只有带 `tpauthkey` 的免登录直链（个人微信账号上是常态，本机这份数据里一条都没有），
> 因此「取原图」对它们会明确回一句「这条没有免登录直链，请在微信里点开一次」。
> 那部分指针技术上要的是**微信登录态凭据**（会话密钥 / 设备签名），也就是「以你的身份向微信
> 服务器发请求」—— 本应用**不做**，也不会去做：它和本文开头「不登录、不发送消息、不连微信
> 服务器同步聊天记录」是同一条承诺的两端。**因此「任何情况下 100% 拿到原图」在守住这条承诺的
> 前提下不可能成立**；能做的是把不越界的部分做到最大，并把剩下的缺口与补救动作说清楚。

### D2. 第三方原图服务 `wxcdn.c3o.re`（**默认关闭**，按流量计费）

| 项 | 说明 |
|---|---|
| 触发 | **只有你在「设置 → 图片解码 → 第三方原图服务」里手动开启后**才会发生。开启后，本机没有原图的聊天图片在解码时会自动向该服务请求一次（`getImageDataUrl` 内部，无需你逐张点）。**默认关闭**，关着时一个字节都不发 |
| 目的地 | `https://wxcdn.c3o.re`（`POST /token` 换凭证、`GET /download` 取原图）。⚠️ **这不是腾讯官方服务**，是第三方 |
| 发出内容 | ① `POST /token` 的 multipart 里带**本机微信的 `global_config` 与 `global_config.crc` 两个文件的字节**，以及微信账号目录名（`wxid_xxx_<hash>`）；② `GET /download` 带该图片的 `cdnbigimgurl` fileid 与图片 `aeskey`。**不发聊天正文、不发通讯录、不发数据库** |
| 开关 | ✅ **有真开关**（本声明里除入站监听外唯一带开关的网络面）：`wxcdn_original_enabled`，默认 `false`。关掉即停，已下载的原图留在本机缓存里照常可用 |
| 代价 | **按流量计费**（Free 套餐 50 MB/天，实测一张 2.7 MB 就扣 2.7 MB）。界面显示剩余额度，可随时「查额度」 |
| 记录 | 走 `image_original_fetch` 那一条操作记录（与 D 段同口径），`via` 写 `wxcdn` |
| 代码 | `query/wxcdn-original.ts`（协议客户端：换 token + 下载 + 额度）、`query/image-auto-upgrade.ts` 的 `tryWxcdnUpgrade`（第三条升级路径）、`remotes/media.ts` 的 `getWxcdnQuota`、`panels/use-third-party-original.ts`（开关与额度） |

> **为什么它存在**：D 段那 81.6% 只带 `cdnbigimgurl` 的图片，本机没有原图、也没有免登录直链。
> 这个第三方服务接受本机微信配置换 token，然后按 fileid 返回原图字节 —— 不需要登录、不需要读
> 进程内存、不需要 hook。**它把「本机配置」发给了第三方**，所以默认关闭、必须你显式开启，
> 且额度与计费在界面上写清楚。
> 实测（2026-10-17）：token 签发成功、下载 8/8 成功、字节数与 XML 的 `hdlength` 完全一致；
> 带 `key=` 时 6/6 拿到真图片（JPEG/PNG，最大 2,751 KB）。
>
> **2026-10-17 补充实测（`working/probe-*.mjs`，脚本不入库）—— 把「读进程内存」这条路也堵死了**：
> ① 扫微信主进程 862 MB 内存，确实找到 `tpauthkey`（806 处）与 `sessionkey`（128 处）；
> ② 但把 `tpauthkey` 拼进 URL 的 **5 种变体全部 403** —— 它是给 mmtls 私有协议用的，不是 HTTP 凭据；
> ③ 内存里有 225 个完整 JPEG，但与数据库 48,882 个图片 md5 **交集为 0** —— 那是界面渲染缓存；
> ④ 内存里 4,014 个微信系 URL 中能直接 GET 的（`mmbiz.qpic.cn` 等）**全是公众号图/朋友圈图**，
>    URL 里含聊天图片 md5 的为 **0 个**。
> 结论：**聊天图片走 mmtls 私有 RPC，不是 HTTP 直链**。微信拿到字节后直接解密渲染，内存里留下的是
> 像素而不是可复用的 URL。要自己取，必须重写 mmtls + 私有 RPC 调用 —— 那是重写半个微信客户端。
>
> **因此本应用改走「收割」而不是「抓取」**：微信**自己**会下载原图（用户点「查看原图」时落盘
> `<md5>_h.dat`，实测本机 1,459 个且仍在新增）。`query/original-harvester.ts` 盯住这个落盘动作 ——
> **微信负责下载，我们负责收割**：不联网、不碰凭据、不注入进程。界面入口在「设置 → 图片解码 →
> 自动收割原图」（`originalHarvest` Remote，四个动作 `start`/`stop`/`status`/`now`）。
> 边界照旧：**只收割用户已经在微信里点开过的图**；没点开过的，微信磁盘上根本没有 `_h.dat`，
> 本应用也变不出来 —— 这是微信的下载策略，不是实现缺陷。
> （原先这里指向 `docs/WXHOOK-ORIGINAL-IMAGE-EMBED.md` 附三的覆盖率矩阵 ——
> 那份文档已随 2026-10-08 的文档精简删除，原文在 git 历史里：
> `git log --diff-filter=D --name-only -- docs/` 可列出，`git show <commit>^:docs/<文件名>` 取回。）

| 读取范围 | 只读当前会话（账号 + `chatUsername`，单聊与群聊都一样），最多 80 条候选、最终最多 60 条、约 6,000 token 上下文预算；所有可回复的对话类型会进入上下文，媒体/卡片缺少展示文本时使用稳定占位或已有标题。**群聊只回复 @我 的消息**，其余群消息只作为上下文。相邻消息间隔超过 3 小时时，提示词里会插入一行固定说明 `（以上是更早的对话，与本条没有直接关系）`，提醒模型断层之前只作背景（该行只进提示词、不进检索正文，且计入 token 预算）。**会话级「上下文时间窗」**可在「AI回复设置」里选（默认「不限」＝最近 60 条；可选 1 / 3 / 6 / 12 小时、1 / 3 / 7 天）：设了窗口后只把窗口内的消息送进提示词，起点以**触发那条消息的时间**为准，窗口外的正文、图片与语音整条排除；窗口与 60 条上限、token 预算叠加生效（窗口不会突破这两个上限）。**语音消息会先在本机用 whisper 转成文字再进上下文**（最多 5 条、总预算约 45 秒；超预算或转写失败的保留 `[语音 …]` 占位；转写走本机子进程，不联网）。**每条消息都带自己的本地时间前缀**（`[2026-11-18 00:15] 对方：…`）。卡片类消息会补上模型需要的细节：转账金额、红包金额与祝福语、引用消息的被引用原文与发言人、语音/视频时长、通话类型与结局、位置地址。最多附带 3 张、合计不超过 6 MiB 的图片/自定义表情。单条正文保留开头和结尾（至多约 600 字），按时间正序送入模型。视觉媒体只在生成前从当前会话的消息定位键解码，不读取其它会话、通讯录、朋友圈或数据库文件。**勾选「知识库参与回复」并选中某个库时**，额外用最近对话检索该库（只读 `include_in_rag = 1` 的文件片段，不读其它库、不读笔记全文库表，也不把检索结果写回知识库），最多取 3 段。聊天正文与知识库片段都按**不可信资料**处理，不能改变系统提示词或工具权限 |
| 模型调用 | 经隐私闸 `ai_reply_analyze` 后调用设置中的当前对话模型，最多生成一条可直接发送的中文回复（输出上限 600 tokens）。system 由后端固定安全规则 + 当前会话可配置的人格/回复风格组成；勾选知识库时再追加命中的知识库片段（标为不可信材料，材料预算 3,000 字）。检索本身在稠密通道启用时还会把最近对话文本作为查询词发给向量模型（功能名 `kb_embed`，与推荐回复同一条通道；未配置向量模型时只用本地词法检索）。人格与知识库都只能追加事实依据/语气与措辞偏好，不能覆盖防注入、隐私脱敏或输出约束。当前模型支持图片输入时会收到本轮解码后的图片与表情内容块；模型或端点拒绝图片时自动去掉视觉内容并降级为纯文字理解一次。人格修改会推进该会话 revision，并取消尚未完成的旧回复；这是**无需点击**的自动模型调用，开启开关即授权该会话后续新消息触发 |
| 落库与幂等 | 回复必须先写入消息列表 `message_list_records`，来源固定 `ai_reply`：确定 `sourceRef` 后、调用模型前先落一条**空正文 pending 预约**（备注「AI 回复 · 生成中」，不保存 Webhook 地址）；模型生成后在同一事务补全整组正文，只有**已有正文**的记录才允许投递。幂等键为 `ai-reply:<账号>:<会话>:<消息时间>:<localId>`。重复键返回 `created:false`：已有正文的 pending 可恢复补投；空白预约若没有对应生成快照，无法证明模型是否执行，按 fail-closed 收口，**不重新生成、不投递**。落库失败不投递；落库成功但投递失败时保留记录并把状态标成「已写入消息列表但投递失败」，可由用户在消息列表显式重发 |
| 发出内容 | **模型侧**：`ai_reply_analyze` 发送“固定 system 安全提示词 + 当前会话人格配置 + 最近上下文提示词”（正文按 60 条 / 约 6,000 token 预算裁剪，单条保留首尾，每条带本地时间前缀，语音已在本机转写为文字，卡片类带金额/结局/地址等细节），人格与上下文分别按隐私闸处理。**勾选知识库参与回复时**，system 里还会带上该库检索命中的最多 3 段文件片段（带文件名，合计预算 3,000 字），与人格/上下文一起过同一道隐私闸；检索失败或空命中时按普通对话回复，不发送任何知识库内容，也不会造假材料。本轮有可用图片或自定义表情时，还会发送**最多 3 张、合计不超过 6 MiB**的视觉 data URL 多模态内容块（按对话时间正序，只含字节与 MIME，不含本机路径、文件名或 md5）；视觉字节不做文字脱敏。纯文本模型或拒绝图片的端点会自动收到一次去视觉后的文字上下文。数据库文件、其它会话、通讯录或朋友圈不发。**发送侧**：消息列表按「会话名 + 触发对象」匹配规则并投递该条 AI 回复。`/send/text` 只发 `{talker,text}`（`talker` 为会话 wxid，`text` 为回复正文），且只有 HTTP 2xx + `{"ok":true}` 才算成功；`/webhook/<token>` 私聊只发 `{target,message}`，群聊发 `{target:群名,message,mention:提问者}`（**同一批次的后续消息不再重复 @**，只有首条点名提问者；未解析到提问者时整批发 `{target,message}`）；`/send/text` 无 mention 字段，群聊只保证发到群、不 @ 人。token 仅来自你配置的 URL，应用不内置、不复制到台账；其它地址继续使用通用消息列表 JSON 请求体，不猜测未登记协议。正文在投递前还要过 `task_callback` 隐私闸 |
| 不发送（发送侧） | Feather 请求不附带本机数据库、其它会话、通讯录、朋友圈或模型提示词，也不把本机绝对路径作为附件。跨机资源先由桌面端复制到 `<数据根>\message-list-spool\`，记录只保存随机 `stagedId` 与展示元数据；`stageMessageListAttachment` 属于 `LOCAL_ONLY`，Webhook 入站明确禁止提交 `stagedId`。投递时读取本机字节并一次性上传，换取 40 位 hex `resource_id`；发送端只按 ID 读取它自己 spool 内的文件，不依赖 SMB/共享目录。附件最多 9 件，单件及整组均 ≤20 MB。**正文与附件必须拆成两条消息记录**。上传文件在发送端默认保留 7 天，仅清理未被任务引用的过期文件；磁盘配额仍由部署方负责。Webhook 错误若回显完整地址，落库前会去掉查询串与路径令牌 |
| 开关与控制 | 聊天窗口**顶部**的「AI回复」按钮逐会话开关（纯图标，开启后高亮），**单聊与群聊都可开启**；开启后紧邻的「AI回复设置」按钮（齿轮）编辑该会话的人格名称与回复风格、**上下文时间窗**，并可勾选「知识库参与回复」后选择参与的知识库（默认不勾选；勾选后未选库会被拒绝保存）。默认关闭，切换会话不会串用设置。群聊里真正触发回复的是「点名 @我」的消息（结构化 `atuserlist`，`@所有人` 不算）。要停止自动调用：关掉该会话开关或退出应用。要停止投递：同时停用/删除匹配的消息列表规则；已有失败记录只能由用户在消息列表显式重发。**要清掉本机留痕**：在消息列表删除对应记录（会一并删除该记录的过程留痕） |
| 失败与重试 | 知识库检索失败（通道关闭、向量库忙、库已删除）只记录操作日志并降级为普通对话回复，不阻断自动回复；语音转写失败（引擎或所选模型未安装、SILK 解码失败、超出 45 秒总预算）只保留 `[语音 …]` 占位，不阻断回复，转写成功的条目按 svr_id 缓存在本机；图片/表情解码失败、坏图或超预算只跳过该视觉内容，不阻断纯文字回复；模型或端点明确拒绝图片（400 / 415 / 422 或 image / vision 相关错误）时，只做**一次去视觉降级**，不是重试原视觉请求。除此之外，模型失败、上下文为空、消息列表写入失败都不自动重试；投递失败也不自动重试，避免下游重复发微信消息。设置写入使用 revision CAS；扫描积压时合并到最新一条对方消息，不逐条补答旧消息；恢复或投递前发现会话已推进时，旧 pending 只收口、不生成也不投递；没有正文的预约不进入 `waiting_config`，只有已有正文、仅缺地址时才标记待配置；会话复核读取失败时暂缓投递而不是假定没有新消息。若下游返回成功但台账仍停在 `pending`，转为 `sent_unconfirmed` 供人工核对，禁止自动批次再次发送。`SQLITE_BUSY` / `SQLITE_LOCKED` 只做有限短退避，不当作租约丢失。后台失败写入会话级状态，不阻塞微信同步主流程。崩溃遗留的 `dispatching` 默认只在超过 5 分钟投递超时窗口后收口为 `sent_unconfirmed`；记录同时保存投递认领进程（owner），owner 进程已退出时可立即收口，仍存活的另一进程正在发送的记录不会被误伤 |
| 审计与落库 | 模型调用前以 `ai_reply_analyze` 记入本机 AI 出站审计（字符数 / 会话数 / 消息数，system 与上下文均经过隐私闸）；消息列表投递再以 `task_callback` 审计。开关、人格、知识库参与设置（是否启用与库 id）、水位、阶段、最近记录 id 与错误保存在 `<数据根>\wechat_task_center.db` 的 `chat_ai_reply_settings`；正文保存在同库 `message_list_records`。**过程留痕**保存在同库 `chat_ai_reply_traces`（主键为消息记录 id）：本轮实际发出的上下文、知识库命中、system/user 提示词、模型名、图片与语音数量、模型输出、各阶段时间戳与错误，单字段有上限（上下文 4 万字、提示词各 2 万字、输出 2 万字、知识库 8 千字）。留痕只写入本机、不出网，仅供「消息列表 → 记录详情 → 回复过程」查看；记录被删除时同事务清掉对应留痕，不留孤儿聊天正文 |

### H. 入站监听：打开网页交接 + 局域网扫码（2026-10-19 v22）—— **不是**出网点，但同属暴露面

> 2026-10-14 新增（v13）；2026-10-15 改为一次性配对码（v14）；2026-10-19 曾移除手机
> 远程访问设置、只留「打开网页」交接（v20）；**同日 v22 按用户需求恢复「局域网访问（手机）」**。
> 它与 A–G 的方向相反：**本机监听、别的设备连进来**。两种入口都必须由用户在桌面端显式触发，
> 默认关闭，没有任何常驻监听或启动自启。

| 项 | 说明 |
|---|---|
| 触发 | **两种显式入口**：① 标题栏「打开网页」交接（点右下角卡片返回即停，`fullAccess`）；② 设置 → 维护与自检 → 局域网访问（手机）→「启用并生成访问凭据 / 轮换令牌」（关闭开关、退出或轮换即停）。**默认关闭**；启动时绝不按旧 `api_enabled` 自动监听。 |
| 监听什么 | 本机的**局域网 IPv4 地址**上的一个端口（默认 `5032`；被占用时顺移 5033–5042）。刻意**绑具体网卡地址而不是 `0.0.0.0`**；只在上述显式入口期间存在。 |
| 谁能连 | 同一局域网内能路由到该地址的设备都可能连到端口，因此必须持**一次性配对码**才能换会话：交接码只交给系统默认浏览器；局域网入口在桌面端显示二维码/链接，由用户自己扫码。 |
| 访问控制 | 桌面端在内存中生成**一次性配对码**：**5 分钟**寿命、**最多 5 次试错**、成功一次即作废；浏览器用 `?t=<配对码>&mode=desktop` 换取会话 Cookie（`HttpOnly` + `SameSite=Lax`，内存态、12 小时、重启/停服即失效）。长期 `api_token` 仍存 `secrets.json`，**不进二维码、地址栏或任何 UI**。Host 头必须等于当前监听的局域网 IP（回环监听额外接受 `localhost`），挡住 DNS rebinding。<br/>**权限**：两种入口都签发 **fullAccess** 会话（与桌面同权），因此二维码/交接链接等同于桌面端本人。 |
| 明确**不**开放 | 日常运行与启动时不监听；没有常驻开关/定时任务。fullAccess 意味着手机侧也能读写配置、模型 Key、许可证、诊断、备份与原生能力 —— 这是「和桌面一样」的代价，所以二维码只能给本人设备，关闭开关/退出/轮换要立即执行。 |
| 桌面交接会话 | ① 桌面端用 `shell.openExternal` 把 `http://<局域网IP>:<端口>/?t=<配对码>&mode=desktop` 交给系统**默认浏览器**；② 主窗口隐藏、右下角出现可拖动卡片，卡片只有「返回桌面应用」一个按钮；③ 浏览器内可执行与桌面端相同的方法，并通过 `/api/native/*` 弹出本机目录/文件对话框、截图导出、读写许可证/诊断/更新/远程访问设置；④ 这些请求只在本机主进程执行，不新增出网点、不上传到我们的服务；⑤ 点卡片后停服、作废全部会话与配对码，浏览器下一次请求即 401/连接失败。交接期间浏览器能看到桌面端能看到的全部内容（含密钥类配置），请把该窗口当作桌面端本人。 |
| 局域网扫码会话 | 设置 → 维护与自检 → 局域网访问（手机）里显式启用后，桌面端显示二维码/链接与配对码；手机扫码换来的会话是 **fullAccess**（与桌面端同一套方法，含配置写入与 `/api/native/*` 原生能力）。二维码/明文配对码只在生成时显示；轮换令牌会作废旧令牌、旧配对码与已连设备。 |
| 发出/返回内容 | 交接会话与局域网扫码会话都走与桌面端同一套后端方法，返回的就是桌面上能看到的同一份数据；不新增任何采集或出网点。 |
| 传输安全 | ⚠️ **明文 HTTP，没有 TLS**。在敌意网络（公共 Wi-Fi、被入侵的路由器）里，同网段的人可以嗅探到**配对码、会话 Cookie 与你查阅的数据正文**。只在你信任的局域网里使用；交接点卡片返回、局域网关闭开关即停。 |
| 资源争用 | 浏览器与桌面共用同一个后端 worker（单线程）。远程调用有**并发上限 2 + 排队**，长任务另有「1 个在跑 + 4 个排队」的重活预算；超时沿用与桌面相同的分档。 |
| 落盘 | **不新增任何落盘位置**。会话与配对码只存在于内存（进程退出或停服即失效）；长期 `api_token` 住在既有的 `secrets.json` 里，不写远程访问日志。 |
| 防火墙 | ⚠️ 应用**没有管理员权限，不能替你添加入站规则**。监听期间 Windows 可能弹出「是否允许访问」——点「取消」浏览器就连不上。手动放行：`netsh advfirewall firewall add rule name="Super Time 远程访问" dir=in action=allow protocol=TCP localport=5032`；要彻底关掉：`netsh advfirewall firewall delete rule name="Super Time 远程访问"`。 |

## 五、如何断网

**应用内没有任何全局出网开关。** 2026-09-30 起，此前那批开关（出站拦截、地图底图拦截、
远端取原图与解密方式）已随这次改造**全部移除** —— 同类功能一律允许出网，界面上也不再有
「允许 / 禁止出网」的按钮。会话级「AI回复」是唯一按单聊生效的例外，默认关闭，只控制该会话
后续的自动模型调用与消息列表投递。原因与代价都写在这里，而不是藏在代码里：那些旧开关要么只影响
"你能不能看到图"，要么与"内容是否发出"无关，留着只会让人以为关掉就安全。

**唯一能真正断掉出网的办法是系统级的**：

1. **断开网络**（拔网线 / 关 Wi-Fi）；或
2. **在系统防火墙里禁止 Super Time 出站**；或
3. **把模型地址指向你自己的内网 / 本机**：改 `llm.json` 的 `apiUrl`（例如自建的
   OpenAI 兼容端点或本机推理服务），内容包括向量化就不会离开你的网络。

断网后：本机已有的图片、头像、封面照常显示（都落在本地缓存里），本机没有缓存的会退成
占位（「加载失败」/ 首字母），地图底图不再画、语音模型下载不可用，
AI 问答、总结、消息分析与已开启的 AI回复会直接报网络错误。**其余功能（搜索、统计、导出、图谱、账本、备份、
隐私体检、待办提取）全部纯本地，断网照常可用。**

**还能关掉的东西（不是出网开关）**：

- `数据边界与出网 → 敏感字段打码`：出站文本发送前脱敏，见第六节；
- 知识库文件的 `参与语义检索（会出网）`：关掉之后**该文件**不进向量索引、正文不发送
  —— 它是**数据范围**开关，不是全局出网开关；
- 不点那些"按需才发生"的按钮（语音模型下载、批量取原图、抽取实体、找链接建议）。

**入站方向是本声明里唯一有应用内开关的一处**：`设置 → 维护与自检 → 局域网访问（手机）`。

- 关掉它 = 本机**立刻停止监听**，局域网里任何设备都连不进来（这是真正的开关，不是数据范围开关）；
- 「轮换令牌」= 让已经连上的手机失效（旧会话 Cookie 与旧配对码一并作废），二维码与链接随之更换；
- 上面那三条系统级办法（断网 / 防火墙 / 指向内网）对入站同样有效：**在系统防火墙里禁止
  Super Time 入站**，即使开关是打开的也连不进来。
- 消息列表的 `/api/message-webhook/<token>` 共用这个监听面，**没有单独开关**：关掉局域网访问
  或轮换令牌即可让它失效；删除规则只会停止新的下游投递，不会删除已经写入的台账记录。

> 注意口径差别：**出网**没有任何应用内开关（2026-09-30 起全部移除），要断只能靠系统；
> **入站**有一个真开关，而且**默认就是关的**。

## 六、发送前的敏感字段打码

`数据边界与出网 → 敏感字段打码` 开启后，出站文本在发送前会把手机号、身份证号、
银行卡号、邮箱、口令等模式替换为掩码（`src/backend/wechat-data/src/query/privacy.ts`）。
它作用于 A、B 两条 AI 链路，以及 G3 的任务触发投递与 G4 的消息列表回复投递 —— G3 / G4
都只对**正文文本**脱敏，任务名 / 会话名 / 触发对象名 / 关键词 / 备注与图片内容不在脱敏范围内；八爪鱼「附加参数」里
由你选择的固定值、自定义模板渲染结果也同样**不脱敏**（模板能引用的白名单字段本身不在打码范围）。

注意：打码是**模式匹配**，不保证覆盖所有敏感形式。它只是改字节，**不减少出网点** ——
对内容最敏感的场景请配合断网使用。

## 七、AI 出站审计

`数据边界与出网 → AI 出站审计` 记录每次模型调用的功能名、次数、字符数、会话与消息数。
可导出 CSV、可清空。审计只存在本机数据库里（`wechat_privacy.db`），不外发。
