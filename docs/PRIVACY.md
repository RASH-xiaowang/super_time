## 一句话结论

你的微信数据在本机解析、存储与分析，**不上传到我们的任何服务器**（我们没有任何服务器）。
唯一会把你**内容**发出去的功能是 AI 问答与总结 —— 那会把检索到的聊天片段发给你**自己配置**的
模型接口。除此之外还有几处**不涉及聊天内容**的出网点（头像、远程图片/视频、地图底图、
语音模型下载，以及只发凭据的**连接测试 / 余额查询**），第四节逐条列明。

**入站方向**：本应用**默认不监听任何端口**，别人无法从网络连进来。唯一的例外是你**自己打开**
「设置 → 远程访问（手机）」那个开关 —— 打开后本机才会在局域网里起一个 HTTP 服务，
让**你自己的手机**用浏览器访问同一套界面；访问必须持配对码，且只开放一份方法白名单
（第四节 H）。关掉开关即恢复「一个端口都不监听」。

> **应用内已没有任何出网开关**：本声明第四节列出的每一个出网点都会按描述发出请求，
> 应用里没有可以逐个关掉它们的按钮。要阻止这些请求，只能靠系统防火墙或直接断网
> （见第五节）。**"参与语义检索"是文件级的数据范围开关，不是出网开关**：它决定某个
> 知识库文件是否进入向量索引，关掉之后该文件完全不出网。

## 一、我们读什么

### 1. 本机微信数据（只读）

- 解密后的 SQLite 库：消息、联系人、群成员、朋友圈、收藏、转账记录等；
- 媒体缓存：图片、视频、语音、文件的本地副本与我们自己的解码缓存。

这些数据来自你**自己**的微信安装（`Weixin.exe`）与数据目录。应用把它们解密、
复制到自己的数据根后**只读**使用。

### 2. 运行中的微信进程内存（只读，用于取数据库密钥）

微信 4.x 的数据库密钥不以明文存在磁盘上，只在**运行中的微信进程内存**里。
因此「自动获取密钥」会：

- 通过 Win32 API（`OpenProcess` → `VirtualQueryEx` → `ReadProcessMemory`）**只读**扫描
  `Weixin.exe` 进程的内存区域；
- 只挑「已提交、可写、非 guard」的区域，按已知的密钥模式匹配并用一个数据库文件校验命中结果；
- **不写入、不修改、不注入、不 hook** 微信进程，也不把扫描到的内存内容保存或外发；
- 命中后把密钥写入本机 `<数据根>/secrets.json`（权限收紧到当前用户）。

代码：`src/backend/wechat-data/src/keys/win32-memory.ts`、`keys/service.ts`。
微信未运行时该能力不可用，可改为手动填写密钥。

### 3. 本机密钥材料与配置

图片密钥可从微信的 kvcomm 缓存（`*_input.statistic` 文件名前缀）与
`%APPDATA%\Tencent\xwechat\config\*.ini` 推导；这只读本机文件，不外发。

### 4. 设备指纹（用于授权）

授权校验需要一份设备指纹（机器标识的哈希）。它**只在本机计算**，写入你导出的
`activation-request.json`；只有你**主动**把该文件交给签发方时才离开本机。

## 二、我们不做什么

- 不登录微信、不发消息、不改动微信的任何文件或数据；
- 不写注册表、不安装驱动、不挂钩（hook）微信进程；
- 不收集遥测、不做崩溃上报、不做使用统计；
- 不把数据库、聊天记录、图片或导出物上传到我们的服务（我们没有这样的服务）；
- **不监听任何端口、不接受任何入站连接** —— 唯一的例外是你自己打开「远程访问（手机）」
  开关（默认关闭；见第四节 H）。关掉它，本应用就回到「只出不进」的形态；
- 不在后台偷偷调用模型：AI 调用只由你的操作触发（提问、总结、定时总结任务、
  知识库的「生成摘要 / 语义索引 / 抽取实体 / 找链接建议」四个按钮）。
  > ClawBot 集成的**默认**行为同样不经模型：收消息自动、**发消息只由你在界面上的发送动作触发**
  > （没有定时发送）。唯一的例外是**你在实例卡上为某个实例打开「AI 自动回复」**（默认关闭）：
  > 打开后，收到消息时会自动走问答管道生成回复 —— 那正是上面说的「无需点击的模型调用」，
  > 用的也是你在这里配置的模型接口（触发方式不同：一个是你点、一个是收到消息）。

## 三、数据存在哪里

| 路径 | 内容 | 保护 |
|---|---|---|
| `<userData>\wechat\config.json` | 路径配置与非敏感设置镜像（**不含**密钥） | 目录权限收紧到当前用户 |
| `<userData>\wechat\llm.json` | 模型接口地址与 **API Key**（可保存多套已配置的模型，切换时整体替换） | 同上 |
| `<userData>\wechat\logs\` | 诊断日志（出网相关内容会脱敏） | 同上 |
| `<userData>\wechat-data\` | 数据根：`decrypted\`（解密库）、`decoded_images\`（图片缓存）、检索/笔记/待办库 | 同上 |
| `<数据根>\secrets.json` | 微信解密密钥（db / image / xor / api_token） | 原子写入 + 仅当前用户可读 |

除上表之外，`<数据根>\wechat_privacy.db` 保存三类**本机元数据**：AI 出站审计（见第七节）、
导出历史（每次导出的路径与参数），以及**问答历史**（每次问答的问题、回答与引用来源，
供「微信问答 → 历史记录」回看）。三者都只存在本机、按数据根隔离，**不参与任何导出或分享**；
问答历史与导出记录都可以在界面上逐条删除或整体清空。

### 微信 ClawBot 集成（`<数据根>\clawbot.db`）

「ClawBot」面板用于把 Super Time 接入微信（官方形态：**手机微信插件 ↔ 桌面端 Agent**
绑定，扫码即绑、无需 App ID / App Secret）。**一个微信号 = 一个实例**：可以同时管几个
（工作号 / 生活号各有自己的通道、会话与配置），每个实例各自持有一条长轮询。
它维护一个**独立的本机库** `<数据根>\clawbot.db`，写入者是 **Super Time 自己**
（单写方，无第三方进程写它）：

| 内容 | 说明 |
|---|---|
| 绑定状态 | 绑定四态（未绑定 / 绑定中 / 已绑定 / 已解绑）与绑定后的微信 `wxid`、昵称、头像（iLink 不下发昵称/头像时显示 `wxid`，不编造） |
| **接入会话** | 你与本机 Super Time 之间的**每条消息正文原文**，含方向（收到 / 发出）、消息类型与时间 |
| **会话凭证** | iLink 会话凭据（`bot_token` / `ilink_bot_id` / 用户 id / 服务地址）、**同步游标**与**发送令牌**（按实例各存一份）。只存在本机、只有 worker 读得到（界面快照与导出都不含它们）；**解绑时随通道一起清除** |
| **实例配置** | 每个实例的行为开关（AI 自动回复开 / 关、是否启用知识库增强及其库 id）。与绑定关系**分表存**：行为偏好是你的选择，应当**活过重新绑定**（重新扫码不该把开关重置成默认） |

**关于这份数据的五件事：**

- **绑定通道会出网：接收侧只发控制面，发送侧只发你写的那条正文，附件点开才取。** 扫码绑定与
  消息接收都要经腾讯 iLink 服务（`ilinkai.weixin.qq.com`，唯一目的地）：申请二维码、轮询扫码状态、
  绑定后**常驻消息长轮询**（约每 35 秒一轮，随应用运行，直到解绑）——这些请求只带会话凭证
  与同步游标，**不含任何本地数据**；而你在「接入会话」里点「发送」时，**你写的那条正文原文**
  会经同一服务送达你的微信（默认只在你的发送动作里发生；另外**按实例开关**的 AI 自动回复
  会自己发一条，默认关）；收到带附件的消息
  后，本机**自动**从腾讯 CDN 取回那份媒体（无人值守；**只下载、不上传**），解密后落本机缓存
  `<数据根>\clawbot-media\`。逐条口径见第四节的 **G2**。
- **发送的内容不做打码。** 「敏感字段打码」只作用于**展示层**：「发送」发的是你输入框里的
  原文（你对着它写、对着它发，改写反而会改变你要表达的东西）；库里与导出文件也是原文。
- **它写的是正文原文，且永久保留。** 这是本声明首次包含「会话正文」类别的本机落盘。
  **没有自动清理、没有保留期上限**；如果开启了「敏感字段打码」，那**只影响界面展示**，
  写入库里的仍是原文、导出文件里也是原文。
- **解绑不删除接入会话。** 解绑只是断开微信通道（停长轮询、清凭证与发送令牌）、把绑定状态
  置为「已解绑」；历史消息仍保留在本机，重新绑定后可继续查看。要彻底清掉请删除数据根
  （`<数据根>\clawbot.db` 随数据根一起消失）。**移除实例**是另一件事：它会把该实例的
  接入会话连同配置一并删除（界面在确认框里如实报出将删除的条数）。
- **AI 自动回复是这条链路唯一的自动外发**（2026-10-13 起）：为某个实例打开「AI 自动回复」后，
  你在微信里发给它的**消息正文会作为问题**走本机问答管道 —— 模型服务商（第四节 F 表那几个
  目的地）会收到它，**这一路是无人值守的**（不需要你点任何东西）；知识库增强打开时，被检索中的
  知识库片段也会一并进入同一次调用。**默认关闭**，开关就在实例卡上，关掉即停。
  除此之外 ClawBot 不参与任何自动分享；「ClawBot」面板的导出按钮把消息导出成 TXT/CSV 时
  由**你自己**选择落点。自动回复的模型调用会按 `ask_wechat` 记进 `wechat_privacy.db` 的
  AI 审计（与手动问答同一口径），并在操作日志里留一行 `clawbot_auto_reply`。

删除全部数据时，除了 `<userData>\wechat` 与 `<userData>\wechat-data`，`<数据根>\clawbot.db`
也会随之消失（它位于数据根下）。

`<userData>` 在 Windows 上是 `%APPDATA%\Super Time`。**安装目录保持只读**：
升级或卸载不会带走你的配置，也不会把本机路径与密钥带到其他机器。

删除数据 = 删掉 `<userData>\wechat` 与 `<userData>\wechat-data`（或你在设置里指定的数据根）。
卸载程序不会自动删除它们。

## 四、网络暴露面清单（出网点 + 入站监听，与代码逐条对应）

> A–G2 是**出网**（本机向外发请求）；**H 是入站**（本机监听端口、别人向本机发请求）。
> 两类都登记在这里，因为「我的数据会不会被别的设备看到」这个问题两边都要答。

### A. AI 调用：LLM chat（发的是**内容**）

| 项 | 说明 |
|---|---|
| 触发 | 微信问答、每日总结、周期总结、群总结任务，问答的「查询改写/优化」，单聊里的「**推荐回复**」，知识库文件详情里的「**生成摘要**」，以及 AI 年度回顾叙述（**按月分段**，每段最多 4,000 字，逐段发出该月的聊天片段） |
| 发出内容 | 检索到的聊天片段 / 当日消息 / 待总结文本（**不是**整个数据库）；「生成摘要」时是**你指定的那一份文件的开头正文**，上限 8,000 字、按文档原有顺序取前若干块 —— 文件更长时后面部分不会发出去，摘要也只覆盖前面那段 |
| 目的地 | 你配置的 `llm.json` 里的 `apiUrl`（默认 `https://api.openai.com/v1`） |
| 开关 | ⚠️ 应用内**没有出网开关**：这一条会按上面的描述发出请求。<br/>✅ 「敏感字段打码」开启时发送前脱敏（它只改发出去的字节，不是出网开关）；<br/>✅ 文件级：关掉「参与语义检索（会出网）」的文件**直接拒绝生成摘要**，不改标志位也不发送 |
| 审计 | ✅ 每次放行都记入本机审计表（功能、次数、字符数），可导出 CSV |
| 代码 | `gateway.ts` 的 `privacyGate(...)`（`ask_wechat` / `daily_summary` / `period_summary` / `summary_task` / `ask_optimize` / `kb_file_summary` / `suggest_reply` / `annual_narrative`） |

### A2. 模型账户类请求：连接测试 / 余额查询（发的是**凭据**，不是内容）

> 2026-09-30 新增。用户要求「给 AI 大模型增加链接测试按钮和余额查询接口，余额实时显示在主界面左下角」。
> 它**不是**内容出网点（一个字节聊天内容都不发），但确实是**出网**，所以照样逐条登记 ——
> 尤其第二条是**无人值守**的定时请求，这一点必须写明白。

| 项 | 说明 |
|---|---|
| 触发 | ① 「设置 → AI 大模型」里的**「测试连接」**（主模型）、**「测试向量」**、**「测试精排」**三个按钮（显式点击，用当前表单的地址与 Key，不必先保存）；② 同面板的**「查询余额」**按钮；③ **主界面左下角（设置按钮下方）的余额条**：挂载后查一次、之后**每 5 分钟一次**（无人值守），点它会立刻刷新 |
| 发出内容 | **只有 API Key**（`Authorization: Bearer`）。三条测试的差别要写清：**测试连接**是 `GET /models`（不发任何内容、不产生费用）；**测试向量 / 测试精排**各发一条**固定的测试串**（`连接测试`，约 3 / 6 个 token）—— 不是你的聊天内容、不是文件名、不是查询词。余额查询不带任何 body。全部动作都不发账号信息与本机路径 |
| 目的地 | 你配置的三套端点（可各不相同）：主模型 `apiUrl` 的 `/models`；向量 `embeddingApiUrl`（留空回落 `apiUrl`）+ `embedPath`（默认 `/embeddings`）；精排 `rerankApiUrl`（留空回落）+ `rerankPath`（默认 `/rerank`）；余额按厂商惯例 —— DeepSeek 打 `{origin}/user/balance`（注意**不带 `/v1`**），其余厂商先 `{base}/user/info`（SiliconFlow 惯例）再退 `{base}/user/balance` |
| 开关 | ⚠️ 应用内**没有任何出网开关**（与 A / B 同口径）。要让它不发生：断网 / 在系统防火墙里禁止本应用出站；或在「AI 大模型」里**清空 API Key** —— 清空后余额条自动隐藏、也不再发任何请求 |
| 审计 | ❌ **不进** AI 隐私审计表 —— 那张表按「哪一类数据出了网」分列，而这两条不发数据。失败原因与耗时只在界面提示（余额条把原因放在悬浮提示里） |
| 厂商差异 | 部分厂商（如 OpenAI）**不提供**余额接口：此时会明确报「余额查询失败：… 404」，界面显示「余额 —」而不是一个编造的数字。查不到余额不影响问答与总结 |
| 代码 | `src/backend/llm-balance.js`（地址推导 `balanceUrlsFor` / 解析 `parseBalance` / 取数 `testLlmEndpoint`、`queryLlmBalance`）；IPC `wechat:llm-test` / `wechat:llm-balance`（`src/backend/ipc-wechat.js`，preload 暴露面同步）；出网统一走 `src/backend/llm-http.js`；界面 `panels/llm-probe.tsx`（四条探针）、`panels/SidebarBalance.tsx`（左下角余额条） |

### B. AI 调用：embedding（发的是**内容**）

| 项 | 说明 |
|---|---|
| 触发 | ① 微信问答的稠密检索通道（把检索到的聊天片段向量化）；② **知识库问答**：把「参与 RAG」的文件**块正文**送去向量化，用于建/补该库的向量索引；③ 「知识库 → 文件」面板上的**「语义索引」按钮**（你主动点才发，只发当前这个库）；④ 同面板的**关键词+语义检索**：只发**你输入的那句查询词**，库内正文不外发 |
| 发出内容 | 待向量化的文本（按配置截断）：① 检索到的聊天片段；② **你选进知识库、且没有关掉「参与 RAG」开关的文件正文**；③ 同 ②（按钮触发的建库）；④ 检索词本身 |
| 目的地 | 同 A（`apiUrl` + `embedPath`，默认 `/embeddings`） |
| 开关 | ⚠️ 没有出网开关。✅ 「敏感字段打码」发送前脱敏；两处的**审计功能名分开记**（`ask_embed` = 聊天片段 / `kb_embed` = 知识库文件正文），这样「我把哪一类数据发出去了」在审计表里分得开。逐文件的「参与语义检索」开关关掉后，该文件**连候选都进不来**（条件写在取语料的 SQL 里，不是取回后再过滤） |
| 代码 | `gateway.ts` 的 `makeEmbedFn`（`feature` 参数）/ `privacyGate` / `buildKbVectorIndex`；消息侧 `query/retrieval/embedding.ts`；知识库侧 `query/kb-vectors.ts` |

> 未配置模型时这两条链路都不会发生：问答直接报「未配置模型」，检索退化为纯本地稀疏通道。
> 知识库侧还有一道**文件级**闸门：「参与 RAG」开关（`kb_files.include_in_rag`）。
> 关掉它的文件，正文既不会进向量索引、也不会被检索到 —— 该条件写在**取语料的 SQL** 里，
> 不是拿到结果之后再过滤（后过滤会让不许出网的文件先占满名额再被丢掉）。
> 索引是**按库**建的：在哪个库里提问，就只把那个库的正文送去 embedding。

### B2. 模型精排（把候选正文发给重排序模型）

| 项 | 说明 |
|---|---|
| 触发 | 问答检索融合出候选之后。**只在「数据配置 → AI 大模型」的重排序模型名非空时发生** —— 这个字段没有独立开关，填了就启用（留空则整段跳过，顺序由本地启发式给出） |
| 发出内容 | 你的查询词 + 头部若干条候选的**正文**（默认上限 60 条；聊天片段与知识库文件正文都算候选）。不发出答案、不发出你的身份标识 |
| 目的地 | 同 A（`rerankApiUrl` 留空则回落 `apiUrl`；路径 `rerankPath`，默认 `/rerank`） |
| 开关 | ⚠️ 没有出网开关（**只在「重排序模型」那一栏填了模型名时才发生**，留空则整段跳过）。逐文件另有「参与语义检索」开关 —— 关掉的文件连候选都进不来。精排失败**不会让问答失败**，只是退回本地加权并在依据行写明 |
| 审计 | 功能名 `ask_rerank`（独立一列）。名字里不写 `kb_` 是因为候选既可能来自聊天记录也可能来自知识库文件 |
| 代码 | `gateway-llm-factory.ts` 的 `makeRerankFnOf`（整批过 `privacyGate`）；`query/retrieval/pipeline.ts` 的融合后精排阶段；`llm-bridge.js` 的 `rerank()`；出网统一走 `llm-http.js` |

> **一处必须说清的副作用**：开启「敏感字段脱敏」时，送出去的是**脱敏后的文本**。
> 脱敏是五条正则（手机号 / 身份证 / 银行卡 / 邮箱 / 口令），它不认识上下文 ——
> 文件正文里连续的 16–19 位数字（订单号、无连字符的 ISBN、时间戳串）会被整段替换成 `[银行卡]`。
> 也就是说**模型读到的字节与落库的原文不同**，而审计表只记录字符数、不记录被改写了什么。
> 这会影响精排的相关性判断（极端情况下把一条本来最相关的候选排到后面），
> 但不会把未脱敏的内容发出去。

### B3. 文档实体抽取（把文件正文发给语言模型换一批名字）

| 项 | 说明 |
|---|---|
| 触发 | **「知识库 → 本库模型」弹层里的「抽取实体」按钮**（`kb_extract`）。只有你点下去才发；不在建索引时顺带跑，也没有定时任务会碰它 |

| 目的地 | 同 A（本库的语言模型；没覆盖就用全局 `apiUrl`） |
| 开关 | ⚠️ 没有出网开关（**只有你点「抽取实体」才会发**，没有定时任务）；✅ 逐文件「参与语义检索」关掉的文件**一次请求都不发**（判据写在取正文的 SQL 里）；✅ 没配语言模型时按钮是禁用状态并说明为什么 |
| 审计 | 功能名 `kb_extract`（独立一列） |
| 代码 | `gateway.ts` 的 `extractKbEntities`（过 `makeChatAsker` → `privacyGate`）；`query/kb/extract.ts` |

> 抽出来的东西落在**新表**（`kb_doc_entities`），是**推断**而不是原文：图谱里连到它的边一律画成
> 虚线，详情里写明「模型推断 · 由 <模型名> 抽出」。重跑同一个文件会**覆盖**它上一次的结果。

### B4. 笔记的链接建议（把正在写的正文发给向量模型）

| 项 | 说明 |
|---|---|
| 触发 | 笔记编辑器里的**「🔗 找链接建议」按钮**（`kb_link_suggest`）。刻意**不**随打字触发 —— 那样会把同一句话发几十遍 |
| 发出内容 | 你正在写的**标题 + 正文**（截到 1,200 字）+ 本库的候选名字（已有笔记标题与上一步抽出的实体，最多 80 条短字符串）。不发给模型的是：别人的聊天内容、你的身份标识 |
| 目的地 | 同 B（本库的嵌入模型） |
| 开关 | ⚠️ 没有出网开关（**只有你点「🔗 找链接建议」才会发**，不随打字触发）；✅ 没配嵌入模型时直接报「未配置」，一个候选都不取 |

### D. 远程图片 / 视频 / 公众号封面（不发内容）

| 项 | 说明 |
|---|---|
| 触发 | 表情原图、**聊天图片的原图**（只有你显式动手才会发请求：逐条点图片下方的「取原图」，或在「设置 → 图片解码」点一次「批量取原图」；**没有任何后台自动批量取**，进会话/滚动都不会触发它）、朋友圈视频与封面、公众号文章封面在本机没有缓存时，后端按消息里的地址取回；**滚到卡片缩略图或朋友圈图片**时也算 —— 渲染层不再自己去取，而是把地址交给 `getRemoteImages`（本机缓存优先，未命中才出网） |
| 目的地 | 微信 CDN（消息 XML 里的 `cdnurl` / `<url>` / `<thumb>`；聊天图片走 `tpurl`/`tphdurl` 直链；头像走 `qlogo.cn`，**主机白名单固定为** `qq.com`、`weixin.qq.com`、`wechat.com`、`wechatcdn.cn`、`qpic.cn`、`qlogo.cn` 六个后缀），公众号文章页**只允许** `mp.weixin.qq.com`。**这条白名单现在管到所有由后端代取的图片、头像、视频与公众号文章页**（原图、朋友圈封面/视频、卡片与朋友圈的远程图、`getRemoteImages` 代理入口）——清单判在发请求之前，主机不在里面就一个字节都不发 |
| 开关 | ⚠️ 没有出网开关：本机没缓存就按消息里的地址去取（**已有缓存照常可用**，不会因为取不到就丢图）。<br/>✅ **域名白名单**（`query/cdn-hosts.ts`，唯一出处）：图片/头像/视频地址主机不在上面那六个后缀内就拒绝发请求，公众号文章页另收窄为 `mp.weixin.qq.com`（消息 XML 是可被离线改写的文件，不能让它指定我们去哪儿）；带凭据的 URL 一律拒。<br/>✅ 远端回来的加密流一律用 `<enc key>` **本机解密**（没有"服务端解密"这个选项）。 |
| 记录 | 取回成功/失败会写进**操作记录**（功能名 `sns_cover_fetch` / `sns_video_fetch` / `image_original_fetch` / `remote_image_fetch`）；批量取原图走同一个 `image_original_fetch`（目标写「批量」），并在本机落一份 `<解码缓存>/.originals-index.json`（**只有 md5 与时间戳**，用于下次续跑不重下）。注意这些**不进** AI 的那张隐私审计表 —— 它们不是模型调用，审计表按「哪一类数据出了网」分列，混在一起就会把「我把消息正文发给了谁」这条查询问成一个含糊的数 |

> 代价要一并写清：① 代理只代取白名单内的微信系主机，指向站外图床的第三方封面 / 头像不显示（内容与卡片照常可读）；② 站外地址里的 `http` 图片（实测朋友圈 1,125 张里 1,104 张是 http）后端也只取 https，所以那部分要靠本机解码或微信里点一次；③ **表情图与朋友圈视频导出这两条链在 2026-09-30 补齐了同一道主机白名单** —— 此前它们只判协议，等于「消息 XML 里写哪个主机就去取哪个」；现在站外地址一律不发请求，且拒绝时会写明是哪个主机。
> 剩下仍由界面直接发出的只有地图底图数据（E 段）与语音模型下载（F 段）—— 两条都**没有**应用内开关。

> **这条能力的边界（2026-09-26 实测，脚本 `working/probe-original-coverage.ts` 与
> `working/probe-wecom-403.ts`，可自行复核）**：本机 51,983 条图片消息里，**16.5%** 带
> `tphdurl`/`tpurl`（8,604 条）、**81.6%** 只带 `cdnbigimgurl`/`cdnmidimgurl`（42,433 条）。
> 但这 8,604 条直链**实测一条都取不到**：它们全部指向企业微信的
> `wwfile.work.weixin.qq.com/cgi-bin/download?f=…&t=…&p=1`，匿名 GET **一律 403** ——
> 与消息新旧（**20 分钟前**的新消息同样 403）、请求头（裸 UA / 加 `Referer: work.weixin.qq.com`
> / 加图片 `Accept`）都无关，URL 里也没有 `tpauthkey`。也就是说**有链接 ≠ 能取**：这类是
> 需要企业微信登录态的服务端令牌端点，和 `cdnbigimgurl` 同类待遇（不取）。
> 真正能取的只有带 `tpauthkey` 的免登录直链（个人微信账号上是常态，本机这份数据里一条都没有），
> 因此「取原图」对它们会明确回一句「这条没有免登录直链，请在微信里点开一次」。
> 那部分指针技术上要的是**微信登录态凭据**（会话密钥 / 设备签名），也就是「以你的身份向微信
> 服务器发请求」—— 本应用**不做**，也不会去做：它和本文开头「不登录、不发送消息、不连微信
> 服务器同步聊天记录」是同一条承诺的两端。**因此「任何情况下 100% 拿到原图」在守住这条承诺的
> 前提下不可能成立**；能做的是把不越界的部分做到最大，并把剩下的缺口与补救动作说清楚。

### H. 入站监听：局域网远程访问（手机端）—— **不是**出网点，但同属暴露面

> 2026-10-14 新增（v13）；2026-10-15 修改（v14）。它与 A–G2 的方向相反：
> **本机监听、别的设备连进来**。
> 之所以照样逐条登记，是因为「聊天数据会不会被这台机器之外的东西读到」这个问题，
> 入站方向的答案更直接 —— 打开开关后，答案是「会，被同一局域网里持配对码的设备读到」。

| 项 | 说明 |
|---|---|
| 触发 | **只有你在「设置 → 远程访问（手机）」里亲手打开开关**（配置键 `api_enabled`，**默认关闭**）。关掉即一个端口都不监听，行为与 v12 完全一致。没有任何定时任务、也没有其它功能会顺带把它打开 |
| 监听什么 | 本机的**局域网 IPv4 地址**上的一个端口（配置键 `api_port`，默认 `5032`；被占用时顺移 5033–5042，界面显示**实际**端口）。刻意**绑具体网卡地址而不是 `0.0.0.0`**，以缩小暴露面；候选地址全部列在界面上 |
| 谁能连 | **同一局域网内的任何设备**（同一路由器 / 同一 Wi-Fi 下的手机、平板、别人的电脑）。这就是为什么必须持配对码 —— 监听地址本身不构成访问控制 |
| 访问控制 | ① **长期 `api_token`**：首次启用时由 `crypto.randomBytes(24)` 生成（base64url），存进 `<数据根>\secrets.json`（与微信数据库密钥**同一套**权限收紧，只有当前 Windows 用户可读），界面上只显示掩码、可轮换；它只作为「远程访问确实启用过」的硬条件，**不进二维码、地址栏或界面明文**。② 每次启用/轮换会签发一个**5 分钟、最多 5 次试错、成功一次即作废**的配对码；手机扫二维码得到 `http://<局域网IP>:<端口>/?t=<配对码>`，配对码**只用于换取一次会话**（服务端用 `crypto.timingSafeEqual` 定长比对），随后下发 `HttpOnly` + `SameSite=Lax` 的会话 Cookie（内存态、12 小时、重启即失效），页面地址里的 `?t=` 立即被抹掉，不在后续请求的 URL 里重复出现。③ **方法白名单**：远程通道只开放一份显式清单里的 `@Remote` 方法，**默认拒绝**（新增方法默认不开放，必须逐条加进清单）。④ **Host 头校验**：请求的主机名必须等于当前监听的局域网 IP（回环监听额外接受 `localhost`），域名形状的 Host 在进入任何路由前回 `421 BAD_HOST`，用于挡住 DNS rebinding 这类把浏览器里的恶意域名解析回本机地址的打法 |
| 明确**不**开放 | 模型配置与 **API Key**（`wechat:llm-get` / `llm-save` / 连接测试 / 余额查询）、许可证与设备指纹（`license:*`）、诊断（`diag:*`）、更新（`update:*`）、备份还原、**任何配置写入**、ClawBot 绑定通道，以及全部原生能力（文件/目录选择对话框、窗口控制、面板截图、在资源管理器中显示）。手机端调到这些会得到明确的「该方法不开放远程访问」错误，而不是静默失败 |
| 发出/返回内容 | 与桌面端同一套后端方法 ⇒ 返回的就是你在桌面上能看到的同一份数据（聊天记录、联系人、朋友圈、统计、图片的 data URL 等）。**不新增任何采集**：手机端能看到什么，完全由白名单决定，而白名单是桌面端已有能力的子集 |
| 传输安全 | ⚠️ **明文 HTTP，没有 TLS**（自签证书在手机上会触发安全警告，实际不可用）。后果如实写：在**敌意网络**（公共 Wi-Fi、被入侵的路由器）里，同网段的人可以嗅探到**配对码、会话 Cookie 与你查阅的数据正文**；长期 `api_token` 不再经过这条链路。`Secure` Cookie 标志也用不上。**请只在你自己信任的局域网里打开这个开关**，用完就关 |
| 资源争用 | 手机与桌面**共用同一个后端 worker（单线程）**。远程调用有**并发上限 2 + 排队**，长任务另有「1 个在跑 + 4 个排队」的重活预算（超过即 `REMOTE_BUSY`），超时沿用与桌面相同的分档（默认 60 秒 / 长任务 10 分钟）；这样手机端点重活不会把整条队列填满、桌面界面仍保留一条轻读车道 |
| 落盘 | **不新增任何落盘位置**。会话与配对码都只存在于内存（进程退出或停服即失效）；长期 `api_token` 住在既有的 `secrets.json` 里。远程访问不写日志文件、不记录你查阅了哪些内容 |
| 防火墙 | ⚠️ 如实说：应用**没有管理员权限，不能替你添加入站规则**。首次监听时 Windows 会弹出「是否允许访问」的对话框 —— **点「取消」的话手机就连不上**（应用这边看起来一切正常）。手动放行：`netsh advfirewall firewall add rule name="Super Time 远程访问" dir=in action=allow protocol=TCP localport=5032`（以管理员身份运行，端口按界面显示的实际值填）。要彻底关掉：在界面里关开关，或 `netsh advfirewall firewall delete rule name="Super Time 远程访问"` |
| 代码 | `src/backend/http-server.js`（监听、静态资源、路由、配对码校验）· `src/backend/http-auth.js`（长期令牌与配对码生成/比对、会话 Cookie）· `src/backend/http-control.js`（开关与轮换控制面）· `src/backend/http-remote-policy.js`（`REMOTE_SAFE_METHODS` 白名单与能力清单）· `src/backend/http-queue.js`（并发上限与排队）· `src/backend/call-gates.js`（与桌面 IPC **共用同一道**许可证闸门，两边不会各写一份）· 界面 `panels/settings-remote-access.tsx`（开关、实际地址、二维码、凭据轮换） |

## 五、如何断网

**应用内没有任何出网开关。** 2026-09-30 起，此前那批开关（出站拦截、地图底图拦截、
远端取原图与解密方式）已随这次改造**全部移除** —— 同类功能一律允许出网，界面上也不再有
「允许 / 禁止出网」的按钮。原因与代价都写在这里，而不是藏在代码里：那些开关要么只影响
"你能不能看到图"，要么与"内容是否发出"无关，留着只会让人以为关掉就安全。

**唯一能真正断掉出网的办法是系统级的**：

1. **断开网络**（拔网线 / 关 Wi-Fi）；或
2. **在系统防火墙里禁止 Super Time 出站**；或
3. **把模型地址指向你自己的内网 / 本机**：改 `llm.json` 的 `apiUrl`（例如自建的
   OpenAI 兼容端点或本机推理服务），内容包括向量化就不会离开你的网络。

断网后：本机已有的图片、头像、封面照常显示（都落在本地缓存里），本机没有缓存的会退成
占位（「加载失败」/ 首字母），地图底图不再画、语音模型与本地决策模型下载不可用，
AI 问答与总结会直接报网络错误。**其余功能（搜索、统计、导出、图谱、账本、备份、
隐私体检、待办提取）全部纯本地，断网照常可用。**

**还能关掉的东西（不是出网开关）**：

- `数据边界与出网 → 敏感字段打码`：出站文本发送前脱敏，见第六节；
- 知识库文件的 `参与语义检索（会出网）`：关掉之后**该文件**不进向量索引、正文不发送
  —— 它是**数据范围**开关，不是全局出网开关；
- 不点那些"按需才发生"的按钮（语音/本地决策模型下载、批量取原图、抽取实体、找链接建议）。

**入站方向是本声明里唯一有应用内开关的一处**：`设置 → 远程访问（手机）`。

- 关掉它 = 本机**立刻停止监听**，局域网里任何设备都连不进来（这是真正的开关，不是数据范围开关）；
- 「轮换令牌」= 让已经连上的手机失效（旧会话 Cookie 与旧配对码一并作废），二维码与链接随之更换；
- 上面那三条系统级办法（断网 / 防火墙 / 指向内网）对入站同样有效：**在系统防火墙里禁止
  Super Time 入站**，即使开关是打开的也连不进来。

> 注意口径差别：**出网**没有任何应用内开关（2026-09-30 起全部移除），要断只能靠系统；
> **入站**有一个真开关，而且**默认就是关的**。

## 六、发送前的敏感字段打码

`数据边界与出网 → 敏感字段打码` 开启后，出站文本在发送前会把手机号、身份证号、
银行卡号、邮箱、口令等模式替换为掩码（`src/backend/wechat-data/src/query/privacy.ts`）。
它作用于 A、B 两条 AI 链路。

注意：打码是**模式匹配**，不保证覆盖所有敏感形式。它只是改字节，**不减少出网点** ——
对内容最敏感的场景请配合断网使用。

## 七、AI 出站审计

`数据边界与出网 → AI 出站审计` 记录每次模型调用的功能名、次数、字符数、会话与消息数。
可导出 CSV、可清空。审计只存在本机数据库里（`wechat_privacy.db`），不外发。

## 八、你的控制权

| 你可以 | 怎么做 |
|---|---|
| 彻底断网 | 断网或系统防火墙禁止 Super Time 出站（见第五节） |
| 用手机访问，或彻底关掉入站 | `设置 → 远程访问（手机）`：**默认关闭**；打开后显示二维码 / 局域网地址 / 实际端口，可随时「轮换令牌」让已连上的设备失效（旧配对码也一起作废），或直接关掉开关停止监听（见第四节 H） |
| 换模型 / 换服务商 | 设置 → 模型配置（`llm.json`） |
| 把模型指向内网 / 本机 | 同上，把 `apiUrl` 改成你自己的端点 |
| 切换已保存的模型 | 「数据配置 → AI 大模型」顶部的「已配置模型」芯片：点击即切换；也可逐条删除（其余配置不受影响） |
| 不提供密钥 | 不点「自动获取密钥」，改用手动填写；或在设置里清空 |
| 让某个知识库文件永不出网 | 关闭该文件的「参与语义检索（会出网）」（数据范围开关） |
| 导出你的数据 | 导出（CSV/HTML/TXT/…）、备份管家 |
| 删除问答历史 / 导出记录 | 「微信问答 → 历史记录」里逐条删除或整体清空；「导出记录」里删除或按策略清理 |
| 删除全部数据 | 删除 `<userData>\wechat`（含密钥与日志）与数据根目录 |
| 重看 / 重新同意本声明 | 主界面「数据配置 → 高级设置 → 重新查看启动页」 |

## 九、变更

本声明随版本变更；材料性变更（新增出网点、**新增入站监听面**、改变数据用途、扩大扫描范围）会提升
`PRIVACY_VERSION`，并要求你在下次启动时重新同意。文档与代码的对应关系由
`src/backend/tests/privacy-statement.spec.ts` 守住（出网点清单必须与代码里的实际调用点一致）。

**版本历史**
