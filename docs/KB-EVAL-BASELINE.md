## 五、怎么读这些数字（口径说明，含一个已知瑕疵）

**两层 ground truth 是两个不同的问题**，不要混着看：

- **块级**（`markers`）：答案**块**排在多前 → 看 MRR / 首相关块名次。回答的是「找到的是不是最该给模型看的那一段」。
- **文件级**（`expectFiles`）：那份**文件**找到了吗 → 看命中数与 MRR。回答的是「用户问的东西，系统有没有翻到正确的文件」。

**① P@10 在这里不要看。** 每条用例的相关项只有 1 个（`multi-block` 是 2 个），除以 `k=10` 之后理论上限就只有
10%~20%。15.0% 已经接近「该拿的都拿了」，把它当「命中率 15%」是误读。

**② 块级 R@10 的口径带一个瑕疵，绝对值被系统性压低。**
`evaluate()` 把 `EvalCase.relevant` **同时**当作「docKey 集合」与「文本片段表」用（见 `eval.ts` 的 `isRelevant`）。
对块级而言，传进去的 `relevant = markers`（标记词字符串，**永远不等于**任何 docKey `kb:<kbId>:<chunkId>`），
靠 `textIndex` 把「命中的块里含这个标记词」的 docKey 扩进相关集。于是相关集 = `{标记词串（恒不命中）} ∪ {含标记词的真实命中块}`
——**分母里恒有一个打不中的名额**。单标记 + 只召回一个含该词的块时，recall 恒为 `1/2 = 50%`。
所以 50.5% 只能**同口径纵向对比**（改参数前 vs 后），不能当「召回了一半」读。
文件级没这个问题：它不传 `textIndex`，键是**文件名 vs 去重文件名列表**，精确相等，口径干净。

**③ 主证据看这三处**（它们没有口径疑义）：
首相关块名次（9 条里 8 条第 1 名、1 条第 2 名）、文件级 MRR **0.900**（= 9 条第 1 名 ÷ 10）、
文件级 R@10 **90.0%**（= 9/10 用例的期望文件被找到）。

## 六、三条结论（直接喂给后续阶段）

### 6.1 字面相近的问题上，稀疏通道已经够用

8 条「答案块独有短语」类用例里，**7 条第 1 名**、1 条第 2 名。七个不同的答案位（末块、末组、标题块、
非 UTF-8 文件、数字串）都被召回，说明 `buildQueryPlan` 的词元 + FTS5 bm25 这条链路是**通的**，
阶段 C 不该把它推倒重来。

### 6.2 配额**不是**当前瓶颈 —— 加配额买不到指标

`topK` sweep（同一批夹具，只动配额）：

| topK | 块级 P@10 | 块级 R@10 | 块级 MRR | 块级 NDCG | 文件级 R@10 | 文件级 MRR |
|---|---|---|---|---|---|---|
| 3 | 13.0% | 48.3% | 0.850 | 0.564 | 90.0% | 0.900 |
| 5 | 14.0% | 48.8% | 0.850 | 0.568 | 90.0% | 0.900 |
| 10 | 15.0% | 50.5% | 0.850 | 0.576 | 90.0% | 0.900 |
| **20（默认）** | **15.0%** | **50.5%** | **0.850** | **0.576** | **90.0%** | **0.900** |
| 50 | 15.0% | 50.5% | 0.850 | 0.576 | 90.0% | 0.900 |
| 省略（= 走意图策略） | 15.0% | 50.5% | 0.850 | 0.576 | 90.0% | 0.900 |

**10 档以上完全不动**：因为答案块天然就排在第 1/2 名，多取的全是噪声。
配额收紧到 3~5 时指标才轻微下滑（P@10 15.0% → 13.0%）。
⇒ 结论：**别指望调大配额救指标**；要动指标只能动「召回不到的东西」，也就是 6.3。

### 6.3 真瓶颈是**词汇缺口**，这正是阶段 C 的靶子

`sparse-gap` 用例：问「滞留期有多长」，文件里写的是「押金留存时间」——
**字面不通**，稀疏检索 0 命中（且这个 0 是**真缺口**：查询有效、库能打开、词表非空，只是词对不上，
spec 里有一条专门断言它「不是 harness 自己造成的原因」）。
⇒ 阶段 C 的稠密通道要证明的**唯一一件事**，就是让这一条从 0 变成 non-0，同时**不许**把上面 9 条的
名次弄差（回归由本报告 + spec 守住）。

### 6.4 附带发现：分块器是「一段一块」，不是 500 字窗口

`kb/chunk.ts` 的 `chunkBlocks` 按解析出的**段（block）**逐段成块，每段 ≤ 500 字自成一块（只有 prose
段落才走 500 字窗口切）。所以**块数由段落数决定，不由字数决定**：
`合作台账.csv` 2843 字只有 **4 块**（40 行一组），而 `会议纪要-九月.txt` 508 字有 **14 块**。
⇒ 影响两件事：① 压缩阶段的「块预算」要按**块数**而非字数想；
② 阶段 E 的「父子块 / heading 参与切点」有明确的现实依据 —— 现在一个标题就是一块。
（这条曾经把我坑过一次：我按「500 字窗口」推断了标记词所在的 ordinal，结果全错；
`multi-block-same-file` 的断言因此改成**从 `markerHits` 推导**，不再猜具体 ordinal 值。）

**⚠ 对计划口径的一处修正（重要）**：计划里把 `DEFAULT_KB_TOP_K` 写成验收物，但**它不是一个有效旋钮**。
`searchKb` 只在调用方**不传** `topK` 时才用它做缺省；而评测（`kb-eval.ts:284`）与流水线（`pipeline.ts:383`）
**都显式传**了配额。所以改 `DEFAULT_KB_TOP_K` 对指标**必然零影响** —— 拿它当验收物是**测不到东西的假验收**
（这也解释了上表里「省略 topK」与「topK=20」逐位相同：缺省走的是意图策略的 `channelTopK.kb`）。
真正决定 KB 召回量的产品参数是**意图策略里的 `channelTopK.kb`**（12~30，见 `config.ts`），变异实验用的就是它。

## 八、这份基线**证不了什么**（边界，防止被过度引用）

1. **夹具是自造的**，词汇重叠度天然高于真实文档（问题里的词就是文件里的词）。所以这组数字**偏乐观**，不能外推成「用户真实文档上也有 MRR 0.85」。
2. **只有 10 条用例**。MRR / NDCG 的**绝对值没有意义**，只能看**相对变化**（C 阶段上线前后对比）。要绝对值就得扩到几十上百条，那是另一件工作。
3. **只评了稀疏通道**（`onlyRag: true`、库里还没有向量表、没有稠密通道）。稠密通道上线后必须**重跑本报告**并追加一列对照。（**2026-09-19 更新**：稠密通道已落地，**管线**已验，但**语义对照仍待端点** —— 为什么这一列现在填不了，见 §十一。）
4. **「命中」= 命中块的文本里含标记词**，不是「答案正确」。它量的是**检索的召回**，不是端到端问答质量（后者要模型参与，不在 G-08 范围）。
5. **只覆盖 4 类文本**：md / txt / csv / GB18030-txt。**pdf / docx / xlsx 一条都没有** —— 它们要等阶段 D 的解析器落地后才可能有夹具。
6. 没有评**多库并存**下的相互干扰（只有甲/乙两库各跑一次的作用域断言）。

## 十一、阶段 C 对照（2026-09-19）：为什么这一列是「待端点」而不是数字

**一句话**：阶段 C 的稠密通道**管线**已经验完（融合 / 库隔离 / 降级如实 / 重建 / 级联），但
**语义质量**这一列暂时量不了 —— 所以这里**不填数字**，而是写清「为什么现在填不了」与「端点就绪后怎么填」。

### 11.1 桩 embedding 不可能让 `sparse-gap` 变 non-0（这不是偷懒，是夹具性质决定的）

`kb-vectors.spec.ts` 里的桩是**字符直方图**（每维 = 某个码点的出现次数），它只让
「字面有重叠 ⟺ 余弦更高」成立 —— 这是**刻意**的（随机哈希连「检索有用」都证不了，见该 spec 头注）。
而 §三 第 10 条用例 `sparse-gap`（问「滞留期有多长」、文件写「押金留存时间」）的**查询与正文
刻意零字面重叠** —— 正是这条用例定义了「词汇缺口」。两者放在一起，结论是可推的：

> 字符直方图桩在 `sparse-gap` 上**必然**给不出非 0 命中，因为它能利用的唯一信号（共同码点）
> 已被夹具刻意抽走。拿它去填「语义对照」那一列，只会得到一个「稠密也没用」的**假结论**。

所以这一列不是「测了但没提升」，而是**这条尺子量不了这件事**。H5（同义改写命中）按前序决策
**延后到真 embedding 端点就绪**，见 `docs/KB-COMPLETION-PLAN.md` §8.5。

### 11.2 阶段 C **已经验完**的那部分（有证据）

| 能力 | 证据 |
|---|---|
| 稀疏 + 稠密**混合**（RRF k=60、两路并行、`ranks` 记两路、保留稀疏那份的高亮） | `tests/kb-vectors.spec.ts` E 段（含「关键词逐字搜不到、换个说法能搜到」—— 桩**能**证的那半边） |
| **库隔离**（按 `kb_id` 不串库） | 同 spec B③；变异 M3/M4 被咬住，M5a/M5b 对照证明它是**纵深防御**两道闸 |
| **降级如实**（稠密跑过 / 没跑 / 失败 三分支各说真话） | 同 spec E 段 4 条 C5 新守卫 |
| **换模型必须能重建** / **关 RAG 清向量** / **删库级联** | 同 spec C 段 / B② / D 段 |
| **开关与配置真能关掉**（关掉 = 零出网） | 同 spec E 段 + 变异 M1/M2 |
