**评审目标**：让单个微信账号成为服务全公司的智能助理
**评审日期**：2026-10-22
**评审对象**：`D:/super-time-wechat`（v1.1.0，Electron + React + Vite + TS，Windows x64）
**评审方式**：5 角色独立评审 + 主评审逐条复核；只读代码与文档。未跑全量测试、未做真实用户测试、未做渗透测试。

## 0. 今天做不到的五件事

这五条不是"限制条件"，是**当前产品的真实边界**——一切方案从这里起步。

| # | 做不到 | 证据 | 后果 |
|---|---|---|---|
| 1 | **同时只能有 1 个会话在线** | `http-control.js:65-79`：`rotate()` → 存新 token → `stop()`（`revokeAll`）→ 重启 → 发码 | 发第二个人的码，就把第一个人踢下线 |
| 2 | **界面签发的配对码一律是全权** | `settings-remote-access.tsx:112` 恒 `fullAccess:true`；`http-server.js:510` 因此跳过白名单 | 白名单**只在长期 token 会话上生效**（非日常路径）；日常扫码全是同权 |
| 3 | **HTTP 通道零审计** | `grep -c recordOperation http-server.js` = **0**；三张审计表均无 actor | 谁问的、看了哪些消息，事后还原不了 |
| 4 | **撤销只能全员下线** | `http-auth.js:224`、`http-server.js:783-784` 只有 `revokeAll` | 无法"踢掉某一个人" |
| 5 | **权限可由持有者自我复制** | `handoff-native.js:270` + `http-server.js:387-388` | 一次泄漏 = 一张不过期的登录凭据 + 可续期的全权 |

## 1. 一句话结论

> **作为「机主自用的单机工具」，它已是成品（6.8/10）；作为「服务全公司的助理」，它还是原型（约 2.7/10，就绪度约 28%）。**
> 真正的阻塞不是功能少，而是**权限、身份、审计三个模型都还不存在**。
> 且已有一条被代码证实的组合缺陷：**配对入口恒签发桌面同权**，拿到凭据的人还能**自签新码续期**，
> 而机主点"关闭"**并不会收回凭据**。

**三句话给决策者**：

1. **现在能给同事用吗？** 只能做 5 人「内部试用」，且须书面接受：同权、范围不可限、可在机主磁盘写文件。**不能叫多用户版本**。
2. **20 人日常用？** 做不到——不是慢，是**同时只允许 1 个会话在线**。
3. **要多久？** 权限止血 5.3–6.7 人日；5 人试用 3 人日 + 2 周试运行；部门级累计约 23.1–26.5 人日（单人约 4 周）；公司级 3–4 个月且必须先过法务。

## 5. 五维评估

### 5.1 功能完整性

**结论**：单机功能密度罕见（212 个 `@Remote`、171 个面板），"服务全公司"所需四类能力**一项都没产品化**。

| 目标场景必需 | 现状 | 缺口 |
|---|---|---|
| 多人接入 | 有 HTTP；同时在线会话 **1** | 无成员概念、无并发会话、无邀请/移除 |
| 身份与权限 | 只有"有令牌/无令牌" | 无角色、无会话级范围、无只读（且只读不可行，§5.4） |
| 共享知识 | 知识库是单机库 | 无共享库/个人库、无来源权限继承 |
| 答案可信 | 引用可点、覆盖度、幻觉拦截 | 无可量化基线（P0-08） |
| 结果带走 | 导出/备份强 | 问答结果不能复制/导出 |
| 服务连续性 | worker 崩溃自愈 | 单机单点、无降级、无 SLA |

> **最小侵入的解法（架构评审补充）**：现有 profile 是三维边界——`入口 × 工具 × 数据`
> （`profiles.ts:33-70` 的 `allowedTools` / `allowWechatData` / `forceUsername`），
> 缺的是第四维"人"。而它可以退化成**一次集合求交**：
> `allowedTools(actor, entry) = profile.allowedTools ∩ toolsFor(role)`，
> 不新增判定路径，越权仍由同一个执行层守卫拒绝，错误码与测试不变。
> `forceUsername` 则是全仓唯一表达"范围限定到某会话"的字段，是"同事只看某几个会话"最省的落点。
> 这让"按人收窄"从"重做权限"降级为"加一次求交"。

### 5.2 易用性

**结论**：机主能上手，**同事不能**。

| 关键旅程 | 现状（A 级） | 摩擦 |
|---|---|---|
| A 首次提问 | 默认落地 `overview`（`WechatDataPanel.tsx:471`） | 同事看到统计大盘，不是输入框 |
| A 数据就绪 | 悬浮 `SetupGuide`（`:730`），步骤含"检测账号/数据库密钥/图片密钥"（`setup-guide.ts:53-55`） | 全是机主动作，同事卡死在空系统 |
| B 问"没有的事" | `insufficient` → "本机记录里没有相关原文，未调用模型" | **全仓最好的表达**，应作模板 |
| B 有歧义 | 后端产出候选，前端只显示"意图：需要澄清" | 无候选可点，只能重打字 |
| C 把结果给别人 | `Ask.tsx` **无复制按钮**（聊天页、总结页都有） | 唯一出口是"沉淀"（存知识库） |
| C 核对来源 | 角标可点、右侧滑出（`AnswerBody.tsx:2-14`） | 主按钮"归档"，次按钮"打开原文" |

**权限感知的一行修法**：现在唯一表达范围的是输入框上方 chip（`ask-composer.tsx:175-179`）与
"M 个会话可检索"（`ask-scope.tsx:39`）。加了人的维度后若仍只显示"3 个会话可检索"，
同事会把"没查到"当成"没发生"——**比不限制更危险**。
应改为「**你可查 3 个会话（本机共 41 个）**」。

### 5.3 稳定性

**结论**：单机稳，多人结构性不稳。瓶颈排序与直觉不同：

| 排序 | 约束点 | 实测值 | 影响 |
|---|---|---|---|
| **1** | **同时在线会话 = 1** | `http-control.js:65-79` | 第 2 人扫码，第 1 人掉线。20 人不是"慢"，是"不在线" |
| 2 | 每次调用重算设备指纹 | `call-gates.js:82` → `service.js:25` → `fingerprint.js:13,26,39`：2 次 `execFileSync`（各 4s 超时）+ RSA 验签，无缓存 | 吞吐天花板 |
| **3** | **调用级无速率限制** | `limiter` 只在 `/api/auth`（`http-server.js:360,379,384`）；`/api/wechat/call` 无限制 | **任何持会话者可稳定制造主进程阻塞**——这是"功能不可用"的直接证据，比安全论证更快说服人 |
| 4 | 远程并发 2 / 队列 32 / 重活 4 / 等待 240s | `http-queue.js:36,39,48,58` | 第 3 个并发开始排队 |
| 5 | 单 worker，重活与桌面共用队列 | `ARCHITECTURE.md`、`http-remote-policy.js` C 类理由 | 一个 10 分钟任务饿死所有人 |
| 6 | 已知缺陷 | N33、N36 | 偶发红稀释门禁可信度 |

### 5.4 安全与合规

**结论**：唯一一个"单机也不及格、多人直接红线"的维度。

#### （1）权限模型：不是粒度粗，是方向错

| 环节 | 位置 | 事实 |
|---|---|---|
| 设置页恒签发全权 | `settings-remote-access.tsx:112` | `api.rotate({ fullAccess: true })` |
| IPC 只校验布尔 | `ipc-remote-access.js:34` | 无法证明"这是机主在桌面点的" |
| HTTP 因此跳过白名单 | `http-server.js:505-510` | `if (!fullAccess && !isRemoteSafe(method))` |
| 全权会话可自签新全权码 | `handoff-native.js:270` | `'remote-access-rotate': () => control.rotate({ fullAccess: true })` |
| 新码即新全权会话 | `http-server.js:387-388` | 配对码标记原样写进会话 |
| 交接态放行写侧与凭据 | `desktop-only.tsx:28-32,86`、`handoff-native.js:119` | 该模块自述"此处开放 = 在机主电脑装应用/改机器级设置"，却把 `llm-get`/`llm-save`/`update.install` 放了进来 |
| 撤销只有"全部" | `http-auth.js:224`、`http-server.js:783-784` | 无单会话撤销 |

**必须说准的两档（避免高估或低估）**：

`http-server.js:374-388` 的实际逻辑是——**长期 token 可当凭据登录，但由此建立的会话 `fullAccess=false`**；
**配对码才换全权**。因此一次扫码泄漏得到的是：

1. **一张不过期的登录凭据**（只在下一次 `rotate` 时被替换；`http-control.js:77-78` 的返回体含 token 原文）。
   该档仍可读 `getMessages` / `searchMessages` / `getLedger` / `getRecords` / `getContact360`——**全量正文与账单**。
2. **只要在 12 小时内重铸一次配对码，即可续期的全权会话。**

攻击者不必"一直在场"，只需"一直回来"。所以"单会话限制了爆炸半径"的安慰**不成立**：
它限制的是"同时在线的攻击者数量"，不是"攻击者能回来几次"——风险从"并发泄漏"变成**持久泄漏**，
对合规结论更坏（更难证明已终止）。

#### （2）三层凭据的寿命不同，混着说会选错止血动作

| 层 | 存在哪 | 寿命 | 怎么作废 | 用户可见 |
|---|---|---|---|---|
| 配对码 | 内存（`http-auth.js:267`） | 5 分钟、单次 | 用掉 / 停服 / 重新生成 | 可见（二维码） |
| 会话 Cookie | 内存（`http-auth.js:171`） | 12 小时，**可被全权会话无限续期** | 只能 `revokeAll()`（`http-auth.js:224`） | 不可见 |
| 长期令牌 | 落盘 `api_token`（`http-control.js:67`） | **永不过期** | **只有** `rotate()` 换新 | 不可见（只给掩码） |

`setEnabled(false)` 的注释明写「关闭时**不动令牌**」（`http-control.js:84`）。所以：

- **关掉访问** ⇒ 断开所有人、清会话、清配对码，**令牌照旧有效**；再打开旧令牌仍可登录。
- **退出应用** 只清内存两层，令牌仍在盘上。
- **唯一的完整止血动作是「重新生成二维码」**（`rotate()` = 换令牌 + `stop()` 清会话 + 发新码）。

**两点必须说清，避免高估也避免冤枉**：

1. 面板文案**已经写清后果**（`settings-remote-access.tsx:217-219`：「关闭监听或重新生成后立即失效……旧配对码与已连上的手机会一起失效」，并有「此码等同桌面端本人，勿给他人」）。**这不是 UX 缺陷，不要写进问题清单。**
2. 令牌"永不过期"本身**不构成漏洞**：它不可见、只落盘，泄漏面是磁盘——而磁盘失守已等于全量数据失守。按「已知风险、无当前暴露路径」记录，不拔高。

**按威胁分开看，止血动作才对得上**：

- **主威胁（把二维码/远程入口转给同事或外人）**：**停止监听就够了**——`stop()` 清会话与配对码，对方立即失效。这一条成立，是主路径。
- **次威胁（怀疑盘上 `api_token` 已泄漏，例如整机镜像/备份被拿走）**：只有 `rotate()` 能换掉它，关闭再打开无效。但这条路径需要先拿到磁盘，而磁盘失守已等于全量数据失守——按"已知风险、无当前暴露路径"记录，不拔高。
- 因此**不把"按钮改名"当缺陷**（面板 `:217-219` 已写清后果）。要补的是一个**独立审计动作** `revoke_all_credentials`（现落在 `saveWechatConfig` 里，混合配置与凭据事件，事后无法回答"有没有撤过凭据"）——这是**举证问题，不是功能问题**，0.5 人日。

#### （3）审计：远程通道是零

- `http-server.js` 中 `recordOperation` 出现 **0** 次。配对码签发、消费、会话创建、每次 `/api/wechat/call`，只在 stdout 打一行。
- `operation_log` 建表只有 `(ts, category, action, target, status, detail)`，**无 actor**；注释却写"谁在何时做了什么"（`operation-log.ts:10`）。
- `ask_history` 存完整问题+回答+引用，**无提问人、无 profile 列**；且 `clearAskHistory` 在远程白名单里（`http-remote-policy.js:80`），同类的 `clearOperationLog`/`clearPrivacyAudit` 在 `:195` 却是 LOCAL_ONLY——口径不一致。
  > 注：改白名单在 S0 之前只对 long-token 会话生效（界面签发的会话恒为 fullAccess），属"意图修正"，不是加固。
- HTTP 会话无 user/role/device 标签（`http-auth.js` 全文无 role/user）。

#### （4）合规：同意屏反而成为加重情节

- `consent.ts:96-101` 已明确披露扫码会话**与桌面端同权**（含模型 Key、许可证、诊断、备份还原、原生文件能力）。
  监管视角下，这从"未知缺陷"变成"明知而为"，是**加重情节**，不是免责。
- 但那份同意是**机主↔厂商**，**不覆盖公司↔员工、公司↔客户**。
- `README.md` 免责声明写"仅用于处理用户**本人**本机数据的**个人/内部**场景"，与"服务全公司"直接冲突。
- 聊天记录含**第三方**（客户、同事）个人信息；多人查阅构成"向他人提供"。
- 第三方 LLM 出网可能构成委托处理甚至出境，无 DPA、无处理清单、无留存期限。
- 删除权落不了地：派生库、索引、备份、`ask_history` 都有副本，无级联删除。
- 降低权限＝材料性变更 → `PRIVACY_VERSION` v27 → **升 v28 并重新同意**。

#### （5）凭据与密钥

`secrets.json` 明文 + ACL；数据根支持 UNC → 指向网络共享即等于把密钥与解密库放进共享目录。

#### （6）"受限档挡住了外流"是错觉，真正的收敛在别处

评审过程中一度把"受限会话调不到 `export*`"当成实质收敛，**该结论已撤回**。
准确的表述是：

- **导出闸门挡的是"一键打包"，不是"带走"。** 在本来就会把明文渲染到屏幕的终端上，
  导出权限只影响**效率**，不影响**可行性**：`getMessages` / `searchMessages` 返回明文正文，
  `getImageDataUrl` / `getVoiceDataUrl` / `getMessageFile` 全在白名单，浏览器里 Ctrl+A 即可。
- **真正的收敛是原生能力被挡**：无法安装更新、无法更换许可证、无法读取 RPA 凭据、**无法自铸新码**。
  收敛的是"权限升级与持久化"，不是"数据外流"。两者不能混为一谈。
- **`getAskHistory` 今天不构成越权，但补上 `profile` 列就会。** 它返回的是"全部本地会话的历史"，
  而 `ask_history` 没有 actor 列，所以现在拿到的是一份没有身份维度的混合历史。
  一旦加了 `profile`，**它就带上了"谁问的"**——若不想让远程读到，要么移出白名单，要么在返回体里剥掉。
- **一个真实的文档错误**：`PRIVACY.md` H 段把"关闭开关"写成控制手段，措辞是"关闭后无法再访问"。
  实际只要不换 token，**旧会话在「关 → 开」之后照常可用**。这不是产品判断问题，是文档写错了。
- **也别低估受限档**：日常扫码都是全权，白名单平时确实不执行；但"长期 token 会话"上它是**真的生效**的
  ——这正是 `getAskHistory` / `clearAskHistory` 可达的原因（P0-10）。

#### （7）三个主体，不是两个

评审前期一直用"机主 vs 同事"二分，这是漏的。真实主体有三个：

| 主体 | 能做什么 | 是否进 `operation_log` |
|---|---|---|
| 桌面端 IPC（机主本人） | 全部 | 部分 |
| **交接态浏览器**（同机、`fullAccess`） | 全部 + 原生动作（含 `llm-get`/`update.install`） | **否**（走独立的 native 桥） |
| 普通扫码会话（手机） | 白名单 | **否**（HTTP 层 0 处写入） |

在"机主与同事共用这台电脑"的试用期场景里，第二类主体不是理论风险：
**任何摸到那台电脑的人都能点「打开网页」，然后读走明文 API Key。**
准确表述是——不是"谁都能利用"，而是"**在设计已承认的转发威胁下，后果比我们原先写的大得多**"。

#### （8）跨层断言 —— 本仓库缺的那一类

这次三处缺陷全是"单层通、跨层漏"：

| 层次 | 它自己看得见的 | 它看不见的 | 该补的跨层断言 |
|---|---|---|---|
| 分发层（Electron / `@Remote`） | 方法面 212 条一致 | 传进来的对象长什么样 | 任何 `@Remote` 消费参数前假定它是 `unknown`；`files.list` 这类要 positional 的方法必须过 `Array.isArray` |
| HTTP 层 | 212 条分类齐 | 这次请求属于**谁、哪个入口** | `session.role × policy(method)` 的矩阵断言，而不只是"名单并集 == 注册表" |
| 前端 | 自己发出的形状对 | 后端实际收到什么 | 契约测试用**真实 client** 发一次，不用手写 mock |

**白名单复核政策（防最危险处失守）**：每次增删远程方法，必须人工过一遍 `REMOTE_SAFE_METHODS`——
因为**这份白名单就是多用户阶段的权限边界**，而宿主 `.d.ts` 是手写的，改坏不会被类型检查发现。
每条新方法进白名单前必须回答一句：**"返回值里有没有凭据、别人的内容、或能用来定位他人的标识？"**

**一个必要的补充**：这份清单的单元是**行为入口**，不是代码位置。
静态解析管得住"新增一个直白调用"，管不住"把两条折成一条"——
例如有人包一层 `function issueFullSession() { return control.rotate({ fullAccess: true }) }`，
调用点从 2 变 1，并集断言仍然全绿，但语义入口没少，只是被折叠了。
补法：会话对象带 `issuePathId`（**由调用方传入**，不是 helper 自生成），测试做**双向对账**
（静态清单 ⊆ 运行期出现集合，且反向成立）。副产品：它正好回答"这个会话是怎么被签出来的"，
比"谁登录的"更早一步，所以不是纯测试设施。

### 5.5 可扩展性

**结论**：**代码结构可扩展，产品模型不可扩展**。

| 好的部分 | 证据 |
|---|---|
| 方法面单一出处 | `gateway*.ts` 的 `@Remote`，`API.md` 自动生成并 CI 校验 |
| 依赖方向有机检 | `layer-direction.spec.ts`、`host-decl-alignment.spec.ts` |
| 策略表可扩展 | 212 条显式二分，新增方法必须分类否则红 |
| 后端可热重启 | `backend-supervisor.js` 有界退避重启 |

| 缺的部分 | 影响 |
|---|---|
| 无 `user`/`tenant` 抽象 | 加权限要改所有查询层签名 |
| 无会话级范围 | 只能"全库"或"当前会话"两档 |
| 单 bundle + 单 worker + 单会话 | 水平扩展必须拆服务 |
| 无配额/限流 | 一个人能打满全公司队列 |

**演进建议（明确推荐 B）**：

| 形态 | 改动 | 规模 | 判断 |
|---|---|---|---|
| A 桌面加固 | 小 | 1–3 人 | 仅过渡 |
| **B 主机 + 内网 Web** | 中：身份 + 多会话 + TLS 反代 + 背压 + 审计 | 5–30 人 | **性价比最高** |
| C 服务化 | 大：API + 队列 + 存储 + 多租户 | 50+ 人 | 现阶段过早 |

## 5.6 根因：一个根因，三个实例

三处缺陷不是三个独立 bug，是同一句话的三种写法：

| 实例 | 权限由谁声明 |
|---|---|
| 会话档位 | `fullAccess` 布尔，由**渲染层**传入（`ipc-remote-access.js:34`） |
| 凭据续期 | native `rotate`，由**持有者**触发（`handoff-native.js:270`） |
| **写操作可见性** | `mode=desktop`，由 **URL 参数**决定（`handoff-boot.ts:29/149` → `capabilities.ts:44` 的 `desktopEquivalent`；其注释明写放开"选目录、**导出**、截图、**ClawBot 写侧**"） |

> **权限的来源是调用方的输入，而不是服务端的判定。**

**原则**：凡"我有什么权限"，只能由服务端从**会话对象**推导，不能从请求参数、客户端状态或渲染层标记读取。

**三类归属写死，不留临场判断**：

| 类别 | 判据来源 | 包含 |
|---|---|---|
| 壳 | `mode=desktop` / 原生桥存在 | 标题栏、窗口控件、拖拽、布局 |
| 权限 | `/api/auth.fullAccess` | 导出、ClawBot 写侧、选目录、截图、在文件夹中显示、许可证、诊断、更新 |
| 物理在场 | **不设此类别** | 并入权限，**默认拒绝** |

> **一旦允许"物理在场"成为判据，系统就会重新长出"谁在这台电脑前谁就是主人"的假设——而那正是问题的原点。**
> 代价（交接态少选目录/截图/在文件夹中显示三项）必须付；补偿放在**文案层**（"这一步需要在电脑上的 Super Time 里做"），不放权限层。

**这条根因还解释了一个即将发生的回归**：S-0a 一旦让 limited 会话真实存在，界面就会展示许可证/诊断/更新/目录选择面板，用户点了却 403。
所以 S-0a 必须同批交付第 4 项：`advertised(s) ⊆ reachable(s)`（与 G6 断言共摊，**+0.3 人日**）。

**方法论（写判据前先看这三行）**：

| 判据类型 | 检查方向 | 放过的错误 |
|---|---|---|
| `toContain` / `satisfies` | 存在 | 漏掉、多出 |
| 白名单并集断言 | 分类完备 | **生产可达性** |
| 单测覆盖 | 我测了什么 | **谁能走到** |

> 能写成类型的不要写成注释；写类型的判据要问两句——**它检查的是存在还是完备**，以及**反例长什么样**。
> 写不出反例的判据只是装饰。
> **当分支只能由测试走到时，覆盖率会一直绿，而生产会一直不经过它**——这类分支既不在风险里，也不在怀疑里，是最安静的一类。

### 6.4 被证伪的方案（负面结果，别重走）

| 方案 | 为什么被否 | 证据 |
|---|---|---|
| **"先上只读降级档"** | 白名单那 70 条读方法**覆盖全部数据类别**，相对全权的差额只有"写与出网"，**没有一项是"看不见"**。所以它不是降级，是"看得见一切但不能改"；且 **UI 可达的会话全是全权，白名单只在 long-token 路径生效** | `http-remote-policy.js:57-80`、`http-server.js:505-510` |

### 7.1 四条设计原则（建议写进 PRD）

1. **宁可拒绝得难看，不要降级得看不出来。** 静默降级比报错危险——报错会被上报，降级不会。
2. **"只读"是写权限的对立面，不是可见范围的对立面。** 要做的是"看不到"，不是"不能改"。
3. **权限是被持有的，不是被使用的。** 列"允许哪些功能"会误导；应按"能触达的数据范围"建模。
4. **每加一条能力，必须同时回答"哪个主体、经哪条通道"。**
   "机主 vs 同事"是二分，会漏掉交接态这第三个主体（§5.4(7)）。这次三处漏洞全是"单层通、跨层漏"。

### 7.2 不建议做的三件事

| 不建议 | 理由 |
|---|---|
| 做移动 App | LAN Web 覆盖 90% 场景；原生要重做认证/离线/推送，ROI 极低 |
| 做多租户 SaaS | 数据是客户私聊，SaaS 化放大合规风险一个量级；先私有化单租户 |
| 放开"无知识库纯聊天"的 ClawBot 自动回复 | 现有硬门禁是对的，**不要为体验放开**——对外代答出错不可撤回 |

**题集字段（出机 / 不出机）**——注意 `answer` 也不能出机：

| 字段 | 处理 |
|---|---|
| `question` | 保留文本，**逐条随机替换**准标识符（人名/金额/精确日期），不保留映射 |
| `answer` | **不出机** → `answer_hmac` + `answer_len` + `citedIndexes`。回答常逐字复述原文（"他说尾款下周一付"），出机等于从后门送出 snippet |

| `snippet` | **不出机** → `snippet_hmac`。不用裸 sha256：短消息（"好的"）的裸哈希等于确认预言机 |
| `model` / `ts` / `consentRef` / `source_ask_id` / 行为标签 | 原样 |
| `sender` / `name` / `username` 明文 | 不出机 |

**三条硬门槛**：① 出机只带指针；② 题集可由机主一键**精确定位删除**（`source_ask_id` 回链）；③ 不早于"可定位删除"能力落地。

**语义抽检只能在本机做**：中心侧看不到答案正文 → 由有数据权限的人执行，QA 只收判定与统计。
未做只能标 `not_reviewed` 并**计入覆盖率**，不许静默跳过——否则"看不到答案"会让每月 30 条悄悄变成 0 条。

**运行位置：试点机 nightly 回放，CI 只校验产物。**

- Windows 计划任务 03:00 → harness 读本机数据根 → 输出 `results.jsonl` + `manifest.json`（`git_sha` / `harness_sha` / `corpus_hmac` / 逐条 `evidence_hmac`）。
- 产物落**内网制品目录**，不进 git、不进公开 CI 日志；保留 180 天。
- CI `quality:verify`：① `harness_sha` == 当次提交；② `corpus_hmac` == 钉住值；③ evidence HMAC 命中率 **≥99%（分母是题集条数）**；④ 阈值判定。
- **fail-closed**：超过 36h 无新结果 → `stale = 红`。**"没跑"绝不能等于"绿"**。

**五个指标（分母写死）**：

| 指标 | 分子 / 分母 | 说明 |
|---|---|---|
| 响应率 | 非 `canceled:*` 的落库轮次 / 全部落库轮次 | 用户点取消不算系统失败，**不进分母** |
| 回答率 | `ok` / 非 canceled | |
| 接地率 | `withheld` / (`ok` + `withheld`) | 有数字但引不出原文的比例 |
| 拒答率 | `refused` / 非 canceled | 政策行为，不是安全问题 |
| 行为合规率 | 行为标签命中 / 有效题数 | 展示点估计 + Wilson 区间，不是单点数字 |

- `blocked` **不进质量指标**，只进安全看板（零容忍）。
- `withheld` 用 `cited_indexes` 拆两子类：空=未标引用；非空=数字/日期核对不上。**分开统计**。
- 双判据：点估计 ≥0.95 **且** Wilson 下界 ≥0.90。

**`returned_message_ids` 本身就是敏感数据**：留 180 天；清空时**清列不删行**（留"谁问过"）；
不进导出与诊断包；备份按 `secrets.json` 同级保护；超长截断 N 条但保留 `returned_count` 真值。

**R-2 整体关闭的判据 = 抽一条真实问答，该字段非空且 id 集合 == 引用证据集**。

| 失效 | 处置 |
|---|---|
| 索引不可恢复（机器全毁/离职/数据根丢失） | **作废整批题集** + `eval_corpus_purged` 审计 `{ts, reason, affectedCount, operator}`；重采后重建基线 |
| salt 疑似泄漏 | **作废整批重建**（salt 不轮换） |
| 题集整批退役 | 同步删除 `eval_cid_index`（同一生命周期组），否则留下无主映射表 |

**已知限制：不建立"可重识别全部题集"的封存钥匙。** 删除义务的落点是"数据不再被处理"，不是"精确到条"；
整批作废同样达成，且可验证、有明确完成时刻。封存方案的代价是组织内长期存在一把能解开所有题的钥匙，
而风险是连续的——只要它在，总会在某次审计或纠纷里被打开。由 QA 负责人执行、产品负责人批准，**不设"尽力而为"档**。

**salt 保管**：本机 `eval_cid_index(cid, wxid, local_id, source_ask_id)` 让按人删除不依赖 salt；
运行副本 DPAPI；恢复码交法务；**保管人=机主、封存人=法务，不得同一人**；`manifest` 加 `cid_salt_fingerprint`。

**人审理由码必须是有限枚举**（`CITATION_MISS/…/OTHER`），`OTHER` **不带自由文本**；
`not_reviewed` 也带理由码（`NO_TIME/NO_ACCESS/SKIPPED`），否则"没看"会被当成"没问题"。

**`getAskHistory` 移出远程后**，手机端历史入口必须同步下线或明确提示——**不能静默变空列表**（会被当成记录丢失）。

**导出物断言**：`diag-export-log` 需断言导出物不含 `eval_cid_index` 与 `ask_history`
（`wechat_privacy.db` 同库里就有正文，"顺手打包整个库"会把两者一起带出去）。

**评测链路不得引入新的外联默认值**：夜间评测默认用**本地模型**；必须调用外部 provider 时，
需显式开关（默认关）+ 单次上限 50 题 + 计入 PRIVACY 新章。未开启 → 质量门禁记 `not_measured`（**不是绿**）。
P0-1 阶段只跑**确定性断言**（状态判定、引用映射、证据命中），不做生成质量结论。
**语料单位是 thread 不是 turn**：`[n]` 是答案内编号，按单条消息回放会改变上下文；
语料在采集时即固定为"该 thread 的 readSet + 答案"，可复算的只有确定性部分。
**harness 静态扫描**：不得 import 任何 provider SDK、不得发 http(s)、不得读 `llm.json`，扫描进 CI。

**S1 会话表的单一真相源**：`list()` 返回 `{sessions, total}`，UI 数字取 `sessions.length`，
**不再读 `state.sessions`**（后者来自 `count()`，自带 `sweep()`，与另一次 `list()` 之间会夹一次惰性清理，
出现"上面 3 个、下面两行"）。判据：同一响应内 `count === list.length`；wiring 用例喂"list 2 条 / state 3"，界面必须显示 2，改回 `state.sessions` 必须红。
字段：`id`（句柄）/`createdAt`/`lastSeenAt`/`ip`/`ua`/`fullAccess`/**当前设备**。
**"当前设备"必须做**：`mode=desktop` 的交接态会渲染这块面板且 `desktopEquivalent=true`，
用户需要知道"哪台是我手上这台"；普通浏览器态渲染不到这一列（桌面专享），不存在泄漏。IP/UA 脱敏展示。

**工作量**：S1 **3–4 人日**（余量给会话存储扩字段——`http-auth.js:170` 现在只有 `{exp, fullAccess}`）；
S6 独立（≤6 人日）；S10 **4 人日**；P0 累计 **23.1–26.5 人日**。

### 11.4 质量门禁清单（G1–G6）

| 编号 | 门禁 | 判据 | 排期 |
|---|---|---|---|
| **G1** | 质量金标 | 行为级用 `runEvalReport(fakeDb)`：fakeDb 在 `json_valid`/`json_array_length` 上抛 `EVAL_JSON1_UNAVAILABLE`/`EVAL_SQL_UNKNOWN_FUNCTION` 时，报告函数必须抛同名错误；**撤掉 AST 形状扫描**（正则会误杀合法调用）；`runEvalReport` 纯函数入参。统计：点估计 ≥0.95 且 Wilson 下界 ≥0.90（每 profile ≥200 题） | 阶段 A |
| **G2** | 真实规模 | 50 万条语料下的检索 P95 与召回基线 | 阶段 B |
| **G3** | 升级迁移 | 派生库 schema 变更 + 版本回滚 | 阶段 B |
| **G4** | 故障注入 | LLM 超时/限流/垃圾返回、磁盘满、杀进程、断网 | 阶段 B |
| **G5** | 多客户端鉴权 | 3 会话并存、撤销隔离、令牌重放、fullAccess 伪造 | 阶段 A |
| **G6** | 授权矩阵 | **`SIGNING_PATHS` 4 条**（settings / browser-handoff / native rotate 三条 `full` + **long-token 一条 `limited`**）逐条跑：`reach == 白名单`；**测量必须双层**：① 服务端 `reach`；② **客户端解析后的能力表**（不是 `/api/auth.native` 字段——客户端根本不读它）。`HANDOFF_ACTIONS`/`REMOTE_SAFE_METHODS` 加 `[full]`/`[limited]` 命名标记，G6 依次直读导出，**不维护第二份名单**。合成会话只补未来档位，**不能替代**这条 | 阶段 B（2.0–2.5 人日） |

**G6 的限度必须写清**：它只保证"声明的策略 == 实际执行的策略"，**不保证"声明本身合理"**。
白名单多放一条、`DESKTOP_ONLY` 该拦的写成放行，G6 会如实执行并判定通过。
补它的只有两条：① 白名单每次增删**人工过一遍**（§5.4(8) 的政策）；② 每条新方法进白名单前回答"返回值里有没有凭据/别人的内容/定位标识"。
**G6 的两句限度**：它保证"声明 = 实现"，**不保证"声明合理"**；
它能证明"权限档被如实执行"，**不能证明"权限档设计正确"**。
前者防"绿了就等于安全"，后者防"绿了就等于权限模型没问题"。

**`SIGNING_PATHS` 锁常量 4 的意义不是"它等于 4"**（3 条 `full` + 1 条 `limited`），
而是让"下次加第五条路径"必须先改常量、必须过 review——把"新增全权入口"从默认动作变成**需要解释的动作**。

**排期口径**：G1 的**执行**依赖"题集已按入集门槛建成"，**不依赖 actor 完成**——前者是时间顺序，后者是任务依赖，别把 G1 画在 actor 后面。
