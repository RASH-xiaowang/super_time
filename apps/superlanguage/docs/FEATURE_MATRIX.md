# SuperLanguage 功能与验收矩阵

> 迁移来源：`C:\Users\Administrator\Desktop\wechat`
>
> 当前项目：`C:\Users\Administrator\Desktop\new_supertime`
>
> 版本：`1.0.0 / API revision 6`

本矩阵描述当前构建实际具备的能力、已知限制和验收方式。原项目的自动化、
队列和协议实现已迁入；内部继续使用 `feather` 命名空间，用户可见品牌、
进程、窗口类和 MCP 服务身份使用 SuperLanguage。

关键状态说明：

- **主链路已接入**：UI、API、Webhook 和 MCP 入队的任务会走这条路径。
- **已移除**：旧版本存在、当前源码已删除的能力，列出以免误用。
- **已知限制**：不是待办承诺，而是当前版本的真实行为。

当前接口面为 10 个 HTTP/Webhook method+path 操作（6 个 `/api/*`、
4 个 Webhook）和 6 个 MCP 工具。`API revision 6` 是接口版本号，不是接口
数量。

## 微信自动化

| 能力 | 当前实现与状态 | 验收方式 |
|---|---|---|
| 客户端发现 | 识别 `Weixin.exe` 与 `WeChat.exe` | 已安装任一版本时可识别 |
| 安装与启动 | 注册表/常见路径解析；普通启动后自动检查微信，必要时受控启动 | 未运行时可从 SuperLanguage 启动 |
| 登录识别 | 按窗口类名、标题和尺寸识别登录界面与已登录主窗 | 登录流程状态显示正确 |
| 登录处理 | 手动登录：显示并前置登录窗口，提示扫码或点击“进入微信”，最多等待 300 秒，登录后自动继续；不自动点击 | 未登录时入队任务，扫码后任务继续执行 |
| 微信不可用 | 未安装、启动失败、登录超时、微信退出或状态未确认且未写意图时任务回队；队列暂停 30 秒起翻倍、上限 5 分钟；手动检查或登录成功立即恢复 | 界面显示“队列等待微信 · N 秒后重试”，任务仍为 `queued` |
| 窗口呈现 | 前置、保持原窗口大小；显示/隐藏使用 `ShowWindow`，不依赖微信显示/隐藏快捷键 | 自动化前稳定聚焦微信，且所有点击为窗口相对坐标 |
| 会话搜索 | 首次或目标变化时先检查输入框为空，点击窗口左上 `(100,58)` DIP 归一化布局，发送两次 `Ctrl+F`，清空后键入目标并回车；搜索词落入输入框时清空并失败 | 日志记录“快捷键 Ctrl+F” |
| 会话复用 | 连续领取同一目标且上次已成功进入该目标、窗口和进程未变化时跳过搜索和回车；只检查前台进程和超时，不读取标题；带 @ 的任务总是重新搜索 | 日志出现“同一目标复用（未读取标题）· 跳过 Ctrl+F 搜索” |
| 会话接受 | 按回车后接受当前高亮结果，不读取会话标题 | 人工验证；存在误选风险 |
| 搜索面板关闭 | 按客户区 `right-15 DIP`、`top+45 DIP` 计算关闭点；仅当该点命中主窗口内 `Chrome_WidgetWin*` 子窗口时点击，否则跳过；点击后不轮询 | 日志记录坐标，微信主窗口保持存活 |
| 标题证明 | **已移除**：不再读取或校验会话标题，相关 UIA 代码已删除 | — |
| 焦点证明 | **已移除**：文本和附件链路都不证明输入框焦点 | — |
| 草稿保护 | 发送按钮绿色像素启发式：搜索前检查（非空时以 183 失败），附件发送前再检查；截图失败按空处理；会话复用路径上的文本任务不检查 | 分别用空草稿和非空草稿验证 |
| 文本发送 | 点击输入区后，逐字发送同步 `WM_CHAR`（间隔 4–12ms 抖动），非 BMP 字符（emoji/扩展 B）改发 `SendInput` Unicode，换行用 `Shift+Enter` 并等待 250ms，`Ctrl+Enter` 单次提交；不证明焦点、不校验正文 | 全字符集逐字一致（实测 37/41 分块，剩余为不可显示码位），多行顺序正确，任务不重复提交 |
| 文本内容校验 | 结果只有 `NotAttempted`/`Failed`/`InjectedUnverified`；`content_verified` 恒为 `false` | API 中 `content_verified=false` |
| @ 成员 | `@` → 200ms → 选择器须 2 秒内出现并稳定，否则失败 → 逐字 100ms 输入成员名最长无空格片段 → 200ms → 回车 → 200ms → 等选择器关闭（必要时补一次回车）→ 空格/换行 → 正文；不回读成员身份 | 旧构建实测选中 `a憨` 后微信按群昵称显示为 `@Y.M`；当前构建未人工验收 |
| 附件发送 | 最多 10 个本机路径；自建 message-only 窗口作剪贴板所有者，`Ctrl+V` 后 10 秒内须出现内容才提交，恢复原剪贴板；提交前失败清空输入框，已发 `Ctrl+Enter` 后不清理 | 多文件任务可执行；失败后输入框为空 |
| 资源 ID 附件 | API/Webhook 最多接受 9 个 40 位十六进制资源 ID；以 `resource-spool\<id>\<原名>` 发出原始文件名 | 10 项及以上返回 400；微信中显示原文件名 |
| 数组附件 | `/api` 与 Webhook 的 `attachments` 均接受字符串数组，最多 16 项；超过执行器 10 项时任务失败 | 11–16 项任务应失败 |
| 输入保护 | 低级鼠标钩子拦截物理鼠标移动/滚轮/按键，允许注入事件；键盘可用；锁定失败时任务以 `ERROR_LOCK_FAILED` 失败 | 执行时移动物理鼠标不干扰轨迹 |
| 鼠标轨迹 | 助推-滑翔曲线、随机中段变轨、末段阻尼、过冲回拉、`SendInput` 注入和光标回位 | 保护期间轨迹可见、落点准确 |
| 超时恢复 | 超时释放钩子，当前任务标记失败/超时；各等待循环在中止时立即退出 | 超时后程序可继续操作 |
| 任务后窗口 | 仅搜索任务保持微信可见；文本和附件任务尝试隐藏微信 | 分别检查搜索和发送任务 |
| 诊断日志 | `mention-debug.log` 记录 @/附件流程结构化信息，不含昵称、目标或正文；超过 1 MiB 轮转为 `.1` | 日志无敏感文本 |
| 投递语义 | 区分已入队、注入未验证、失败；已记录意图的未验证结果报告不确定 | 不把入队或注入当作已送达 |

## 队列与恢复

| 能力 | 当前实现与状态 | 验收方式 |
|---|---|---|
| SQLite 持久化 | 单文件 `queue.db`；启动时执行兼容迁移；`busy_timeout=3000ms`；未启用 WAL | 重启后任务仍在 |
| 崩溃恢复 | 未开始投递的 `running` 回到 `queued` | 原生队列测试覆盖 |
| 已尝试恢复 | 已持久化发送意图的 `running` 转为 `failed`，错误码 1067 | 不自动重发 |
| 发送意图 | 不可逆动作前原子记录 `delivery_attempted`；重复记录被拒绝 | 原生队列测试覆盖 |
| 回队 | `requeue` 只接受未写意图的 `running` 任务，保留原 ID 和创建时间，按原顺序优先领取 | 原生队列测试覆盖可回队/不可回队状态 |
| 任务状态 | `queued/running/succeeded/failed` | API 与队列窗口一致 |
| 任务 ID | 随机 16 位小写十六进制；查询不区分大小写 | 原生队列测试覆盖格式 |
| 活动容量 | 最多 200 条 `queued+running` | 超限拒绝新任务 |
| 历史保留 | 启动时和每条任务完成后裁剪，任何时刻最多 50 条已完成记录 | 原生队列测试覆盖启动与运行期裁剪 |
| 附件引用 | 队列仍引用 spool 资源时阻止清理；数据库未打开时不清理 | 资源引用检查通过 |
| 历史视图 | 运行中、排队、已结束任务按面板顺序展示；窗口不显示正文、@ 和附件路径明细 | 队列窗口显示关键字段 |

## HTTP 与 Webhook

| 能力 | 当前实现与状态 | 验收方式 |
|---|---|---|
| Bearer 鉴权 | `/api/*` 常量时间比较 32 位十六进制令牌，并拒绝带 `Origin` 的请求 | 缺失/错误令牌返回 401 |
| Webhook 鉴权 | URL 令牌；同样拒绝带 `Origin` 的请求 | 错误令牌返回 401 |
| 健康与状态 | `/api/health` 返回服务名、版本、API revision、端口和 Webhook 标志；`/api/status` 返回队列、鼠标保护、微信状态 | 隔离测试校验字段 |
| 任务查询 | `/api/jobs/{id}` 与 `/webhook/<token>/jobs/{id}`；ID 不区分大小写 | 已入队任务可查询 |
| 文本入队 | `target`、`message` 必填；可选 `mention`、`mention_separator`/`mention_newline`，@ 由简化发送链路执行 | 合法请求返回 202 |
| JSON 解析 | `/api` 与 Webhook 共用：格式错误 400 `invalid json`；重复字段取第一次；空字符串视为未传；超长按字段返回 `target too long` 等 | 构造异常 JSON 返回对应 400 |
| 附件入队 | 本机路径或资源 ID，二者互斥；本机路径仅允许来自 `127.0.0.1` 的请求；数组元素为空或含 `;` 返回 400；暂存失败 500 | 策略和错误码正确 |
| 资源上传 | `application/octet-stream`、`Content-Length`、`X-SuperTime-Filename`/`X-SuperTime-SHA256`、1 B–20 MiB、40 位 ID；拒绝结尾点/空格、保留设备名和 0x7F；不识别 `X-Feather-*` | 上传、校验、引用成功；旧头返回 400 |
| 请求限制 | JSON 请求体上限 8192 字节（只计请求体），请求头上限 16 KiB；请求头含 NUL 返回 400 | 请求体超限返回 413；大请求头小请求体不返回 413 |
| 并发与超时 | 最多 8 个连接并发，第 9 个返回 503 `server busy`；请求头+JSON 体 10 秒截止，超时 408；上传按 64 KiB/s 延长截止 | 慢速连接被 408 断开 |
| 监听配置 | 默认 `0.0.0.0`（局域网可访问）；`loopback`/`0`/`127.0.0.1` 只绑定 `127.0.0.1`；`lan`/`any`/`all`/`0.0.0.0`/`*` 或指定 IPv4；失败回退回环并记录 | loopback 时非回环地址连接被拒绝 |
| 令牌轮换 | 主界面“刷新”生成新令牌并持久化，旧令牌立即失效 | 旧令牌请求返回 401 |
| 停止接口 | `POST /api/stop` 释放输入锁并请求退出程序 | 隔离测试返回 202 且进程退出 |
| 投递不确定 | 已尝试但未验证/失败的任务报告 `delivery_uncertain=true` | 调用方不得自动重发 |

## MCP 网关

| 工具 | 当前行为 | 验收方式 |
|---|---|---|
| `health` | 只读健康信息 | 假 API 协议测试 |
| `status` | 队列、微信和输入保护状态 | 假 API 协议测试 |
| `get_job` | 按 1–16 位十六进制 `job_id` 查询任务 | ID 校验和错误映射 |
| `wait_job` | 轮询到终态或 `delivery_uncertain`，默认 30 秒、最大 120 秒；单次 HTTP 超时不超过剩余时间（下限 1 秒） | 超时不等于失败，不重发 |
| `send_message` | 将文本任务（含可选 `mention`）加入本地队列 | 返回 `queued_not_delivered` |
| `send_attachments` | 本机绝对路径或资源 ID 均最多 9 项 | 互斥校验和安全提示 |

协议层：`2025-06-18` 及 `initialize` 之前拒绝 JSON-RPC 批量请求（`-32600`），
旧协议版本仍支持批量；只读取 `SUPERTIME_*` 环境变量。

## 必须保留的安全边界

- MCP 错误结果不包含 API 令牌；SuperLanguage 界面、日志和帮助窗口只显示
  令牌首尾各 4 位，但“复制”得到完整令牌/URL，含令牌的截图和复制内容应按
  敏感数据管理。
- API 令牌和 Webhook URL 属于凭据，Webhook 令牌位于 URL 中。
- 本机附件路径只允许来自 `127.0.0.1` 的请求；不要在本机部署把远程请求
  转发到 `127.0.0.1` 的反向代理或隧道，否则远程请求可读取并发送任意本地文件。
- 当前文本路径没有标题或焦点证明，空草稿检查只是像素启发式，属于已知风险，
  不应描述为已验证安全。
- @ 成员要求选择器出现并稳定，但不回读最终成员身份；输入别名和微信显示的
  群昵称可能不同，发送前应使用受控群和已知成员。
- 已持久化发送意图后的失败不得描述为“肯定未发送”。
- `delivery_uncertain=true` 或连接中断/5xx 的发送请求不得自动重试。
- 自动化不读取微信消息正文、不绕过登录验证、不代替用户点击登录，也不提供
  UIA/OCR/LLM 识别。
